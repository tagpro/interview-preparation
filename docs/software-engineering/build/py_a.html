Part one

The object model

Python has no variables in the C sense. It has names bound to objects, and almost every beginner surprise — the function that mutated your list, the default argument that remembered, the is that worked until it did not — follows from that one fact. Learn the binding model first and the rest stops being folklore.

Python · 00

Names, objects and references

Assignment never copies. It points a name at an object that already exists. Two names can reach the same object, and only one of the two operations you can perform — rebinding a name, mutating an object — is visible to the other name.

a = [1, 2, 3]
b = a                           # one object, two names
b.append(4)
print(a)                        # [1, 2, 3, 4] -- a sees it
print(a is b, id(a) == id(b))   # True True

def rebind(lst):
    lst.append(99)              # mutates the caller's object
    lst = [0]                   # rebinds the LOCAL name only
    return lst

x = [1]
rebind(x)
print(x)                        # [1, 99] -- append survived, rebind did not
L1 · Beginner

Bindings, not boxes

  • Assignment binds a name — x = obj makes x refer to obj. Nothing is copied and no storage is reserved for x.
  • == vs is — equal value versus the same object. Use == unless you specifically mean identity.
  • Everything is an object: integers, functions, modules, classes and exceptions all have a type, attributes and an id().
  • Because functions are objects, you can put one in a list, pass it as an argument, or return it — no special syntax required.
  • type(x) tells you what it is; id(x) tells you which one it is.
L2 · Intermediate

What a call actually passes

  • Argument passing is name binding — the parameter becomes another name for the caller’s object. Not by value, not by reference in the Pascal sense.
  • So a function can mutate your list, dict or set, and cannot rebind your name. lst.append(x) escapes; lst = [] does not.
  • del x removes the name, not the object. Any other name still bound to it keeps it alive.
  • Rebinding in a loop, a comprehension or an except ... as e block follows the same rule — and e is deleted at the end of the except block.
  • Take a copy at the boundary if the caller must not see your edits; say so in the docstring either way.
L3 · Advanced

Lifetime, and why is lies

  • Reference counting frees an object the moment its last reference goes; a cycle detector handles the rest. What keeps an object alive is a reference, from anywhere — a list, a frame, a closure cell, a traceback.
  • id() is reused. It is the address in CPython, so a freed object’s id can be handed straight to the next one. Never store an id as a key.
  • is on ints and strings is a bug that passes its own test. Interning is an implementation detail that varies between literal, computed, and interactive contexts.
  • A traceback holds a reference to every frame, and every frame holds its locals — this is how exception handling keeps large objects alive longer than expected.
  • sys.getrefcount, gc.get_referrers and weakref are the tools when something will not die.
Python · 00

Mutability, copying, and the default-argument trap

A default value is evaluated once, when the def statement runs — not once per call. If that value is mutable, every call shares it, and the function quietly accumulates state across the life of the process.

def add(item, bucket=[]):        # bucket is created ONCE, at def time
    bucket.append(item)
    return bucket

add("a")            # ["a"]
add("b")            # ["a", "b"]  <- the same list, still there
add.__defaults__    # (["a", "b"],)  the evidence, on the function object

def add(item, bucket=None):      # the None-sentinel fix
    if bucket is None:
        bucket = []              # a fresh list per call
    bucket.append(item)
    return bucket
L1 · Beginner

Know which builtins bite

  • Mutable: list, dict, set, bytearray, and instances of most classes you write.
  • Immutable: int, float, str, bytes, tuple, frozenset, bool, None.
  • The default-argument trap — never write def f(x=[]) or def f(x={}). Use None and build inside the body.
  • list.copy() / dict.copy() hand out an independent top level; x[:] does the same for sequences.
  • A linter catches this one — ruff rule B006 exists precisely because it is so common.
L2 · Intermediate

Copy depth and hashability

  • Shallow vs deep — copy.copy duplicates one level; copy.deepcopy duplicates the whole reachable graph and keeps a memo so shared nodes stay shared and cycles terminate.
  • deepcopy costs — it is recursive, pickle-adjacent, and easily the slowest line in a hot loop. Prefer restructuring so you do not need it.
  • Mutable objects are unhashable because a dict places a key by its hash and would lose it if the hash moved.
  • A tuple containing a list is immutable at the top and still unhashable — hash((1, [2])) raises TypeError.
  • Dataclasses: field(default_factory=list) is the same fix, spelled for a class.
L3 · Advanced

Contracts and boundaries

  • The __hash__/__eq__ contract: equal objects must hash equal, and the hash must be stable for the object’s lifetime. Defining __eq__ alone sets __hash__ to None.
  • Freeze deliberately — frozenset, tuple, @dataclass(frozen=True), or a NamedTuple, when a value must be a key or crosses a thread boundary.
  • Defensive copying at API edges: copy on the way in if you will store it, on the way out if the caller might mutate it. Document the choice; do not make callers guess.
  • Copy-on-write is a myth here. Python has none — not for lists, not across fork() (refcount updates dirty the pages anyway).
  • __copy__ and __deepcopy__ let a type control its own duplication; use them for handles that must not be cloned.
Python · 00

The data model: protocols, not inheritance

Syntax is a call. len(x) is x.__len__(), x[k] is x.__getitem__(k), with x is x.__enter__(). Nothing checks a base class — the interpreter looks for the method and calls it.

class Money:
    __slots__ = ("amount", "currency")

    def __init__(self, amount, currency):
        self.amount, self.currency = amount, currency

    def __repr__(self):          # what logs, reprs and tracebacks show
        return f"Money({self.amount!r}, {self.currency!r})"

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented    # let the other type try
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __hash__(self):          # define WITH __eq__ or the type is unhashable
        return hash((self.amount, self.currency))
# the container and context-manager protocols -- no base class, just the methods
class Basket:
    def __init__(self):
        self._items: list[str] = []

    def __len__(self) -> int:                 # bool(basket), len(basket)
        return len(self._items)

    def __getitem__(self, i: int) -> str:      # basket[0], and makes it iterable for free
        return self._items[i]

    def __iadd__(self, item: str) -> "Basket": # basket += "eggs"
        self._items.append(item)
        return self

class transaction:                             # with transaction(conn): ...
    def __init__(self, conn):
        self.conn = conn

    def __enter__(self):
        self.conn.execute("BEGIN")
        return self.conn

    def __exit__(self, exc_type, exc, tb) -> bool:
        self.conn.execute("ROLLBACK" if exc_type else "COMMIT")
        return False                           # False: never swallow the exception
L1 · Beginner

The dunders you write first

  • __init__ initialises an object that already exists; __new__ is what actually creates it, and you almost never touch it.
  • __repr__ is for you — unambiguous, ideally something you could paste back in. __str__ is for the user.
  • Logs and tracebacks use __repr__, and lists of objects print their repr. A default <Order object at 0x7f...> is a wasted debugging session.
  • If you define only one, define __repr__ — str() falls back to it.
  • Dunder names are called by the interpreter. You define them; you rarely call them.
L2 · Intermediate

Implementing the protocols

  • __eq__ and __hash__ travel together; return NotImplemented (not False) for a type you do not understand, so the other operand gets its turn.
  • Iteration: __iter__ returns an iterator, whose __next__ raises StopIteration when done. A generator function gives you both for free.
  • __getitem__ alone makes an object indexable and, as a legacy fallback, iterable — which is why some old classes work in for without __iter__.
  • Operator overloading is for types where the operator already means something — vectors, money, paths. Not for cleverness.
  • functools.total_ordering fills in the other comparisons from __eq__ plus one of __lt__.
L3 · Advanced

Attribute machinery

  • Descriptors are the mechanism under @property, methods, classmethod and __slots__: an object with __get__/__set__ stored on the class.
  • __slots__ removes the per-instance __dict__ — less memory, faster attribute access, no ad-hoc attributes. Worth it for millions of small objects.
  • __getattr__ vs __getattribute__: the first runs only after normal lookup fails, the second intercepts every access and is easy to make infinitely recursive.
  • Metaclasses exist; __init_subclass__ and __set_name__ cover most of what people reach for them for. Learn them, deploy them rarely.
  • Say the protocol out loud. An ABC or a typing.Protocol turns “must have read and close” from a comment into something a checker enforces.
Part two

Functions and flow

Python’s function machinery is unusually rich: five kinds of parameter, laziness as a first-class control-flow tool, and closures that make decorators an ordinary consequence rather than a feature. All three shape how your API reads at the call site — and two of them have a trap that only shows up under load.

Python · 00

Arguments: positional, keyword, and the star operators

A signature has five zones, separated by / and by *. Where you put a parameter decides how callers may pass it — and therefore what you are free to change later without breaking them.

def connect(host, /, port=5432, *, timeout=5.0, sslmode="require"):
    ...

connect("db1")                       # host is positional-only
connect("db1", 6432)                 # port may be positional
connect("db1", timeout=1.0)          # timeout MUST be by keyword
connect(host="db1")                  # TypeError: host is positional-only

opts = {"timeout": 1.0, "sslmode": "disable"}
connect("db1", **opts)               # unpack a dict into keyword arguments

args = ("db1", 6432)
connect(*args, timeout=1.0)          # unpack an iterable into positionals
L1 · Beginner

Passing and collecting

  • Defaults make a parameter optional; keyword arguments let the caller name it and skip ordering entirely.
  • *args collects the leftover positionals into a tuple; **kwargs collects the leftover named ones into a dict.
  • Unpacking at the call site: f(*seq) spreads an iterable into positions, f(**mapping) spreads a dict into names.
  • The names args and kwargs are convention only — the stars do the work.
  • Keyword arguments at a call site are documentation: retry(3, True) tells a reader nothing, retry(3, jitter=True) tells them everything.
L2 · Intermediate

Designing the signature

  • Keyword-only parameters (after a bare *) can be reordered, renamed in position, and added to without breaking callers. Use them for every flag and option.
  • Positional-only (before /) frees the name: useful for a first argument like self-ish subjects, and for wrappers that also take **kwargs and must avoid name clashes.
  • Defaults are evaluated once, at def time — the same fact as the mutable-default trap above, and it applies to datetime.now() defaults too.
  • Booleans are almost always keyword-only. send(msg, True, False) is unreadable by construction.
  • *-unpacking works in literals as well: [*a, *b], {**d1, **d2}.
L3 · Advanced

Binding, introspection and restraint

  • functools.partial pre-binds arguments and returns a callable — cheaper and clearer than a lambda, and it keeps a usable repr.
  • inspect.signature reads the real parameter list; sig.bind(*a, **kw) resolves a call the way the interpreter would, which is how frameworks do dependency injection.
  • Accept **kwargs rarely. It defeats type checkers, autocomplete and inspect, turns typos into silent no-ops, and pushes errors down into whatever you forward to.
  • Argument order is API surface and shows up in every caller’s source. Treat a reorder like a rename: it needs a deprecation, not a patch release.
  • typing.ParamSpec and Concatenate exist so a decorator can keep the wrapped signature visible to the checker.
Python · 00

Comprehensions, generators and laziness

A comprehension builds the whole result before anything downstream runs. A generator computes one element per request and forgets it. Same answer, same code shape, and a memory profile that differs by the size of your input.

# Materialises every line: peak memory is the whole file.
total = sum([int(line) for line in open("events.log")])

# Streams: one line resident at a time, same answer.
with open("events.log") as f:
    total = sum(int(line) for line in f)

# A pipeline of generators -- still one element in flight.
def parse(lines):
    for line in lines:
        if line.strip():
            yield json.loads(line)

with open("events.ndjson") as f:
    errors = (e for e in parse(f) if e["level"] == "error")
    first_ten = list(itertools.islice(errors, 10))   # stops reading after 10
L1 · Beginner

Building sequences

  • Comprehensions come in three shapes: [x for ...] list, {k: v for ...} dict, {x for ...} set.
  • They replace the result = [] / append loop and are usually faster, because the append is done in C.
  • range is lazy — range(10**9) costs nothing until you iterate it. So are zip, map, filter and enumerate.
  • yield makes a generator: calling the function runs no code, it hands back an object that runs on demand.
  • One condition and one loop is a comprehension; two of either is a for loop.
L2 · Intermediate

Picking lazy or eager

  • Generator expression vs list comprehension — parentheses instead of brackets. Choose the generator when the result is consumed once, the list when you need len, indexing or a second pass.
  • Generators are single-use. Re-iterating a spent generator silently yields nothing, which looks like missing data, not like an error.
  • itertools is the standard toolkit: islice (take n), chain (concatenate), groupby (needs sorted input), batched (fixed-size chunks, 3.12+).
  • enumerate and zip replace index arithmetic; zip(strict=True) catches length mismatches instead of truncating.
  • A generator that wraps a resource should be consumed inside the with block that owns it.
L3 · Advanced

Pipelines and their cost

  • yield from delegates to a sub-generator, forwarding values, send and exceptions — and flattens recursion without a manual loop.
  • Generators were the original coroutines: send, throw and close predate async/await, which was built on exactly this machinery. Write new async code with async def.
  • A pipeline of generators keeps one item per stage alive, so memory is O(stages), not O(input) — the same shape as a Go channel pipeline, minus the concurrency.
  • __iter__ returning self is what makes an iterator work in for; a re-iterable iterable returns a fresh iterator each time. Confusing the two is why a class works once and then stops.
  • Laziness moves work rather than removing it: tracebacks point at the consumer, and per-element function-call overhead can make a generator slower than one bulk operation.
Python · 00

Scope, closures and decorators

A name is resolved local, enclosing, global, built-in — first match wins. A closure captures the enclosing variable, not its value at capture time, and a decorator is nothing more than a function that takes a function and returns one.

import functools, time

def timed(fn):
    @functools.wraps(fn)                 # keeps __name__, __doc__, __wrapped__
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            ms = (time.perf_counter() - start) * 1000
            log.info("%s took %.1f ms", fn.__name__, ms)
    return wrapper

@timed                                   # charge = timed(charge)
def charge(order_id):
    ...
# the late-binding trap: a closure reads the variable, not a snapshot of it
handlers = []
for route in ["orders", "users", "health"]:
    handlers.append(lambda: log.info("handling %s", route))

[h() for h in handlers]        # "handling health" three times -- route is one shared cell

# the fix: bind it as a default argument, evaluated once, right now
handlers = []
for route in ["orders", "users", "health"]:
    handlers.append(lambda route=route: log.info("handling %s", route))

[h() for h in handlers]        # "handling orders", "handling users", "handling health"
L1 · Beginner

Where names live

  • Local vs global — assigning to a name anywhere in a function makes it local for the whole function, even on lines above the assignment.
  • global and nonlocal are needed only to rebind an outer name. Reading and mutating need neither.
  • A closure keeps its enclosing variables alive after the outer function has returned — that is what makes inner functions useful.
  • @decorator is f = decorator(f), applied right after the def. Nothing more.
  • Module-level mutable state is global state; it will be shared by every import.
L2 · Intermediate

Writing decorators that behave

  • Late binding in loops — closures created in a loop all see the final value. Bind with a default (x=x) or functools.partial.
  • functools.wraps copies __name__, __doc__, __module__, annotations and sets __wrapped__. Without it, every decorated function is called “wrapper” in logs and docs.
  • A decorator with arguments is three nested functions: factory takes the arguments, returns a decorator, which returns the wrapper.
  • functools.lru_cache memoises on the arguments — which requires them to be hashable, and leaks if the key space is unbounded. cache is the unbounded form.
  • Always use try/finally in a timing or resource decorator, or exceptions skip your teardown.
L3 · Advanced

Where decorators get expensive

  • Class-based decorators (__call__) hold state cleanly, but an instance is not a descriptor — decorating a method loses the automatic self binding unless you implement __get__.
  • Order with classmethod/staticmethod matters: those must be outermost, because what they wrap has to be a plain function.
  • Stacking applies bottom-up — the decorator nearest the def wraps first and ends up innermost, which is the opposite of reading order.
  • Decorators hide signatures: a bare *args, **kwargs wrapper erases the parameter list for the type checker and the IDE. ParamSpec restores it.
  • Every decorator adds a frame to the traceback and a call to the hot path. Cheap individually, visible five deep.
