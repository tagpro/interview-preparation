Part six

The front door

Something has to accept the connection, decide it is allowed, and pick a backend. Whether that is a load balancer or API Gateway changes your latency floor, your per-request cost and the vocabulary of your 5xx errors.

Load balancers, and what each 5xx actually means

An ALB is a listener, a set of rules, and target groups with health checks. Four numbers — idle timeout, keep-alive, deregistration delay and health check thresholds — produce nearly every mysterious error it will ever show you.

SettingDefaultConsiderWhy
Idle timeout60sJust above your slowest endpointIt bounds every request. A long-poll or a streaming response needs it raised deliberately, not accidentally.
Deregistration delay300sSlightly longer than your longest request — often 30sFive minutes per task makes every rolling deploy glacial. Too short truncates requests in flight.
Health check interval / threshold30s, 2 unhealthy (healthy threshold 5)10s, 2The defaults still take about a minute to remove a dead target. That is a long time to serve errors.
Health check path/A dedicated /healthz that checks nothing downstreamA health check that queries the database turns one slow database into zero healthy targets, fleet-wide.
AlgorithmRound robinLeast outstanding requestsRound robin sends work to a task that is already stuck. LOR routes around it automatically.
Cross-zoneOn for ALB, off for NLBOn, and know the costOff means an imbalanced zone gets an imbalanced share. On means cross-AZ data transfer charges on NLB.
Access logsOffOn, to S3, with a lifecycle ruleThey contain the target processing time, the target status and the TLS details. Without them a 502 investigation is guesswork.
 
// An HTTP server configured for life behind an ALB. Every timeout here exists
// to fail in a way you can reason about.
srv := &http.Server{
    Addr:              ":8080",
    Handler:           mux,
    ReadHeaderTimeout: 5 * time.Second,     // slow-header attacks, and stuck clients
    ReadTimeout:       15 * time.Second,
    WriteTimeout:      30 * time.Second,
    // THE important one: strictly greater than the ALB idle timeout (60s),
    // so the balancer always closes idle connections, never the application.
    IdleTimeout: 75 * time.Second,
}

// Two endpoints, two meanings. Conflating them is how a slow database becomes
// a fleet-wide outage.
mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, r *http.Request) {
    // Liveness: am I this process, and is my event loop turning? Nothing else.
    w.WriteHeader(http.StatusOK)
})

mux.HandleFunc("GET /readyz", func(w http.ResponseWriter, r *http.Request) {
    // Readiness: should the load balancer send me traffic right now?
    // Flipped to false by the SIGTERM handler before the drain begins.
    if !ready.Load() {
        w.WriteHeader(http.StatusServiceUnavailable)
        return
    }
    w.WriteHeader(http.StatusOK)
})

// The client’s real address is in X-Forwarded-For, appended by the ALB. Trust
// only the LAST entry — anything earlier is client-supplied and forgeable.
func clientIP(r *http.Request) string {
    xff := r.Header.Values("X-Forwarded-For")
    if len(xff) == 0 {
        return r.RemoteAddr
    }
    parts := strings.Split(xff[len(xff)-1], ",")
    return strings.TrimSpace(parts[len(parts)-1])
}

def client_ip(request: Request) -> str:
    # The client’s real address is in X-Forwarded-For, appended by the ALB.
    # Trust only the LAST entry — anything earlier is forgeable by the client.
    xff = request.headers.get("x-forwarded-for")
    if not xff:
        return request.client.host
    return xff.split(",")[-1].strip()

NLB when you need layer four

Static IP addresses per zone, source IP preserved to the target, millions of connections, and no HTTP awareness at all. Choose it for non-HTTP protocols, for clients that must allow-list an IP, and for extreme connection counts. Everything else wants an ALB, where routing rules and WAF live.

Health checks must not cascade

If /healthz checks the database, then one database blip marks every target unhealthy at the same moment. The load balancer falls back to routing at unhealthy targets anyway, ECS starts replacing tasks that were never broken, and a slow dependency becomes a fleet-wide restart. Check dependencies in readiness at most, and even then with a stale-tolerant cached result.

API Gateway, and the three cheaper things it competes with

API Gateway is four products in one name. Most teams need the HTTP API, some need REST’s older feature set, and a fair number would be better served by a Function URL or an ALB — at a tenth of the price.

// An HTTP API (payload format 2.0) handler. The event shape is different from
// the REST API’s v1 — routeKey, http.method, and a flattened single-value
// header map are the differences that bite when you migrate.
func handle(ctx context.Context, req events.APIGatewayV2HTTPRequest) (
    events.APIGatewayV2HTTPResponse, error) {

    id := req.PathParameters["id"]                       // from route GET /orders/{id}

    // The authorizer’s output arrives here — already verified, so do not
    // re-parse the token, and never trust a claim you did not configure.
    tenant, _ := req.RequestContext.Authorizer.JWT.Claims["tenant_id"]

    order, err := app.load(ctx, tenant, id)
    switch {
    case errors.Is(err, ErrNotFound):
        return jsonErr(404, "not_found", "no such order"), nil
    case err != nil:
        // Returning an error gives the caller an opaque 500 and no body.
        // Prefer an explicit response you control, and log the detail.
        log.Error("load order", "id", id, "err", err)
        return jsonErr(500, "internal", "try again"), nil
    }

    body, _ := json.Marshal(order)
    return events.APIGatewayV2HTTPResponse{
        StatusCode: 200,
        Headers: map[string]string{
            "content-type":  "application/json",
            "cache-control": "no-store",
        },
        Body: string(body),
    }, nil
}
# An HTTP API (payload format 2.0) handler. The event shape differs from the
# REST API’s v1 — routeKey, requestContext.http.method, and single-value
# headers are the differences that bite when you migrate.
from aws_lambda_powertools.event_handler import APIGatewayHttpResolver
from aws_lambda_powertools.event_handler.exceptions import NotFoundError

app_router = APIGatewayHttpResolver()


@app_router.get("/orders/<order_id>")
def get_order(order_id: str):
    # The authorizer’s output arrives already verified — do not re-parse the
    # token, and never trust a claim you did not configure the authorizer to check.
    claims = app_router.current_event.request_context.authorizer.jwt_claim
    tenant = claims["tenant_id"]

    order = load(tenant, order_id)
    if order is None:
        raise NotFoundError                     # becomes a clean 404 JSON body

    return Response(
        status_code=200,
        content_type="application/json",
        headers={"cache-control": "no-store"},
        body=json.dumps(order),
    )


@logger.inject_lambda_context

ConceptDetail worth knowing
Integration timeout29 seconds is the long-standing maximum, and on REST APIs it can now be raised by quota. Anything longer needs an asynchronous pattern: accept, return 202 with a status URL, and do the work behind a queue.
AuthorizersJWT authorizers on HTTP APIs validate an OIDC token natively — no code, no cold start. A Lambda authorizer is for anything else, and its result is cacheable by identity source for up to an hour.
StagesA deployment is immutable; a stage points at one. Stage variables plus a canary deployment give you a percentage rollout on REST APIs without touching the client.
Private integrationA VPC link lets the gateway reach an internal ALB or Cloud Map service, so “public API, private compute” needs no public subnet at all.
CORSConfigured on the API for HTTP APIs, which then answers OPTIONS itself. On REST APIs it is a mock integration you must create per resource — a classic half-day.
Access logsOff by default. The $context variables carry the request id, the integration latency and the authorizer result — the three fields you need to tell “slow backend” from “slow gateway”.
Payload limits10 MB request, and Lambda’s own 6 MB synchronous response cap sits behind it. Large uploads belong on a presigned S3 URL, not through the gateway.
