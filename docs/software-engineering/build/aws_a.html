Part one

The contract every service shares

Before any single service, three things are true of all of them: your code gets credentials from a chain it did not write, every call is wrapped in retries and signing you cannot see, and the packet has to physically leave your subnet. Most “the SDK is broken” incidents are one of these three.

AWS · 00

The client, the credential chain and the retry

An AWS client is not a connection. It is a credential provider, a retryer, a signer and an HTTP pool bolted together — and each of those four has a default that is wrong for a busy service.

Snippets below in Go and Python — switch with the control in the bar, or press g / p.

// config.go — built once at start-up, shared by every client in the process.
cfg, err := config.LoadDefaultConfig(ctx,
    config.WithRegion("eu-west-1"),
    config.WithRetryer(func() aws.Retryer {
        // Standard: 3 attempts, exponential backoff with full jitter, and a
        // token bucket so a storm of retries cannot amplify an outage.
        // retry.NewAdaptiveMode wraps it with a client-side rate limiter that
        // slows you down when the service starts throttling.
        return retry.NewStandard(func(o *retry.StandardOptions) {
            o.MaxAttempts = 5
            o.MaxBackoff = 3 * time.Second
        })
    }),
    config.WithHTTPClient(awshttp.NewBuildableClient().
        WithTimeout(10*time.Second).                // PER ATTEMPT, not per call
        WithTransportOptions(func(t *http.Transport) {
            t.MaxIdleConnsPerHost = 100             // the SDK client defaults to 10
        })),
)
if err != nil {
    return fmt.Errorf("aws config: %w", err)        // fail the process, not the request
}

// One client per service. They are goroutine-safe and hold the pool.
app := &App{
    ddb: dynamodb.NewFromConfig(cfg),
    s3:  s3.NewFromConfig(cfg, func(o *s3.Options) { o.UsePathStyle = false }),
    sqs: sqs.NewFromConfig(cfg),
}
# aws.py — imported once; module-level clients live for the whole process.

Errors: the code matters more than the message

Every AWS error carries a code, an HTTP status and a request ID. Branch on the code — never on the message text, which AWS reserves the right to reword. The request ID is what support asks for, so log it.

// Typed errors: the modelled ones have Go types, the rest satisfy smithy.APIError.
_, err := app.ddb.PutItem(ctx, &dynamodb.PutItemInput{
    TableName:           aws.String("orders"),
    Item:                item,
    ConditionExpression: aws.String("attribute_not_exists(pk)"),
})

var dup *types.ConditionalCheckFailedException
var thr *types.ProvisionedThroughputExceededException
var api smithy.APIError

switch {
case errors.As(err, &dup):
    return ErrAlreadyExists                       // not an error: someone won the race
case errors.As(err, &thr):
    return backoffAndRetryLater(ctx)              // the SDK already tried; the table is hot
case errors.As(err, &api):
    // RequestID is on the response metadata, not on the error itself
    var re *awshttp.ResponseError
    id := ""
    if errors.As(err, &re) {
        id = re.ServiceRequestID()
    }
    log.Error("aws call failed", "code", api.ErrorCode(),
        "fault", api.ErrorFault().String(),       // client | server | unknown
        "request_id", id)
    return err
case err != nil:
    return err                                    // context cancelled, DNS, TLS…
}
# botocore raises ClientError for anything the service returned; the shape is
# always the same, and every client exposes its modelled errors as attributes.
from botocore.exceptions import ClientError, EndpointConnectionError

try:
    DDB.put_item(
        TableName="orders",
        Item=item,
        ConditionExpression="attribute_not_exists(pk)",
    )
except DDB.exceptions.ConditionalCheckFailedException:
    raise AlreadyExists                    # not an error: someone won the race
except DDB.exceptions.ProvisionedThroughputExceededException:
    raise Retryable("table is hot")        # the SDK already retried; still throttled
except ClientError as e:
    err = e.response["Error"]
    meta = e.response["ResponseMetadata"]
    log.error(
        "aws call failed",
        extra={
            "code": err["Code"],                          # branch on THIS
            "status": meta["HTTPStatusCode"],
            "request_id": meta["RequestId"],              # what support will ask for
            "attempts": meta.get("RetryAttempts"),        # how many the SDK burned
        },
    )
    raise
except EndpointConnectionError:            # never reached the service at all:
    raise Unreachable                      # DNS, route, security group, endpoint

Pagination and waiters, without the loop you always get wrong

Every list-shaped AWS API is paginated, and the page you get back is capped by size as well as count — a Query can return zero items and still hand you a continuation token because it scanned 1 MB of non-matching rows. Never treat an empty page as the end. Both SDKs ship paginators that get this right; use them.

p := s3.NewListObjectsV2Paginator(app.s3, &s3.ListObjectsV2Input{
    Bucket: aws.String("orders-archive"),
    Prefix: aws.String("2026/08/"),
})
for p.HasMorePages() {
    page, err := p.NextPage(ctx)          // ctx cancels mid-listing
    if err != nil {
        return err
    }
    for _, o := range page.Contents {
        handle(aws.ToString(o.Key), aws.ToInt64(o.Size))
    }
}

// Waiters poll for you, with the service’s own recommended interval —
// and, crucially, with a maximum wait, so a stuck resource fails the deploy.
w := rds.NewDBInstanceAvailableWaiter(app.rds)
err = w.Wait(ctx, &rds.DescribeDBInstancesInput{
    DBInstanceIdentifier: aws.String("orders-prod"),
}, 20*time.Minute)
for page in S3.get_paginator("list_objects_v2").paginate(
    Bucket="orders-archive",
    Prefix="2026/08/",
    PaginationConfig={"PageSize": 1000},          # per request, not a total cap
):
    for obj in page.get("Contents", []):          # .get: an empty page has no key
        handle(obj["Key"], obj["Size"])

# Server-side filtering beats client-side: JMESPath runs in botocore, but
# search() still downloads every page — use Prefix/StartAfter where you can.
keys = S3.get_paginator("list_objects_v2").paginate(
    Bucket="orders-archive", Prefix="2026/08/"
).search("Contents[?Size > `0`].Key")

# Waiters: the service’s own polling loop, with a bounded maximum.
RDS.get_waiter("db_instance_available").wait(
    DBInstanceIdentifier="orders-prod",
    WaiterConfig={"Delay": 30, "MaxAttempts": 40},   # 20 minutes, then raise
)

Region is not a formality

The region decides the endpoint, the signing scope and the price. A client with no region falls back to the environment, then the profile, then fails — and in Lambda it silently inherits the function’s region, which is why code that works deployed fails on a laptop.

The retry you did not order

SDK retries are invisible in your traces unless you look for them. In Go, retry.AddWithMaxAttempts and the attempt metrics; in Python, ResponseMetadata.RetryAttempts. A p99 that is exactly 3× your p50 is a retry story, not a slow-service story.

IAM: the evaluation order, and how a process gets a role

IAM is not a list of permissions. It is a decision function run per request over up to six policy types, and it answers “deny” unless something explicitly allows — and nothing explicitly denies.

PrincipalA user has long-lived keys. A role has none — it is assumed, and hands out credentials that expire. Production code should only ever use roles.
Trust policyThe resource policy of the role itself. Names the principal allowed to assume it: a service, an account, or an OIDC provider with a sub condition.
BoundaryA ceiling attached to an identity. Lets you delegate “you may create roles” without letting the delegate create an admin role.
Condition keysWhere real least privilege lives: aws:PrincipalOrgID, aws:SourceVpce, s3:prefix, aws:SecureTransport, sts:ExternalId.

Assuming a role from code — and refreshing it

The one detail people miss: AssumeRole returns credentials with a fixed expiry. If your process outlives it and you did not wrap the call in something that refreshes, you get a clean, confusing ExpiredToken an hour after deploy.

// Cross-account: assume the data account’s reader role. NewCredentialsCache
// is what makes this safe for a long-lived process — it refreshes shortly
// before expiry and serialises concurrent refreshes into one STS call.
base, err := config.LoadDefaultConfig(ctx, config.WithRegion("eu-west-1"))
if err != nil {
    return err
}

prov := stscreds.NewAssumeRoleProvider(sts.NewFromConfig(base),
    "arn:aws:iam::222233334444:role/orders-reader",
    func(o *stscreds.AssumeRoleOptions) {
        o.RoleSessionName = "orders-" + hostname       // shows up in CloudTrail
        o.Duration = 30 * time.Minute                  // short: blast radius of a leak
        o.ExternalID = aws.String(externalID)          // third-party: confused deputy
        o.Tags = []types.Tag{                          // session tags can drive ABAC
            {Key: aws.String("service"), Value: aws.String("orders")},
        }
    })

cross := base.Copy()
cross.Credentials = aws.NewCredentialsCache(prov)
reader := dynamodb.NewFromConfig(cross)

// Who am I, really? The first line of any IAM debugging session.
who, err := sts.NewFromConfig(cross).GetCallerIdentity(ctx, nil)
log.Info("identity", "arn", aws.ToString(who.Arn))     // .../orders-reader/orders-h7
# boto3’s assume_role returns FIXED credentials — fine for a script, a trap
# for a server. For anything long-lived, hand botocore a refreshable provider
# so it re-assumes before expiry instead of dying with ExpiredToken.
from botocore.credentials import DeferredRefreshableCredentials
from botocore.session import get_session

STS = boto3.client("sts")
ROLE = "arn:aws:iam::222233334444:role/orders-reader"


def _fetch():
    r = STS.assume_role(
        RoleArn=ROLE,
        RoleSessionName=f"orders-{HOSTNAME}",     # shows up in CloudTrail
        DurationSeconds=1800,                     # short: blast radius of a leak
        ExternalId=EXTERNAL_ID,                   # third-party: confused deputy
        Tags=[{"Key": "service", "Value": "orders"}],   # session tags drive ABAC
    )["Credentials"]
    return {
        "access_key": r["AccessKeyId"],
        "secret_key": r["SecretAccessKey"],
        "token": r["SessionToken"],
        "expiry_time": r["Expiration"].isoformat(),
    }


_bs = get_session()
_bs._credentials = DeferredRefreshableCredentials(_fetch, "assume-role")
CROSS = boto3.Session(botocore_session=_bs)
reader = CROSS.client("dynamodb", config=CFG)

# Who am I, really? First line of any IAM debugging session.
print(CROSS.client("sts").get_caller_identity()["Arn"])   # .../orders-reader/orders-h7

The policy you should actually write

A policy with "Resource": "*" is a policy you will never be able to audit. Scope by resource ARN, then narrow further with conditions — the two below are the highest-value conditions on the platform, and neither costs you anything.

// The same JSON, whichever language calls it. Two things make it real:
// a resource ARN with a prefix, and conditions that survive a leaked key.
policy := `{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadOwnTenantObjects",
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::orders-archive/tenant/${aws:PrincipalTag/tenant}/*",
      "Condition": {
        "Bool":        {"aws:SecureTransport": "true"},
        "StringEquals":{"aws:SourceVpce": "vpce-0abc123"}
      }
    },
    {
      "Sid": "DenyEverythingOutsideTheOrg",
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*",
      "Condition": {"StringNotEquals": {"aws:PrincipalOrgID": "o-exampleorgid"}}
    }
  ]
}`

// Pass it as a session policy to shrink a broad role for one job.
o.Policy = aws.String(policy)   // inside AssumeRoleOptions: intersects, never grants

Read the denial, it tells you which rule fired

“User: arn:…/task-role is not authorized to perform: s3:GetObject … because no identity-based policy allows” means step 6 found nothing. “…with an explicit deny in a service control policy” means step 1 or 2, and no amount of editing the role will help. IAM Access Analyzer’s policy generator will write a first draft from 90 days of CloudTrail — a far better starting point than *.

Where your code sits in the network

A private subnet has no route to the internet. Everything that follows — NAT bills, timing-out Lambdas, endpoints, security-group loops — is a consequence of that one sentence.

Make the network failure legible at boot

The worst version of this bug is a service that starts healthy, passes its health check, and only fails when the first real request needs S3. A ten-line probe at start-up turns a 3 a.m. mystery into a log line.

// reachable dials the service endpoint and separates the failure modes:
// name resolution (DNS / private DNS) from the TCP handshake (route / SG).
func reachable(ctx context.Context, host string) error {
    ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
    defer cancel()

    ips, err := net.DefaultResolver.LookupHost(ctx, host)
    if err != nil {
        // private DNS off on the interface endpoint, or DNS support off on the VPC
        return fmt.Errorf("dns %s: %w", host, err)
    }

    var d net.Dialer
    conn, err := d.DialContext(ctx, "tcp", net.JoinHostPort(host, "443"))
    if err != nil {
        // resolved but unreachable: no route, no egress rule, or no endpoint
        return fmt.Errorf("dial %s (%v): %w", host, ips[0], err)
    }
    _ = conn.Close()
    return nil
}

// At start-up, before the health check goes green:
for _, h := range []string{
    "sts.eu-west-1.amazonaws.com",              // credentials
    "dynamodb.eu-west-1.amazonaws.com",         // gateway endpoint or NAT
    "secretsmanager.eu-west-1.amazonaws.com",   // interface endpoint only
} {
    if err := reachable(ctx, h); err != nil {
        return fmt.Errorf("startup connectivity: %w", err)   // crash loudly, now
    }
}
# reachable() dials the service endpoint and separates the failure modes:
# name resolution (DNS / private DNS) from the TCP handshake (route / SG).
import socket


def reachable(host: str, port: int = 443, timeout: float = 3.0) -> None:
    try:
        infos = socket.getaddrinfo(host, port, proto=socket.IPPROTO_TCP)
    except socket.gaierror as e:
        # private DNS off on the interface endpoint, or DNS support off on the VPC
        raise Unreachable(f"dns {host}: {e}") from e

    family, kind, proto, _, addr = infos[0]
    with socket.socket(family, kind, proto) as s:
        s.settimeout(timeout)
        try:
            s.connect(addr)
        except OSError as e:
            # resolved but unreachable: no route, no egress rule, or no endpoint
            raise Unreachable(f"dial {host} ({addr[0]}): {e}") from e


# At start-up, before the health check goes green:
for host in (
    "sts.eu-west-1.amazonaws.com",              # credentials
    "dynamodb.eu-west-1.amazonaws.com",         # gateway endpoint or NAT
    "secretsmanager.eu-west-1.amazonaws.com",   # interface endpoint only
):
    reachable(host)                             # crash loudly, now, not at 03:00
ConceptWhat it really isThe detail that bites
SubnetA CIDR pinned to one availability zone, with one route tableAWS reserves 5 addresses per subnet. A /28 gives you 11 usable IPs — and one ECS task in awsvpc mode takes one each.
Public vs privatePurely whether the route table has 0.0.0.0/0 → igwThere is no “public subnet” setting. A subnet is public because of a route, and instances also need a public IP to use it.
NAT gatewayA managed SNAT device in a public subnet, per AZCharged hourly and per gigabyte processed. One per AZ for resilience triples the hourly cost; one shared across AZs adds cross-AZ transfer to every byte.
Gateway endpointA route table entry for S3 or DynamoDBFree, and the single highest-return change on most bills. If your NAT charge is dominated by S3 traffic, this deletes it.
Interface endpointAn ENI in your subnet with private DNS for one servicePriced per AZ per hour plus data. Worth it above roughly a terabyte a month, or whenever compliance forbids the public path.
Security groupA stateful allow-list on an ENIReference other groups, not CIDRs. sg-app → sg-db:5432 keeps working when the app fleet is replaced.
Lambda in a VPCHyperplane ENIs shared across invocationsSince 2019 this costs no per-invocation ENI setup — but a VPC Lambda still has no internet unless the subnet routes to NAT, which surprises people calling third-party APIs.

Plan addresses before you plan anything else

A VPC CIDR cannot be shrunk, and every workload that uses awsvpc networking — Fargate tasks, EKS pods with the VPC CNI, VPC Lambdas — consumes real subnet addresses. A /16 split into three /20 private subnets gives you about 4,000 usable addresses per zone, which sounds infinite until a pod-per-request architecture arrives. Size private subnets at least two rungs larger than you think, and keep a spare /20 unallocated in each zone.
