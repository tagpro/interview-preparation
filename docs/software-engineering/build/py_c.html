Part six

Memory and speed

Python costs roughly 10–100× a compiled language per operation, and every value is a heap object with a header. Neither fact is fixable by rewriting a loop more cleverly. What is fixable: doing fewer operations, holding fewer objects, and knowing which measurement answers which question.

Python · 00

How CPython holds an object, and what that costs

Every value is a separately allocated heap object carrying a reference count and a type pointer, and every container holds pointers to those objects rather than the values themselves. That is why an int is 28 bytes and a list of a million of them is not eight megabytes.

import sys

sys.getsizeof(1)             # 28   -- refcount, type, size, one digit
sys.getsizeof(2**64)         # 36   -- three 30-bit digits now
sys.getsizeof("hello")       # 54   -- 49 of header, 1 byte per ASCII char
sys.getsizeof([0] * 1000)    # 8056 -- 56 header + 8 per slot, and nothing else

xs = [1234 + i for i in range(1_000_000)]
sys.getsizeof(xs)                    # about 8.4 MB: the pointer array only
sum(sys.getsizeof(x) for x in xs)    # about 28 MB more: what it points at

class Point:                         # a dict per instance, any attribute allowed
    def __init__(self, x: float, y: float) -> None:
        self.x, self.y = x, y

class Slim:
    __slots__ = ("x", "y")           # fixed offsets, no __dict__, typos raise
    def __init__(self, x: float, y: float) -> None:
        self.x, self.y = x, y
# a cycle: refcounting alone never frees this pair -- only the collector can
class Node:
    def __init__(self, name: str) -> None:
        self.name, self.parent, self.children = name, None, []

    def add(self, child: "Node") -> None:
        child.parent = self          # parent -> child -> parent: a cycle
        self.children.append(child)

# fix: the back-reference doesn't need to keep the parent alive
import weakref
child.parent = weakref.ref(root)     # dies with root, not with child

import gc, os
gc.freeze()                          # at start-up, after imports, before fork():
os.fork()                            # stops the collector from touching every object's refcount
                                      # and un-sharing every copy-on-write page across workers
L1 · Beginner

Objects, references, and a shallow ruler

  • Everything is a heap object — an int, a string, a function, a class — each carrying a reference count and a type pointer before any data.
  • Containers hold references. Copying a list copies pointers, which is why b = a[:] gives you a new list of the same objects.
  • sys.getsizeof is shallow: it measures the container itself, not the objects it refers to.
  • Small ints (−5 to 256) and some short strings are cached, so is occasionally looks true by accident. Compare with ==.
  • Two numbers worth memorising: an int is 28 bytes, a list slot is 8.
L2 · Intermediate

Hold fewer objects, and smaller ones

  • __slots__ on classes you create by the hundred thousand: fixed offsets instead of a per-instance dict, and a misspelt attribute becomes an error instead of a new field.
  • Lists over-allocate on growth, which is what makes append amortised O(1) — so append in a loop is rarely the thing to fix.
  • Generators and yield stream a pipeline instead of materialising each stage; peak memory becomes one item rather than n.
  • array.array, bytes, memoryview for homogeneous data: one contiguous buffer of values instead of n pointers to n objects.
  • sys.intern for strings you compare or key on constantly — identical objects short-circuit the character-by-character compare.
L3 · Advanced

Refcounts, cycles, and RSS that never falls

  • Reference counting frees immediately; the generational collector exists only for cycles. Deterministic release is why with works so well and why a stray reference in a traceback keeps a whole object graph alive.
  • gc.freeze() after imports and before fork(): the collector otherwise touches the refcount of every shared object, un-sharing copy-on-write pages until each worker owns a private copy of your imports.
  • weakref and WeakValueDictionary for caches and observer registries, so the cache is not the leak.
  • RSS does not fall after a spike. Freed memory returns to CPython’s arenas, not the OS, and one live object pins a whole arena. Fragmentation looks exactly like a leak on a graph.
  • Where Python stops being the answer: a million small records wants NumPy or a columnar buffer; a leak you cannot find wants a worker process recycled every N requests.

Finding the slow part, then fixing it

Each tool answers exactly one question, and the common failure is reading a CPU profile for a problem that was never CPU. Pick the tool from the symptom, not from habit.

# 1. where does the time go
python -m cProfile -o run.prof -m myapp.batch
python -c "import pstats; pstats.Stats('run.prof').sort_stats('cumulative').print_stats(15)"

# 2. is this really faster than that
python -m timeit -s "xs = list(range(1000))" "sum(xs)"

# 3. what grew between here and there
import tracemalloc
tracemalloc.start()
before = tracemalloc.take_snapshot()
handle_batch()
for stat in tracemalloc.take_snapshot().compare_to(before, "lineno")[:10]:
    print(stat)             # file:line, size delta, count delta

# 4. production, right now, with no restart and no redeploy
py-spy top --pid 4131
py-spy dump --pid 4131      # every thread's Python stack, as it stands
L1 · Beginner

Measure before you change anything

  • Never optimise what you have not timed. Intuition about which Python line is slow is wrong roughly half the time.
  • time.perf_counter() for durations: monotonic, and the highest resolution the platform offers.
  • time.time() is the wrong clock — it is a wall clock that NTP can step backwards, so a duration computed from it can come out negative.
  • timeit for anything under a millisecond: it runs the snippet many times and reports the best, because the mean is mostly noise from other processes.
  • Write the number down before and after. “It feels faster” is not a result.
L2 · Intermediate

Find the hot spot, then confirm it

  • cProfile to a file, then pstats sorted by cumulative time. Cumulative finds the expensive subtree; tottime finds the expensive function itself.
  • Read the call tree downwards. The leaf with the huge tottime is often a stdlib function called two million times — the fix is in the caller, not the leaf.
  • tracemalloc snapshots and compare_to for growth: it names the allocating line, which a total heap size never does.
  • line_profiler (kernprof -l) when the hot function is forty lines and the cost is one of them.
  • functools.lru_cache on a pure function with a bounded key space — the cheapest win there is, until the cache pins objects you wanted freed.
L3 · Advanced

Sampling, the observer effect, and the ladder

  • Deterministic profilers instrument every call. cProfile costs 2–3× and distorts exactly the many-small-calls code you were investigating — you profile the profiler.
  • Sampling profilers read stacks from outside the process at a fixed rate: small constant overhead, nothing imported into your app, safe to attach to a live pod. py-spy record for a flame graph, py-spy dump for a hung process.
  • The ladder, in order: a better algorithm → fewer Python-level operations → vectorise with NumPy → a C extension or Rust via PyO3 → another process or another language.
  • Skipping rungs wastes weeks. A Rust extension wrapped around a quadratic algorithm is still quadratic, and now nobody on the team can change it.
  • The honest baseline: the interpreter costs roughly 10–100× a compiled language per operation. That gap is why the winning move is almost always to perform fewer operations, not faster ones.

The performance patterns worth knowing by heart

A short list of rewrites that are always worth making, because each one moves work out of the interpreter or removes it entirely. None of them need a profiler to justify — but a profiler will tell you which one matters here.

s += chunk in a loop"".join(parts)Each += allocates a new string and copies everything so far. join measures once, allocates once, copies once.

math.sqrt(...) or self.total looked up inside a hot loopBind it to a local first: sqrt = math.sqrtEvery attribute and global reference is a dictionary lookup at run time; a local is an index into the frame. Worth 10–20% in a tight loop, and nothing at all elsewhere.

The order to apply these in

Top to bottom, these are worth between nothing and a hundredfold, and the table cannot tell you which. Apply the ones that cost nothing in readability everywhere — join, sets for membership, generators, batched queries — and apply the rest only where a measurement pointed. Binding locals and unrolling loops in code that runs twice a day is how a codebase becomes unreadable for no gain.

Part seven

Production Python

A dynamic language moves a class of errors from compile time to run time, which is where tests, logs and configuration validation have to catch them instead. None of this is Python-specific in principle; all of it is Python-specific in the details.

Python · 00

Tests that catch what Python actually gets wrong

There is no compiler to tell you that a name is misspelt or an argument is the wrong type on the path nobody ran. Tests are the type checker for the paths you actually care about — and pytest’s mechanics decide how much they cost to keep.

import pytest
from app.orders import Order, parse_qty

@pytest.fixture(scope="module")
def store(tmp_path_factory):
    path = tmp_path_factory.mktemp("data") / "orders.db"
    s = Store(path)          # setup: once per test file
    yield s                  # the tests in this module run here
    s.close()                # teardown: runs even if a test fails

@pytest.mark.parametrize(
    "raw, want",
    [("3", 3), (" 3 ", 3), ("03", 3), ("", None), ("x", None)],
    ids=["plain", "padded", "leading-zero", "empty", "not-a-number"],
)
def test_parse_qty(raw, want):
    assert parse_qty(raw) == want

def test_rejects_negative_quantity(store, monkeypatch):
    monkeypatch.setattr("app.orders.now", lambda: FIXED_TIME)
    with pytest.raises(ValueError, match="quantity"):
        store.add(Order(qty=-1))
L1 · Beginner

pytest, and one behaviour per test

  • pytest finds test_*.py and functions named test_*. No class, no base class, no registration.
  • A plain assert is enough — pytest rewrites it so a failure shows both sides, which is why you never need assertEqual.
  • Arrange, act, assert, in that order, with a blank line between the three.
  • One behaviour per test, named for the behaviour: test_rejects_negative_quantity, not test_order_2.
  • Test the public function, not the private helper. The helper must stay free to change.
L2 · Intermediate

Fixtures, parameters, and the seams

  • A fixture is setup and teardown around a yield; naming it as an argument is the entire wiring mechanism. Shared ones live in conftest.py, imported by nobody.
  • scope decides how often it runs: function (the default), class, module, session. Session for a container or a pool; function for anything mutable.
  • parametrize with ids fans one body into many named cases, each reported separately, so the failure names the input.
  • monkeypatch for environment variables, attributes and the working directory — reverted automatically, unlike mock.patch applied by hand.
  • tmp_path for files, pytest.raises(ValueError, match=…) for errors, and markers plus -m "not slow" to keep the fast set fast.
L3 · Advanced

Tests that survive a refactor

  • Fakes over mocks. A small in-memory implementation of your own interface tests behaviour; assert_called_once_with tests today’s call graph and breaks on every refactor that found no bug.
  • Patch only at seams you own. mock.patch("app.module._helper") welds the test to an implementation detail — passing the collaborator in does not.
  • Time is an input. Inject a clock (now: Callable[[], datetime]) or use freezegun; a time.sleep in a test is a slow flake waiting for a loaded CI runner.
  • Property-based testing with Hypothesis: state the invariant — parse(format(x)) == x — and let it find the empty string, the surrogate pair and the boundary you would never have typed.
  • Coverage is a signal, not a target: it shows what never ran. A suite with no assertions can reach 100%. Mutation testing (mutmut) asks the sharper question — if I break the code, does anything fail?

Logging, configuration, and shipping it

Three decisions decide whether a running service can be debugged: what the logs carry, where the configuration comes from, and what exactly is inside the image. All three are made once, at start-up, in main.

# any library module: take a logger, never configure one
log = logging.getLogger(__name__)

def charge(order_id: str) -> None:
    log.info("charging", extra={"order_id": order_id, "req": request_id.get()})

# main.py: configure once, fail fast, drain on SIGTERM
def main() -> None:
    cfg = Config.from_env()          # SystemExit now beats a 500 later
    logging.basicConfig(level=cfg.log_level, handlers=[JsonHandler(sys.stdout)])
    server = make_server(cfg)

    stopping = threading.Event()

    def on_sigterm(signum, frame) -> None:
        ready.clear()                # 1. readiness starts failing
        stopping.set()               # 2. flip a flag -- a handler must never block

    signal.signal(signal.SIGTERM, on_sigterm)
    threading.Thread(target=server.serve_forever, daemon=True).start()
    stopping.wait()                  # main thread parks here until SIGTERM
    time.sleep(5)                    # 3. keep serving while the LB notices
    server.shutdown()                # 4. stop accepting, drain in flight
L1 · Beginner

Logging and configuration, plainly

  • logging, not print: levels, a timestamp, the module name, and a destination the operator chooses rather than you.
  • The levels mean something — DEBUG for you, INFO for lifecycle events, WARNING for something a human may need to look at, ERROR for a request that failed, CRITICAL for the process.
  • Configure exactly once, in main, at start-up. A library that calls basicConfig has stolen a decision that belongs to the application.
  • In every module: log = logging.getLogger(__name__). The dotted name gives per-package level control for free.
  • log.exception("…") inside an except records the traceback; log.error(str(e)) throws it away.
L2 · Intermediate

Structured logs, env config, a locked image

  • One JSON object per line, with fields — request_id, order_id, duration_ms — not an English sentence you will later have to write a regex against.
  • A correlation id minted at the edge, kept in a ContextVar so every record and every outbound header carries it. This is where these logs join the traces from the cloud page.
  • Config from environment variables, parsed into one frozen object and validated at start-up. A missing setting should kill the process in the first second, not the first request.
  • A committed lockfile and uv sync --frozen (or pip install -r a compiled requirements file) so CI and production resolve to identical versions.
  • A slim base image, dependencies in their own layer, non-root user. python -X dev turns on extra runtime checks in staging; python -O strips asserts, which is why an assert must never be your validation.
L3 · Advanced

What running it actually costs

  • Log volume is money and cardinality. One INFO line per request at 5,000 req/s is over 400 million lines a day: sample the routine ones, keep every error, and never put a user id or a full URL in a metric label.
  • SIGTERM, in the Go page’s order: fail readiness, wait for the load balancer to notice, stop accepting, drain in-flight work, close pools, exit. Python’s default on SIGTERM is to die immediately, mid-request.
  • Liveness and readiness are different questions — “should you kill me” versus “should you send me traffic”. A liveness probe that checks the database restarts your app whenever the database is slow.
  • Worker models: gunicorn with N sync workers is one process per core, no shared memory, and the safe default for blocking code; uvicorn/ASGI workers give I/O concurrency inside each process. Threads help only where the work releases the GIL.
  • A Python process is not a static binary. The interpreter, the C extensions and every wheel are part of what you ship, so the image — pinned by digest — is your dependency contract. There is nothing else to hand over.

The Python review checklist

Fifteen things worth a second look in any Python diff. Each takes about five seconds to check and can cost an afternoon to debug later — and roughly half of them a linter will find before you do.

The two questions behind all fifteen

“Who owns this object, and when is it released?” — which covers files, sockets, pools, caches, tasks and the references that keep them all alive. And “what does this do when the thing it calls never answers?” — the same question the Go page ends on, and the one that decides whether a slow dependency becomes a slow endpoint or a dead service. Every item above is one of those two, asked about a specific line.
