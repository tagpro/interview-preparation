Part three

Key-value, objects and cache

DynamoDB and S3 are the two services that will still be under your architecture in ten years, and both punish the same mistake: designing for the data you have rather than the access pattern you will run against it a million times a day.

AWS · 00

DynamoDB: the partition key is the design

Every DynamoDB property — the latency, the throughput ceiling, the queries you can and cannot run, the bill — follows from one decision: what you hash to choose a partition. Change your mind later and it is a migration, not an ALTER TABLE.

Capacity units1 WCU = one 1 KB write. 1 RCU = one 4 KB strongly consistent read, or two eventually consistent. Transactions cost double, both ways.
Hard limitsItem 400 KB. Query or Scan page 1 MB before your filter runs. BatchWriteItem 25 items, TransactWriteItems 100.
On-demandPay per request, no planning, instant doubling of the previous peak. Roughly 3–4× the unit price of provisioned since the 2024 price cut — and worth it below about 30% steady utilisation.
StreamsA 24-hour ordered log per partition key, with old and new images. The hook for search indexing, audit trails and outbox delivery.

Write like the retry is guaranteed

Two idioms cover most correctness problems: a condition expression that makes a create idempotent, and a version attribute that makes an update safe against concurrent writers. Both are free — a failed condition costs capacity but never corrupts.

// Optimistic locking: succeed only if the item is still at the version we read.
// A lost race returns ConditionalCheckFailed, which is a normal outcome here.
upd := expression.Set(expression.Name("status"), expression.Value("shipped")).
    Set(expression.Name("version"), expression.Value(cur.Version+1)).
    Set(expression.Name("updated_at"), expression.Value(time.Now().UTC().Format(time.RFC3339)))

cond := expression.Name("version").Equal(expression.Value(cur.Version))

expr, err := expression.NewBuilder().WithUpdate(upd).WithCondition(cond).Build()
if err != nil {
    return err
}

_, err = app.ddb.UpdateItem(ctx, &dynamodb.UpdateItemInput{
    TableName: aws.String("orders"),
    Key: map[string]types.AttributeValue{
        "pk": &types.AttributeValueMemberS{Value: "ORDER#" + id},
        "sk": &types.AttributeValueMemberS{Value: "META"},
    },
    UpdateExpression:          expr.Update(),
    ConditionExpression:       expr.Condition(),
    ExpressionAttributeNames:  expr.Names(),      // handles reserved words for you
    ExpressionAttributeValues: expr.Values(),
    ReturnValues:              types.ReturnValueAllNew,
})

var stale *types.ConditionalCheckFailedException
if errors.As(err, &stale) {
    return ErrConcurrentUpdate                     // re-read and decide, do not blind-retry
}

// Idempotent create: the same request twice leaves one item and no error.
_, err = app.ddb.PutItem(ctx, &dynamodb.PutItemInput{
    TableName:           aws.String("orders"),
    Item:                item,
    ConditionExpression: aws.String("attribute_not_exists(pk)"),
})

# A lost race raises ConditionalCheckFailed, which is a normal outcome here.
try:

        TableName="orders",
        Key={"pk": {"S": f"ORDER#{order_id}"}, "sk": {"S": "META"}},
        UpdateExpression=(
            "SET #s = :new, version = :next, updated_at = :now"
        ),
        ConditionExpression="version = :cur",
        # "status" is a reserved word — every table hits this eventually
        ExpressionAttributeNames={"#s": "status"},
        ExpressionAttributeValues={
            ":new": {"S": "shipped"},
            ":cur": {"N": str(current_version)},
            ":next": {"N": str(current_version + 1)},
            ":now": {"S": datetime.now(timezone.utc).isoformat()},
        },
        ReturnValues="ALL_NEW",
    )
except DDB.exceptions.ConditionalCheckFailedException:
    raise ConcurrentUpdate      # re-read and decide; do not blind-retry

# Idempotent create: the same request twice leaves one item and no error.
try:
    DDB.put_item(
        TableName="orders", Item=item,
        ConditionExpression="attribute_not_exists(pk)",
    )
except DDB.exceptions.ConditionalCheckFailedException:
    pass                        # already created — that is success

Read the page, not the table

A Query stops at 1 MB of scanned data and hands back a cursor. A FilterExpression runs after that limit, so filtering never saves you capacity — it only saves you bandwidth. And a batch write is not a transaction: it can partially succeed, and the items it refused come back for you to send again.

// Paginated query over one partition, newest first, only the fields we need.
kc := expression.Key("pk").Equal(expression.Value("ORDER#"+id)).
    And(expression.Key("sk").BeginsWith("EVENT#"))
expr, _ := expression.NewBuilder().
    WithKeyCondition(kc).
    WithProjection(expression.NamesList(
        expression.Name("sk"), expression.Name("kind"))).
    Build()

p := dynamodb.NewQueryPaginator(app.ddb, &dynamodb.QueryInput{
    TableName:                 aws.String("orders"),
    KeyConditionExpression:    expr.KeyCondition(),
    ProjectionExpression:      expr.Projection(),
    ExpressionAttributeNames:  expr.Names(),
    ExpressionAttributeValues: expr.Values(),
    ScanIndexForward:          aws.Bool(false),      // descending by sort key
    Limit:                     aws.Int32(100),       // items per page, not a total
})
for p.HasMorePages() {
    page, err := p.NextPage(ctx)
    if err != nil {
        return err
    }
    // An empty page with a cursor is normal: 1 MB scanned, nothing matched.
    var events []Event
    if err := attributevalue.UnmarshalListOfMaps(page.Items, &events); err != nil {
        return err
    }
    out = append(out, events...)
}

// BatchWriteItem is NOT atomic. Unprocessed items are the normal case under
// load, and dropping them silently loses data.
req := map[string][]types.WriteRequest{"orders": writes}
for attempt := 0; len(req) > 0 && attempt < 5; attempt++ {
    out, err := app.ddb.BatchWriteItem(ctx, &dynamodb.BatchWriteItemInput{
        RequestItems: req,
    })
    if err != nil {
        return err
    }
    req = out.UnprocessedItems
    if len(req) > 0 {
        time.Sleep(time.Duration(1<<attempt) * 50 * time.Millisecond)   // back off
    }
}
if len(req) > 0 {
    return fmt.Errorf("gave up with %d unwritten items", len(req))
}

pages = DDB.get_paginator("query").paginate(
    TableName="orders",
    KeyConditionExpression="pk = :pk AND begins_with(sk, :prefix)",
    ExpressionAttributeValues={

    ProjectionExpression="sk, kind",
    ScanIndexForward=False,                # descending by sort key
    PaginationConfig={"PageSize": 100},    # items per request, not a total
)
events = []
for page in pages:
    # An empty page with a cursor is normal: 1 MB scanned, nothing matched.
    events.extend(page.get("Items", []))

# BatchWriteItem is NOT atomic. Unprocessed items are the normal case under
# load, and dropping them silently loses data.
pending = {"orders": writes}
for attempt in range(5):
    res = DDB.batch_write_item(RequestItems=pending)
    pending = res.get("UnprocessedItems") or {}
    if not pending:
        break
    time.sleep(0.05 * 2 ** attempt)        # back off before resending
else:
    raise IncompleteWrite(f"{len(pending.get('orders', []))} items unwritten")
You wantUseNotBecause
All rows for one entityQuery on the partition keyScan with a filterScan reads every partition and bills you for all of it, then throws most of it away.
A second access patternA GSI, or a second item type in the same partitionA second table kept in sync by your codeThe index is maintained transactionally with the write. Your synchroniser is not, and will drift.
Two items to change togetherTransactWriteItemsTwo PutItem callsAll-or-nothing across up to 100 items, at 2× the capacity. Cheaper than a reconciliation job.
Strong consistencyA base-table read with ConsistentReadA GSI readGSIs are never strongly consistent, whatever the parameter you pass.
To delete old dataTTL attribute, epoch secondsA scheduled delete jobTTL is free and does not consume write capacity. It deletes within about 48 hours — it is a cleanup, not a deadline.
Sub-millisecond readsDAX, or a read-through cacheProvisioning more RCUDynamoDB is single-digit milliseconds by design. Capacity buys throughput, never latency.

The three metrics to alarm on

ThrottledRequests and the per-operation *Throttle* counters catch capacity problems. SuccessfulRequestLatency catches item-size and index problems. And ConsumedWriteCapacityUnits on each GSI compared with the base table catches the projection you over-specified — usually the difference between a reasonable bill and a strange one.

S3: a flat namespace with strong opinions

There are no directories, no rename, and no partial update: an object is written whole or not at all. Everything S3 gives you — versioning, lifecycle, presigned access, event notification — is built on that immutability.

ConceptWhat is actually true
ConsistencyStrong read-after-write for PUT, DELETE and LIST, in all regions, with no performance penalty. The old “eventually consistent, add a retry” advice is obsolete.
PrefixesNot folders — just key strings. Rate limits scale per prefix: 3,500 writes and 5,500 reads per second, automatically partitioned. Randomised key prefixes are no longer necessary, but a single hot prefix still throttles.
Conditional writesIf-None-Match: * makes a PUT fail if the key exists — a real compare-and-swap, and the basis for a leader lock or a write-once ledger. If-Match on an ETag gives you optimistic concurrency.
ETagsAn MD5 for a single-part upload; for multipart it is a hash of hashes with a -N suffix. Never use it as a content checksum — ask for a CRC32C instead.
EncryptionSSE-S3 is on by default for every new object. SSE-KMS adds an audited, revocable key — enable bucket keys with it, or a busy prefix will generate a KMS call per object and a surprising KMS bill.
Public accessBlock Public Access is on by default for every new bucket, and ACLs are disabled — but the account-level setting is still yours to switch on. If you need public reads, put CloudFront in front with an origin access control instead of opening the bucket.
Express One ZoneSingle-AZ, directory buckets, several times the storage price but cheaper requests, and roughly a tenth of the latency. For shuffle and scratch data, not for anything you need to survive an AZ.

Presign the upload, and never proxy the bytes

The default architecture for user uploads is wrong: bytes flow through your service, consuming memory, request time and NAT charges. A presigned URL moves them directly to S3 with a signature that constrains the method, the key and the expiry — and the conditional PUT below makes the write idempotent as well.

// A presigned PUT: the browser uploads straight to S3, we never see the bytes.
ps := s3.NewPresignClient(app.s3)

req, err := ps.PresignPutObject(ctx, &s3.PutObjectInput{
    Bucket:      aws.String("orders-uploads"),
    Key:         aws.String("tenant/" + tenantID + "/" + uuid.NewString()),
    ContentType: aws.String("application/pdf"),
    // Signed headers are constraints: a client that sends a different
    // content type or length gets a 403, not a surprise object. Note that
    // this pins an EXACT length; a MAXIMUM needs a presigned POST, below.
    ContentLength:        aws.Int64(size),
    ServerSideEncryption: types.ServerSideEncryptionAwsKms,
    SSEKMSKeyId:          aws.String(kmsKeyARN),
}, s3.WithPresignExpires(10*time.Minute))       // bounded by the caller’s own session
if err != nil {
    return err
}
return json.NewEncoder(w).Encode(map[string]string{"url": req.URL})

    Bucket="orders-uploads", Key=f"tenant/{tenant_id}/${{filename}}",

)

try:

except ClientError as e:

Big objects: let the transfer manager do it

// The uploader splits, parallelises and retries individual parts. It also
// aborts the multipart upload on failure — the one thing hand-rolled code
// forgets, and the reason the abort lifecycle rule exists.
up := manager.NewUploader(app.s3, func(u *manager.Uploader) {
    u.PartSize = 16 * 1024 * 1024      // 16 MiB parts; minimum is 5 MiB
    u.Concurrency = 8
})
_, err := up.Upload(ctx, &s3.PutObjectInput{
    Bucket:       aws.String("orders-archive"),
    Key:          aws.String(key),
    Body:         file,                // any io.Reader — no need to know the size
    StorageClass: types.StorageClassIntelligentTiering,
})

// Downloading a slice of a large object beats downloading all of it:
// a range GET is billed on bytes transferred, not on object size.
obj, err := app.s3.GetObject(ctx, &s3.GetObjectInput{
    Bucket: aws.String("orders-archive"),
    Key:    aws.String(key),
    Range:  aws.String("bytes=0-8191"),      // just the header of the file
})

Events are at-least-once and unordered

An S3 notification can arrive twice and out of order, and a rapid overwrite can deliver the second event first. Carry the versionId in the event and fetch that version, or make the handler idempotent on the key. Routing events through EventBridge instead gives you filtering, replay and multiple consumers for the same cost.

Requests are not free

Roughly $0.0004 per thousand GETs sounds like nothing until a job lists a million-key prefix in a loop. On a bucket of small objects, request charges and per-object overheads regularly exceed storage. Aggregate small files before you archive them.

ElastiCache: a cache is a load-bearing dependency

Adding a cache changes your failure modes as much as your latency. The two questions that matter are what happens on a miss storm, and what happens when the cache itself is gone.

// Cache-aside with single flight and fail-open. golang.org/x/sync/singleflight
// collapses concurrent misses of the same key into one origin call.
type Cache struct {
    rdb *redis.Client
    sf  singleflight.Group
}

func (c *Cache) Order(ctx context.Context, id string) (*Order, error) {
    key := "order:" + id

    // A cache read gets a much tighter deadline than the request itself.
    rctx, cancel := context.WithTimeout(ctx, 50*time.Millisecond)
    defer cancel()

    if b, err := c.rdb.Get(rctx, key).Bytes(); err == nil {
        var o Order
        if json.Unmarshal(b, &o) == nil {
            return &o, nil
        }
    } else if !errors.Is(err, redis.Nil) {
        cacheErrors.Inc()          // FAIL OPEN: log it, fall through to origin
    }

    v, err, _ := c.sf.Do(key, func() (any, error) {
        o, err := loadFromDB(ctx, id)
        if err != nil {
            return nil, err
        }
        b, _ := json.Marshal(o)
        // Jitter: 10 minutes +/- 10%, so a batch cached together does not
        // expire together and rebuild the stampede you just prevented.
        ttl := 10*time.Minute + time.Duration(rand.Int63n(int64(2*time.Minute))) - time.Minute
        _ = c.rdb.Set(ctx, key, b, ttl).Err()
        return o, nil
    })
    if err != nil {
        return nil, err
    }
    return v.(*Order), nil
}
# Cache-aside with single flight and fail-open. One asyncio task per key does
# the work; everyone else awaits the same future.
import asyncio, json, random

_inflight: dict[str, asyncio.Future] = {}


async def get_order(order_id: str) -> Order:
    key = f"order:{order_id}"

    # A cache read gets a much tighter deadline than the request itself.
    try:
        raw = await asyncio.wait_for(redis.get(key), timeout=0.05)
        if raw is not None:
            return Order(**json.loads(raw))
    except (asyncio.TimeoutError, RedisError):
        CACHE_ERRORS.inc()      # FAIL OPEN: count it, fall through to origin

    # Single flight: first caller creates the future, the rest await it.
    fut = _inflight.get(key)
    if fut is not None:
        return await asyncio.shield(fut)

    fut = asyncio.get_running_loop().create_future()
    _inflight[key] = fut
    try:
        order = await load_from_db(order_id)
        # Jitter: 10 minutes +/- 10%, so a batch cached together does not
        # expire together and rebuild the stampede you just prevented.
        ttl = int(600 * random.uniform(0.9, 1.1))
        await redis.set(key, json.dumps(order.dict()), ex=ttl)
        fut.set_result(order)
        return order
    except Exception as exc:
        fut.set_exception(exc)
        raise
    finally:
        _inflight.pop(key, None)
DecisionGuidance
EngineValkey is the default now: same protocol, materially cheaper than the Redis OSS option, and Serverless removes node sizing entirely. Memcached only if you genuinely want nothing but a hash table with multiple threads.
Eviction policyThe ElastiCache default is volatile-lru, which only evicts keys that have a TTL — so a cache holding any TTL-less keys can fill and start rejecting writes. For a pure cache, set allkeys-lru.
What to cacheExpensive reads with a tolerable staleness, not everything. A cached row that must be correct will produce a bug you debug at the wrong layer.
InvalidationWrite-through on the same code path as the write, or delete-on-write and let the next reader repopulate. Never a background job that hopes to keep up.
FailoverMulti-AZ with automatic failover takes tens of seconds and returns errors during the switch. Client-side retries plus fail-open turn that into a latency bump.
DAXOnly for DynamoDB, and it caches by request shape: an item cache plus a query cache, write-through on the item side. Microseconds instead of milliseconds, at the price of another cluster to run.
