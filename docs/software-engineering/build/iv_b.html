Part two

The coding round

One or two rounds, forty-five minutes each, a problem with a known shape and an interviewer watching you find it. The subject is finite: a few dozen structures, a few dozen algorithms, and about fifteen patterns that connect a problem statement to one of them. This part is the full list, plus the two things that decide the score once the code works — complexity you can defend and correctness you demonstrated yourself.

The fifteen patterns that connect a problem to a structure

Interview problems are disguised. The disguise is the story; the cue is in the constraints. Learning to read the cue is most of what “being good at these” means.

Two patterns are worth writing out because candidates who know them by name still get the boundaries wrong under pressure. The first is binary search on the answer: when the question asks for the smallest capacity, the minimum speed or the largest minimum, the search space is not the array — it is the range of possible answers, and the array only appears inside a feasibility check that is monotone.

# feasible.py — binary search over the ANSWER, not over the input.
# Cue: "minimum capacity", "smallest k such that ...", "maximum minimum".
def min_capacity(weights: list[int], days: int) -> int:
    def fits(cap: int) -> bool:
        # Greedy is safe here only because fits() is monotone in cap:
        # if a capacity works, every larger capacity works too.
        used, load = 1, 0
        for w in weights:
            if load + w > cap:
                used, load = used + 1, 0
            load += w
        return used <= days

    lo, hi = max(weights), sum(weights)   # lo must itself be feasible-or-not
    while lo < hi:                        # invariant: answer is in [lo, hi]
        mid = lo + (hi - lo) // 2         # never (lo+hi)//2 in a fixed-width int
        if fits(mid):
            hi = mid                      # mid may be the answer — keep it
        else:
            lo = mid + 1                  # mid is definitely not — discard it
    return lo                             # lo == hi, and it is feasible

The second is the monotonic stack, which answers “for each element, where is the next one bigger than it?” in one pass. The trick to state out loud is that each index is pushed once and popped once, so the nested-looking loop is linear, not quadratic — that sentence is the whole complexity argument and interviewers wait for it.

# next_greater.py — one pass, each index pushed once and popped once: O(n).
def next_greater(nums: list[int]) -> list[int]:
    out = [-1] * len(nums)
    stack: list[int] = []              # indices, values strictly decreasing
    for i, v in enumerate(nums):
        # Everything smaller than v has just found its answer.
        while stack and nums[stack[-1]] < v:
            out[stack.pop()] = v
        stack.append(i)
    return out                         # whatever is left never found one: -1
Two pointersOpposite ends on sorted data, or same-direction to keep a window. Ask what makes it safe to move each pointer.
Sliding windowFixed size is arithmetic; variable size needs a shrink condition. Say which invariant the window maintains.
Fast and slow pointersCycle detection, middle of a list, k-th from the end. One list, one pass, no extra memory.
Prefix sumsRange queries in O(1) after O(n) setup. With a hash map of seen prefixes it becomes “subarrays summing to k”.
Binary searchOn a sorted array, on a rotated one, or on the answer. Get the invariant right and the off-by-one disappears.
Heap / top kA min-heap of size k for the k largest. O(n log k) beats sorting when k is small; quickselect beats both when you may reorder.
Monotonic stackNext greater, largest rectangle, stock span, daily temperatures. Amortised linear.
Interval sweepSort by start, then merge or count. Meeting rooms, calendars, skyline — all the same three lines.
BFS / DFSGrids and boards are graphs with implied edges. BFS for fewest steps, DFS for reachability and structure.
Topological sortAnything with prerequisites. Kahn’s algorithm also detects the cycle for free, which is usually part two of the question.
Disjoint set unionGrouping under merges. With both optimisations, near-constant per operation — say “inverse Ackermann” once and move on.
BacktrackingChoose, recurse, un-choose. The score is in the pruning, not the enumeration.
Dynamic programmingState, transition, base case, order of evaluation. Say all four before writing any of them.
GreedyOnly correct with an argument. Exchange argument or a counterexample — produce one or the other.
BitmaskSets of up to about twenty elements as integers. Subsets, assignment problems, travelling salesman on small n.

Complexity, in the way it is actually asked

Not “what is big-O”. The real questions are: which class does this fall into, does the bound hold in the worst case as well as on average, what does it cost in space, and would that fit in a second.

Correctness: invariants, edge cases, and testing your own code

The difference between a hire and a no-hire is often not the algorithm — it is who found the bug. Finding your own scores; having it found for you costs.

An invariant is a sentence that is true before and after every iteration. Say it out loud and most boundary bugs become impossible to write: “everything left of lo is too small, everything from hi on is a candidate” determines whether the loop is < or <= and whether you assign mid or mid + 1. Guessing at those two decisions is the single most common source of a failed binary search under time pressure.

Empty and oneEmpty input, one element, two elements. Roughly a third of interview bugs live here.
All the sameEvery element equal — kills naive partitioning and many two-pointer conditions.
Already sorted, reverse sortedThe worst case for a fixed pivot, and the best case that hides a bug.
DuplicatesAsk explicitly. Duplicates change set logic, binary-search bounds and dedupe requirements.
Negatives and zeroProducts, sums, prefix sums and greedy arguments all change sign with them.
Overflow(lo + hi) / 2 in a fixed-width integer, or a sum that exceeds 32 bits. Say it even in Python, where it cannot happen.
Not foundWhat does the function return when the answer does not exist? Decide before you write the loop.
Off-by-oneInclusive or exclusive bounds. Pick one convention for the whole function and say which.
Cycles and self-loopsIn graph problems, in linked lists, and in anything user-supplied.
Unicode and case“Reverse a string” is a different problem once a code point is not a character.
Mutation of the inputAre you allowed to sort in place? Ask — some rounds are entirely about this.
Recursion depthA linked list of a million nodes overflows a recursive solution. Mention it and offer the iterative form.

Then run it. Not “it looks right” — take a small awkward input, put a finger on the first line, and say what every variable holds after each step. Two minutes of this catches more than ten minutes of re-reading, and it is visible work: the interviewer is writing down that you tested unprompted.

# two_sum.py — a dry run is a table, spoken. nums = [2, 1, 2], target = 4
#
#   i   v   need   seen                 action
#   0   2     2    {}                   miss -> seen[2] = 0
#   1   1     3    {2: 0}               miss -> seen[1] = 1
#   2   2     2    {2: 0, 1: 1}         hit  -> return (0, 2)
#
# Two things this catches that re-reading does not: that `seen` is written
# AFTER the lookup (otherwise an element pairs with itself), and that the
# duplicate 2 is fine because the first index is the one still stored.
def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    seen: dict[int, int] = {}
    for i, v in enumerate(nums):
        if (need := target - v) in seen:
            return seen[need], i
        seen[v] = i
    return None
  • What is the complexity?both dimensions, and whether the bound you quote is worst case or average. Answer before you are asked and it counts for more.
  • Can you do it in less space?whether you know the standard trade: rolling arrays for dynamic programming, in-place partitioning, pointers instead of a copy.
  • What breaks if the input does not fit in memory?whether you can move from an algorithm to a system: external sort, streaming, sharding by key, a sketch instead of an exact count.
  • How would you test this?named categories rather than examples — empty, single, duplicates, sorted, adversarial — plus a property that must hold for any input.
