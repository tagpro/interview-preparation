Part five

Graphs, which are most problems in disguise

A graph is nodes and edges, and the reason it matters is that an enormous number of real problems are one once you look: build dependencies, service call chains, permission inheritance, routing, scheduling, deadlock detection, social connections, state machines. The algorithms are few and they compose. The hard part — the part worth practising — is recognising the graph.

Modelling: what is a node, what is an edge

Before any algorithm, two decisions. What the graph is made of — and that is a modelling question with more than one right answer — and how to store it, which is nearly always an adjacency list and occasionally, for very dense graphs, a matrix.

PropertyAdjacency listAdjacency matrix
SpaceO(V + E)O(V²) — a million nodes is a terabyte
Iterate a node’s neighboursO(degree)O(V), mostly reading zeros
Is there an edge u→v?O(degree), or O(1) with a set per nodeO(1)
Add an edgeO(1)O(1)
Best forNearly everything. Real graphs are sparse: E is a small multiple of V, not V²Dense graphs, tiny graphs, and algorithms defined on matrices (Floyd–Warshall, spectral methods)

The modelling move that solves the problem

Many puzzles that look nothing like graphs become easy once you pick the right node. “The fewest word changes from COLD to WARM” is a shortest path where nodes are words and edges join words differing in one letter. “Can these courses be taken?” is cycle detection. “The cheapest exchange from GBP to JPY” is a shortest path over a graph whose edge weights are logarithms of rates — because multiplying rates becomes adding logs, and now Dijkstra applies. When a problem resists, the useful question is not “which algorithm” but “what are the nodes?”

// algorithm below then indexes arrays instead of hashing, which is

The four searches, and how little separates them

Breadth-first, depth-first, Dijkstra and A* are the same loop. Take a node from a collection of frontier nodes, mark it seen, add its unseen neighbours. The only difference is which node the collection hands back — the oldest, the newest, the cheapest, or the cheapest-plus-a-guess — and that single choice changes everything about the search.

SearchFrontierCostWhat it guarantees
Breadth-firstQueue — oldest firstO(V + E)Fewest edges. Correct only when every edge costs the same, which is the case people forget.
Depth-firstStack — newest firstO(V + E)Nothing about distance. It gives you reachability, cycle detection, topological order and articulation points.
DijkstraMin-heap by distanceO((V + E) log V)Cheapest path, for non-negative weights. A negative edge breaks it outright — the “already finalised” assumption fails.
A*Min-heap by distance + heuristicO((V + E) log V)Cheapest path, if the heuristic never overestimates. With a zero heuristic it is Dijkstra.
Bellman–FordNo frontier — V−1 passes over all edgesO(V·E)Handles negative weights, and detects a negative cycle. The currency-arbitrage algorithm.
Floyd–WarshallNone — a V×V matrixO(V³)Every pair at once. Only sane below a few hundred nodes, where its tiny constant beats V runs of Dijkstra.
 
// search.go — BFS and Dijkstra, written to show that they are one
// algorithm with two frontiers.

// BFS: shortest path in EDGES. The queue is what makes it correct --
// nodes come out in non-decreasing distance order.
func BFS(g *Graph, src int32) []int32 {
    dist := make([]int32, len(g.adj))
    for i := range dist {
        dist[i] = -1
    }
    dist[src] = 0
    q := []int32{src}
    for len(q) > 0 {
        u := q[0]
        q = q[1:]
        for _, v := range g.adj[u] {
            if dist[v] == -1 {                   // mark on ENQUEUE, not on
                dist[v] = dist[u] + 1            // dequeue, or a node can be
                q = append(q, v)                 // queued twice
            }
        }
    }
    return dist
}

// Dijkstra: same shape, heap instead of queue. The "lazy deletion"
// variant pushes duplicates and skips stale ones on the way out, which
// avoids needing decrease-key and is what nearly everyone ships.
func Dijkstra(g [][]Edge, src int32) []int64 {
    const inf = math.MaxInt64
    dist := make([]int64, len(g))
    for i := range dist {
        dist[i] = inf
    }
    dist[src] = 0

    pq := &NodeHeap{{Node: src, Dist: 0}}
    for pq.Len() > 0 {
        cur := heap.Pop(pq).(NodeDist)
        if cur.Dist > dist[cur.Node] {
            continue                             // stale entry: already improved
        }
        for _, e := range g[cur.Node] {
            if nd := cur.Dist + int64(e.Weight); nd < dist[e.To] {
                dist[e.To] = nd
                heap.Push(pq, NodeDist{Node: e.To, Dist: nd})
            }
        }
    }
    return dist
}

// When every weight is 0 or 1, a deque beats the heap: push 0-weight
// edges on the front and 1-weight on the back. O(V+E), no log factor.
// This "0-1 BFS" is worth knowing; it comes up constantly in grids.
# search.py — the same two, and the third that people reach for a graph
# library to avoid writing.
import heapq
from collections import deque

def bfs(graph, src):
    """Fewest EDGES from src. Only correct when all edges cost the same."""
    dist = {src: 0}
    q = deque([src])
    while q:
        u = q.popleft()
        for v in graph.get(u, ()):
            if v not in dist:                    # mark on enqueue
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

def dijkstra(graph, src):
    """Cheapest path. Non-negative weights only."""
    dist = {src: 0}
    pq = [(0, src)]                              # (distance, node) -- tuples compare
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")):
            continue                             # stale duplicate: skip it
        for v, w in graph.get(u, ()):
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

# A* is dijkstra with one line changed: the heap is keyed by
# cost-so-far PLUS an estimate of the cost remaining. The estimate must
# never overestimate, or the answer stops being optimal. On a grid with
# unit steps, Manhattan distance is the standard admissible heuristic.
#     heapq.heappush(pq, (nd + h(v), nd, v))

# DFS: write it with an explicit stack. The recursive version is prettier
# and dies at a depth of 1000.
def dfs(graph, src):
    seen, stack = {src}, [src]
    while stack:
        u = stack.pop()
        for v in graph.get(u, ()):
            if v not in seen:
                seen.add(v)
                stack.append(v)
    return seen
// Search.java — BFS on primitive arrays, Dijkstra on a PriorityQueue.

int[] bfs(Graph g, int src) {
    int[] dist = new int[g.size()];
    Arrays.fill(dist, -1);
    dist[src] = 0;
    Deque<Integer> q = new ArrayDeque<>();
    q.add(src);
    while (!q.isEmpty()) {
        int u = q.poll();
        for (Edge e : g.neighbours(u)) {
            if (dist[e.to()] == -1) {            // mark on enqueue
                dist[e.to()] = dist[u] + 1;
                q.add(e.to());
            }
        }
    }
    return dist;
}

long[] dijkstra(Graph g, int src) {
    long[] dist = new long[g.size()];
    Arrays.fill(dist, Long.MAX_VALUE);
    dist[src] = 0;

    // long[]{distance, node} avoids a record allocation per push; the
    // comparator reads element 0.
    PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[0]));
    pq.add(new long[]{0, src});

    while (!pq.isEmpty()) {
        long[] cur = pq.poll();
        int u = (int) cur[1];
        if (cur[0] > dist[u]) continue;          // stale entry
        for (Edge e : g.neighbours(u)) {
            long nd = cur[0] + e.weight();
            if (nd < dist[e.to()]) {
                dist[e.to()] = nd;
                pq.add(new long[]{nd, e.to()});  // lazy decrease-key
            }
        }
    }
    return dist;
}

// The bug that makes Dijkstra silently wrong: a negative edge weight.
// The algorithm assumes a popped node is final, and a negative edge can
// improve it afterwards. There is no error -- just a wrong answer. If
// weights can be negative you need Bellman-Ford, at O(V*E).

Topological order and cycles: the build-system algorithm

Given tasks with dependencies, produce an order in which each task comes after everything it needs. This is what a build system, a migration runner, a package manager and a scheduler all do, and the same algorithm that produces the order also proves that no order exists — because there is a cycle.

// topo.go — Kahn's algorithm, with the cycle report as a first-class
// result rather than a boolean.

func TopoSort(n int, deps [][]int32) ([]int32, error) {
    indeg := make([]int32, n)
    for _, vs := range deps {                    // deps[u] = things that need u
        for _, v := range vs {
            indeg[v]++
        }
    }

    ready := make([]int32, 0, n)
    for i, d := range indeg {
        if d == 0 {
            ready = append(ready, int32(i))
        }
    }

    order := make([]int32, 0, n)
    for len(ready) > 0 {
        // Everything in `ready` right now is independent: a build system
        // runs this whole slice in parallel and then re-fills it.
        u := ready[len(ready)-1]
        ready = ready[:len(ready)-1]
        order = append(order, u)
        for _, v := range deps[u] {
            if indeg[v]--; indeg[v] == 0 {
                ready = append(ready, v)
            }
        }
    }

    if len(order) != n {
        stuck := make([]int32, 0, n-len(order))
        for i, d := range indeg {
            if d > 0 {
                stuck = append(stuck, int32(i))  // in, or downstream of, a cycle
            }
        }
        return nil, fmt.Errorf("dependency cycle involving %v", stuck)
    }
    return order, nil
}

    batch = ts.get_ready()                       # a tuple of independent tasks
    for task in run_in_parallel(batch):
        ts.done(task)

# Cycle detection by hand, when you want the cycle itself. Three
# colours: 0 unvisited, 1 on the current path, 2 finished. An edge to a
# colour-1 node is a back edge, and the stack above it is the cycle.
def find_cycle(graph):
    colour, stack = {}, []

    def visit(u):
        colour[u] = 1
        stack.append(u)
        for v in graph.get(u, ()):
            if colour.get(v) == 1:               # back edge
                return stack[stack.index(v):] + [v]
            if colour.get(v, 0) == 0:
                if (found := visit(v)):
                    return found
        colour[u] = 2
        stack.pop()
        return None

    return next((c for u in graph if colour.get(u, 0) == 0 and (c := visit(u))), None)
// Topo.java — Kahn's algorithm with the batch structure exposed, which
// is what makes it a scheduler rather than just a sort.

static List<List<Integer>> waves(int n, List<List<Integer>> dependents) {
    int[] indeg = new int[n];
    for (List<Integer> vs : dependents)
        for (int v : vs) indeg[v]++;

    Deque<Integer> ready = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) ready.add(i);

    List<List<Integer>> out = new ArrayList<>();
    int emitted = 0;
    while (!ready.isEmpty()) {
        int width = ready.size();                // this wave is independent
        List<Integer> wave = new ArrayList<>(width);
        for (int i = 0; i < width; i++) {
            int u = ready.poll();
            wave.add(u);
            emitted++;
            for (int v : dependents.get(u))
                if (--indeg[v] == 0) ready.add(v);
        }
        out.add(wave);                           // hand each wave to an executor
    }

    if (emitted != n) {
        List<Integer> stuck = IntStream.range(0, n).filter(i -> indeg[i] > 0).boxed().toList();
        throw new IllegalStateException("dependency cycle involving " + stuck);
    }
    return out;
}

Minimum spanning trees, and where union-find comes back

Connect every node using the least total edge weight. Two algorithms solve it, both greedy, and both correct for the same reason — the cut property, which says that the lightest edge crossing any division of the nodes into two groups must belong to some minimum spanning tree.

KruskalSort all edges, keep any that joins two different components. O(E log E), and the component test is exactly union-find. Best when the graph is sparse or the edges already arrive sorted.
PrimGrow one tree, always taking the cheapest edge leaving it. O(E log V) with a heap — structurally identical to Dijkstra, keyed by edge weight instead of path length. Best when the graph is dense.
Where it is usedNetwork and circuit layout, clustering (cut the k−1 heaviest edges of the MST and you have k clusters), image segmentation, and approximating the travelling salesman within a factor of two.
What it is notNot shortest paths. The MST minimises total weight over the whole tree; the path between two nodes within it can be far worse than their shortest path.
// mst.go — Kruskal is four lines once you have the DSU from part three.
// That is the payoff for having written it.

type WEdge struct {
    U, V   int32
    Weight int64
}

func Kruskal(n int, edges []WEdge) ([]WEdge, int64) {
    slices.SortFunc(edges, func(a, b WEdge) int {
        return cmp.Compare(a.Weight, b.Weight)   // the greedy order
    })

    dsu := NewDSU(n)
    tree := make([]WEdge, 0, n-1)
    var total int64
    for _, e := range edges {
        if dsu.Union(int(e.U), int(e.V)) {       // false == would close a cycle
            tree = append(tree, e)
            total += e.Weight
            if len(tree) == n-1 {
                break                            // a spanning tree has exactly n-1
            }
        }
    }
    return tree, total
}

// If len(tree) < n-1 when the loop ends, the graph was disconnected and
// what you have is a minimum spanning FOREST -- one tree per component.
// That is usually the right answer rather than an error.

// Single-linkage clustering falls out for free: stop early. Running
// Kruskal until exactly k components remain gives the clustering that
// maximises the smallest gap between clusters.
func Cluster(n int, edges []WEdge, k int) *DSU {
    slices.SortFunc(edges, func(a, b WEdge) int { return cmp.Compare(a.Weight, b.Weight) })
    dsu := NewDSU(n)
    for _, e := range edges {
        if dsu.groups == k {
            break
        }
        dsu.Union(int(e.U), int(e.V))
    }
    return dsu
}
# mst.py — Prim, which is Dijkstra with one word changed.
import heapq

def prim(graph: dict[int, list[tuple[int, int]]], start: int = 0):
    """Minimum spanning tree by growing one component.

    Compare with dijkstra() above: the ONLY difference is that the heap
    key is the edge weight `w` rather than the accumulated `d + w`.
    Dijkstra minimises distance from the source; Prim minimises the cost
    of attaching one more node to the tree.
    """
    seen = {start}
    pq = [(w, start, v) for v, w in graph[start]]
    heapq.heapify(pq)
    tree, total = [], 0

    while pq and len(seen) < len(graph):
        w, u, v = heapq.heappop(pq)
        if v in seen:
            continue                             # stale: v joined another way
        seen.add(v)
        tree.append((u, v, w))
        total += w
        for nxt, nw in graph[v]:
            if nxt not in seen:
                heapq.heappush(pq, (nw, v, nxt))

    return tree, total

# Kruskal in Python, using the DSU from part three:
def kruskal(n: int, edges: list[tuple[int, int, int]]):
    dsu = DSU(n)
    tree, total = [], 0
    for u, v, w in sorted(edges, key=lambda e: e[2]):
        if dsu.union(u, v):                      # False means it closes a cycle
            tree.append((u, v, w))
            total += w
    return tree, total
// Mst.java — Kruskal with the Dsu from part three. Note how little code
// the algorithm itself is: the work is all in the two data structures.

record WEdge(int u, int v, long weight) {}

static List<WEdge> kruskal(int n, List<WEdge> edges) {
    List<WEdge> sorted = new ArrayList<>(edges);
    sorted.sort(Comparator.comparingLong(WEdge::weight));

    Dsu dsu = new Dsu(n);
    List<WEdge> tree = new ArrayList<>(n - 1);
    for (WEdge e : sorted) {
        if (dsu.union(e.u(), e.v())) {           // false: both ends already joined
            tree.add(e);
            if (tree.size() == n - 1) break;
        }
    }
    return tree;                                 // size < n-1 => disconnected graph
}

// Why greedy is provably correct here, which is worth knowing because
// greedy is usually wrong: the CUT PROPERTY. Split the nodes into any
// two non-empty groups. The lightest edge crossing that split is in
// SOME minimum spanning tree -- if a tree omits it, adding it creates a
// cycle, and removing any other crossing edge from that cycle gives a
// tree no heavier. Every edge Kruskal accepts is the lightest crossing
// the cut between its two components, so every acceptance is safe.
