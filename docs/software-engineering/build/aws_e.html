Part five

Queues, buses and streams

Three services that all “move messages” and are not interchangeable. A queue buffers work for one consumer. A bus routes one event to many. A stream keeps an ordered log you can rewind. Picking the wrong one is recoverable; pretending one is another is not.

AWS · 00

SQS: visibility timeout is the whole contract

SQS does not deliver messages — it lends them. A receive hides the message for a while; a delete ends the loan. Every SQS bug is a disagreement between how long you borrowed it for and how long you actually needed it.

// A consumer loop that does the three things people leave out: long polling,
// a visibility heartbeat, and a batch delete of exactly what succeeded.
for {
    out, err := app.sqs.ReceiveMessage(ctx, &sqs.ReceiveMessageInput{
        QueueUrl:              aws.String(queueURL),
        MaxNumberOfMessages:   10,
        WaitTimeSeconds:       20,          // long poll: cheaper AND lower latency
        VisibilityTimeout:     60,
        MessageAttributeNames: []string{"All"},
        // ApproximateReceiveCount tells you this is a retry — log it, and treat
        // a high count as a signal rather than a surprise.
        MessageSystemAttributeNames: []types.MessageSystemAttributeName{"ApproximateReceiveCount"},
    })
    if err != nil {
        if errors.Is(err, context.Canceled) {
            return nil                       // shutting down
        }
        log.Error("receive", "err", err)
        time.Sleep(time.Second)
        continue
    }

    var done []types.DeleteMessageBatchRequestEntry
    for _, m := range out.Messages {
        hb, stop := context.WithCancel(ctx)
        go heartbeat(hb, app.sqs, queueURL, *m.ReceiptHandle, 60)   // extend while busy

        err := handle(ctx, m)
        stop()
        if err != nil {
            log.Error("handler", "id", aws.ToString(m.MessageId), "err", err)
            continue                          // leave it: it becomes visible again
        }
        done = append(done, types.DeleteMessageBatchRequestEntry{
            Id: m.MessageId, ReceiptHandle: m.ReceiptHandle,
        })
    }

    if len(done) > 0 {
        // A batch delete can partially fail. Anything in .Failed stays in the
        // queue and WILL be delivered again — which is why handlers are idempotent.
        res, err := app.sqs.DeleteMessageBatch(ctx, &sqs.DeleteMessageBatchInput{
            QueueUrl: aws.String(queueURL), Entries: done,
        })
        if err == nil && len(res.Failed) > 0 {
            log.Warn("delete partially failed", "count", len(res.Failed))
        }
    }
}

# a visibility heartbeat, and a batch delete of exactly what succeeded.
import threading

QUEUE = "https://sqs.eu-west-1.amazonaws.com/1234/orders"


def heartbeat(receipt: str, every: float, timeout: int, stop: threading.Event):
    # Extend the loan while we are still working on it.
    while not stop.wait(every):
        SQS.change_message_visibility(
            QueueUrl=QUEUE, ReceiptHandle=receipt, VisibilityTimeout=timeout
        )


while running:
    res = SQS.receive_message(
        QueueUrl=QUEUE,
        MaxNumberOfMessages=10,
        WaitTimeSeconds=20,              # long poll: cheaper AND lower latency
        VisibilityTimeout=60,
        MessageAttributeNames=["All"],
        # ApproximateReceiveCount tells you this is a retry — log it, and treat
        # a high count as a signal rather than a surprise.
        MessageSystemAttributeNames=["ApproximateReceiveCount"],
    )

    done = []
    for msg in res.get("Messages", []):
        stop = threading.Event()
        t = threading.Thread(
            target=heartbeat, args=(msg["ReceiptHandle"], 20.0, 60, stop), daemon=True
        )
        t.start()
        try:
            handle(msg)
            done.append({"Id": msg["MessageId"], "ReceiptHandle": msg["ReceiptHandle"]})
        except Exception:
            log.exception("handler failed", extra={"id": msg["MessageId"]})
            # leave it: visibility expires and it comes back
        finally:
            stop.set()

    if done:
        # A batch delete can partially fail. Anything in Failed stays in the
        # queue and WILL be delivered again — hence idempotent handlers.
        out = SQS.delete_message_batch(QueueUrl=QUEUE, Entries=done)
        if out.get("Failed"):
            log.warning("delete partially failed", extra={"n": len(out["Failed"])})

The DLQ is not a graveyard

Alarm on ApproximateNumberOfMessagesVisible on the dead letter queue — any non-zero value is a bug report with the payload attached. When you have fixed the cause, the redrive API moves messages back to the source queue without a custom script.

FIFO ordering costs you parallelism

Messages in one group are delivered strictly in order, which means strictly one at a time. If your throughput target divided by your per-message time exceeds one, you need many groups — usually one per customer or entity, never one per queue.

SNS and EventBridge: publish once, route many

Both take one message and give it to several places. SNS is a fast, cheap fan-out pipe with attribute filtering. EventBridge is a router that reads the message body, keeps a schema registry, and can replay last Tuesday.

// and the fields inside Detail are what every consumer’s rule will match on,
// so they are a public interface — version them.

The rule that receives it — and the filter that saves you money

An EventBridge pattern matches the structure of the event, not a string. Anything you omit matches everything; anything you include must match exactly, unless you use one of the comparison operators. Filtering at the bus is free; filtering inside a Lambda costs an invocation.

// A rule pattern is JSON that mirrors the event. Values are always ARRAYS —
// "any of these" — which is the syntax people get wrong first.
pattern := `{
  "source": ["com.example.orders"],
  "detail-type": ["OrderPlaced"],
  "detail": {
    "currency": ["GBP", "EUR"],
    "totalCents": [{"numeric": [">=", 50000]}],
    "tenantId": [{"anything-but": ["internal-test"]}]
  }
}`

_, err := app.eb.PutRule(ctx, &eventbridge.PutRuleInput{
    Name:         aws.String("large-orders-to-review"),
    EventBusName: aws.String("orders"),
    EventPattern: aws.String(pattern),
    State:        types.RuleStateEnabled,
})

// Every target needs its own retry policy and dead letter queue: a target
// that fails without one loses the event after 24 hours of attempts.
_, err = app.eb.PutTargets(ctx, &eventbridge.PutTargetsInput{
    Rule:         aws.String("large-orders-to-review"),
    EventBusName: aws.String("orders"),
    Targets: []types.Target{{
        Id:  aws.String("review-queue"),
        Arn: aws.String(reviewQueueARN),
        RetryPolicy: &types.RetryPolicy{
            MaximumRetryAttempts:     aws.Int32(4),
            MaximumEventAgeInSeconds: aws.Int32(3600),
        },
        DeadLetterConfig: &types.DeadLetterConfig{Arn: aws.String(dlqARN)},
    }},
})

Kinesis Data Streams: an ordered log with a cursor

A stream is not a queue. Records are not deleted when read — each consumer keeps its own position, records stay for as long as retention says, and ordering holds within a shard. That buys replay and multiple readers, and costs you the ability to skip a bad record for free.

// PutRecords is a batch of up to 500 records — and it returns 200 with
// individual failures inside. Resending the WHOLE batch duplicates the
// records that succeeded, so resend only the failed indexes.
func putAll(ctx context.Context, k *kinesis.Client, stream string,
    recs []types.PutRecordsRequestEntry) error {

    for attempt := 0; attempt < 5 && len(recs) > 0; attempt++ {
        out, err := k.PutRecords(ctx, &kinesis.PutRecordsInput{
            StreamName: aws.String(stream),
            Records:    recs,
        })
        if err != nil {
            return err
        }
        if aws.ToInt32(out.FailedRecordCount) == 0 {
            return nil
        }

        var retry []types.PutRecordsRequestEntry
        for i, r := range out.Records {
            if r.ErrorCode != nil {
                // ProvisionedThroughputExceededException — this shard is hot
                retry = append(retry, recs[i])
            }
        }
        recs = retry
        time.Sleep(time.Duration(1<<attempt) * 100 * time.Millisecond)
    }
    return fmt.Errorf("%d records never accepted", len(recs))
}

// each order’s events in sequence and spreads load; "orders" would put the
// entire stream on one shard.

# put_records is a batch of up to 500 records — and it returns HTTP 200 with
# individual failures inside. Resending the WHOLE batch duplicates the records
# that succeeded, so resend only the failed indexes.
KIN = boto3.client("kinesis", config=CFG)


def put_all(stream: str, records: list[dict]) -> None:
    pending = records
    for attempt in range(5):
        res = KIN.put_records(StreamName=stream, Records=pending)
        if not res["FailedRecordCount"]:
            return
        # ProvisionedThroughputExceededException — that shard is hot
        pending = [
            rec for rec, out in zip(pending, res["Records"]) if "ErrorCode" in out
        ]
        time.sleep(0.1 * 2 ** attempt)
    raise PublishFailed(f"{len(pending)} records never accepted")

Configure the poison-pill escape before you go live

On a Kinesis or DynamoDB Streams event source mapping, set MaximumRetryAttempts, turn on BisectBatchOnFunctionError so a failing batch is halved until the bad record is isolated, and give it an OnFailure destination so the record lands somewhere you can read it. Without those three, one malformed record halts a shard until retention drops it — and takes every well-formed record behind it along the way.
