Part eleven

A whole service, file by file

Everything before this was a mechanism, a snippet, or one slice of Spring. This is the repository — one small service, built in the order you would actually build it, with every file that has to exist before anyone will let you deploy it. The domain is a link shortener, chosen because it is small enough to hold in your head and still needs every production concern there is: validation, a database and a migration, idempotency under a race, authentication, rate limiting, structured logs, two different health checks, tests that run in CI, and an image that starts as a non-root user. It is the same service the Python page builds, in the same order, so you can read the two side by side and see what the language actually changes.

A version range is not a dependency, it is a promise you cannot keep

Nothing in that pom except the parent and ArchUnit states a version, and neither states a range. Maven resolves ranges at build time, which means the artifact your CI produces on Tuesday is not the one it produced on Monday, and the difference is invisible in the diff. Pin exactly, upgrade in a commit that says so, and let a bot open that commit for you. The parent doing the pinning for forty transitive libraries is the reason Spring Boot is worth using at all — it is a curated dependency set with a starter API on top, not just a framework.

Configuration, typed and validated at boot

A service reads its environment exactly once, on the way up, into objects whose types are checked. The failure mode you are designing against is the one where a mistyped variable is discovered on the tenth request in production instead of in the first second of the deploy — and Spring will do that for you, but only if you stop reading settings with @Value.

Virtual threads did not raise your concurrency limit; the pool did not move

Turning on spring.threads.virtual.enabled means Tomcat stops handing requests to a fixed pool of 200 platform threads, so ten thousand concurrent requests no longer queue at the connector. What it emphatically does not do is let ten thousand of them talk to Postgres: maximum-pool-size: 10 is still ten, and requests 11 and up block for a connection with a two-second timeout. That is the correct design — a database has a real concurrency ceiling and a pool is how you respect it — but it moves the bottleneck rather than removing it, and it moves it somewhere you have to size on purpose. Load-test the pool, not the thread model.

open-in-view is on by default and it should not be

Boot leaves the Hibernate session open for the whole request so that a lazy association touched inside a Jackson serializer still resolves. That is convenient exactly once and expensive forever: it holds a database connection for the duration of view rendering, it turns an N+1 into something that works rather than something that throws, and it means the transaction boundary you carefully drew in the service is not where the database work actually stops. Set it to false on day one, before any code depends on it. You will get a LazyInitializationException the first time it matters, and that exception is the design telling you to fetch what you need inside the transaction.

The core, which knows nothing about Spring

This package imports the JDK and nothing else. No annotations, no framework, no database — which is why its tests run in a millisecond and why the rules survive the day someone rewrites the web layer. The technique it leans on is the one the records topic introduced: make illegal states unrepresentable by validating in the constructor, so a ShortCode that exists is a ShortCode that is well formed.

// src/main/java/info/jaspreet/shortlink/domain/ShortCode.java
package info.jaspreet.shortlink.domain;

import java.util.Locale;
import java.util.Objects;
import java.util.regex.Pattern;

/**
 * The code in the short URL. A record over a single String, which sounds
 * like ceremony until you count the methods that take two Strings and can
 * be called with them the wrong way round.
 */
public record ShortCode(String value) {

  private static final Pattern SHAPE = Pattern.compile("[a-z0-9]{4,32}");

  // A compact constructor may reassign the parameter before it is written
  // to the field, so normalising and validating happen in one place and
  // there is no way to construct an instance that skips them.
  public ShortCode {
    Objects.requireNonNull(value, "value");
    value = value.trim().toLowerCase(Locale.ROOT);
    if (!SHAPE.matcher(value).matches()) {
      throw new IllegalArgumentException("not a short code: " + value);
    }
  }

  @Override
  public String toString() {
    return value;
  }
}
// src/main/java/info/jaspreet/shortlink/domain/TargetUrl.java
package info.jaspreet.shortlink.domain;

import java.net.URI;
import java.net.URISyntaxException;
import java.util.Locale;
import java.util.Set;

/** The URL a code points at. Parsing it is a security control, not a format check. */
public record TargetUrl(URI value) {

  private static final Set<String> SCHEMES = Set.of("http", "https");
  private static final int MAX_LENGTH = 2048;

  public static TargetUrl parse(String raw) {
    if (raw == null || raw.isBlank()) {
      throw new IllegalArgumentException("url is required");
    }
    if (raw.length() > MAX_LENGTH) {
      throw new IllegalArgumentException("url longer than " + MAX_LENGTH);
    }
    URI uri;
    try {
      uri = new URI(raw.trim()).normalize();
    } catch (URISyntaxException e) {
      throw new IllegalArgumentException("url is not a valid URI", e);
    }
    // The one that matters: without this, "javascript:alert(1)" is a link
    // you will happily hand a browser a 302 to, from your own domain.
    String scheme = uri.getScheme() == null ? "" : uri.getScheme().toLowerCase(Locale.ROOT);
    if (!uri.isAbsolute() || !SCHEMES.contains(scheme)) {
      throw new IllegalArgumentException("only http and https can be shortened");
    }
    if (uri.getHost() == null || uri.getHost().isBlank()) {
      throw new IllegalArgumentException("url has no host");
    }
    // http://user:pass@host is a credential in a database column.
    if (uri.getUserInfo() != null) {
      throw new IllegalArgumentException("credentials in a url are not stored");
    }
    return new TargetUrl(uri);
  }
}

package info.jaspreet.shortlink.domain;

import java.time.Instant;

/**
 * The thing itself. Note what is absent: no @Entity, no @Id, no getters
 * generated by a library, and no identifier column -- the database's
 * primary key is the database's business, and this record is what the rest
 * of the application passes around.
 *
 * ownerId is a String here for brevity; in a service with more than one
 * kind of id, make it a record too. Two adjacent Strings in a signature is
 * a bug waiting for someone to reorder the arguments.
 */
public record Link(
    ShortCode code,
    TargetUrl target,
    String ownerId,
    Instant createdAt,
    Instant expiresAt) {

  public boolean isExpired(Instant now) {
    return expiresAt != null && !now.isBefore(expiresAt);
  }
}
// src/main/java/info/jaspreet/shortlink/domain/CodeGenerator.java
package info.jaspreet.shortlink.domain;

import java.security.SecureRandom;

/**
 * Codes are random, not sequential. A sequential code leaks how many links
 * exist and lets anyone walk every link you have ever made by counting.
 *
 * The alphabet has 32 characters, not 36: 0/o, 1/l and their friends are
 * removed so a code read aloud or copied off a slide survives the trip.
 */
public final class CodeGenerator {

  private static final char[] ALPHABET = "23456789abcdefghijkmnpqrstuvwxyz".toCharArray();

  private final SecureRandom random = new SecureRandom();
  private final int length;

  public CodeGenerator(int length) {
    this.length = length;
  }

  public ShortCode next() {
    char[] out = new char[length];
    for (int i = 0; i < out.length; i++) {
      out[i] = ALPHABET[random.nextInt(ALPHABET.length)];
    }
    return new ShortCode(new String(out));
  }
}

// 32^7 is about 34 billion codes. With ten million links already stored, a
// fresh code collides roughly once every 3,400 inserts -- rare, but not
// never, and "rare" is the failure mode that reaches production untested.
// The unique index catches it and the repository retries; see the next
// topic. The generator does not have to be perfect, it has to be random.

Validating the host is not the same as blocking a private address

It is tempting to add a check here that refuses 127.0.0.1, 10.x and 169.254.169.254, and for a service that fetches the target — to unfurl a preview, to check liveness — you must, because otherwise your link shortener is a proxy into your own VPC and the cloud metadata endpoint is one request away. But do it at fetch time, on the resolved IP, not here on the hostname: a name that resolves to a public address when the link is created can resolve to a private one when it is followed, and a check written at creation time cannot see that. This service only ever hands the URL back to a browser, so the parse above is the whole control — and the day someone adds a preview fetcher, that is the day this note becomes code.

The schema, the entity, and the first migration

Three lifetimes live in this topic and confusing them is the source of most Spring Data pain: the schema, which Flyway owns and Hibernate is only allowed to check; the entity, which is a mutable class because Hibernate needs one; and the session, which lasts exactly as long as the transaction and not one line longer.

-- V1__create_links.sql -- Flyway runs this once, in order, and records it.
-- Once this file has run anywhere but your laptop it is immutable. A fix
-- is V2, always, because Flyway checksums what it has already applied and
-- will refuse to start against a file that changed underneath it.

CREATE TABLE links (
    id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    code            TEXT        NOT NULL,
    target_url      TEXT        NOT NULL,
    owner_id        TEXT        NOT NULL,
    idempotency_key TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at      TIMESTAMPTZ,

    -- Named, not auto-generated. The service switches on this name to tell
    -- "that code is taken" apart from "that request already happened", and
    -- a name Postgres invented is a name someone will change by accident.
    CONSTRAINT links_code_key UNIQUE (code)
);

-- Idempotency, as a constraint rather than as a check in application code.
-- Partial, because most links have no key and NULLs are not equal to each
-- other -- without the WHERE clause this index would be pointless on
-- Postgres and wrong on a database where NULLs do compare equal.
CREATE UNIQUE INDEX links_owner_idempotency_key
    ON links (owner_id, idempotency_key)
    WHERE idempotency_key IS NOT NULL;

-- The list endpoint's query, in the order it reads.
CREATE INDEX links_owner_created_at ON links (owner_id, created_at DESC);

CREATE TABLE api_keys (
    id         BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    owner_id   TEXT NOT NULL,
    label      TEXT NOT NULL,
    key_hash   TEXT NOT NULL,   -- sha-256 hex. Never the key itself.
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    revoked_at TIMESTAMPTZ,

    CONSTRAINT api_keys_key_hash_key UNIQUE (key_hash)
);

TIMESTAMPTZ, every time, with no exceptions worth arguing about

Postgres’ TIMESTAMP stores a wall-clock reading with no zone, which means it is only meaningful if every writer and every reader agree about which clock they meant — and they will not, because one of them is a batch job that runs on a machine in a different region and one of them is a laptop in October. TIMESTAMPTZ stores an instant. It maps to java.time.Instant, it survives a daylight-saving boundary, and it makes “when did this happen” a question with one answer. The only cost is that you must remember it does not store the zone the event happened in — if that is business data, it is a second column.

  private String targetUrl;

  private String ownerId;

  @Column(name = "idempotency_key", updatable = false)
  private String idempotencyKey;

  @Column(name = "created_at", nullable = false, updatable = false)
  private Instant createdAt;

  @Column(name = "expires_at")
  private Instant expiresAt;

  protected LinkEntity() {
    // for Hibernate, and for nobody else
  }

  LinkEntity(String code, String targetUrl, String ownerId,
             String idempotencyKey, Instant createdAt, Instant expiresAt) {
    this.code = code;
    this.targetUrl = targetUrl;
    this.ownerId = ownerId;
    this.idempotencyKey = idempotencyKey;
    this.createdAt = createdAt;
    this.expiresAt = expiresAt;
  }

  // null until the row is flushed, so an entity added to a HashSet before
  // the flush and looked up after it would be gone -- the hash changed
  // while the object was in the bucket. code is assigned before persist
  // and never updated, so it is stable for the object's whole life, which
  // is exactly what the collections topic said the contract requires.
  @Override
  public boolean equals(Object other) {
    return other instanceof LinkEntity that && Objects.equals(code, that.code);
  }

  @Override
  public int hashCode() {
    return Objects.hashCode(code);
  }

  String getCode() { return code; }
  String getTargetUrl() { return targetUrl; }
  String getOwnerId() { return ownerId; }
  String getIdempotencyKey() { return idempotencyKey; }
  Instant getCreatedAt() { return createdAt; }
  Instant getExpiresAt() { return expiresAt; }

  void setTargetUrl(String targetUrl) { this.targetUrl = targetUrl; }
  void setExpiresAt(Instant expiresAt) { this.expiresAt = expiresAt; }
}

IDENTITY silently turns off insert batching, and the property that claims otherwise stays in your YAML

hibernate.jdbc.batch_size: 50 is in the configuration above and it is doing nothing for inserts into this table. To batch inserts, Hibernate has to hold several rows and send them together; to return the generated id of a row, it has to send that row on its own and read back what the database assigned. GenerationType.IDENTITY asks for the second, so it gets the second. For a service that writes one row per request — this one — that is free, and IDENTITY is the simpler schema. For anything that imports in bulk, switch the id to a SEQUENCE with an allocation size, let Hibernate pre-allocate a block of ids, and the batching starts working. Knowing why your batch setting is inert is the difference between tuning and guessing.

The repository, and the race you cannot check for

Two requests arrive at the same millisecond with the same Idempotency-Key. Both look for an existing link, both find nothing, both insert. Reading before writing does not fix that and no amount of application code can, because the gap between the read and the write is where the other request lives. The database closes the gap; the interesting part in Java is that catching the violation is not allowed to happen where you would naturally write it.

package info.jaspreet.shortlink.persistence;

import info.jaspreet.shortlink.error.ShortlinkException.CodeTaken;
import info.jaspreet.shortlink.error.ShortlinkException.IdempotencyClash;
import java.time.Instant;
import org.hibernate.exception.ConstraintViolationException;
import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

/**
 * The insert, alone, in a transaction of its own -- and this is the whole
 * point of the class existing rather than being a method on the service.
 *
 * A constraint violation marks the current transaction rollback-only. You
 * cannot catch it and carry on inside the same transaction: the next
 * statement fails with "Transaction silently rolled back" and the real
 * cause is three frames further back. So the attempt that might fail gets
 * its own boundary, and the caller's catch block sits outside it, where
 * there is nothing broken to continue.
 *
 * REQUIRES_NEW rather than the default, so this stays true on the day
 * somebody annotates the service. And a separate bean rather than a
 * private method, because @Transactional is a proxy and a call to this.x()
 * never touches it.
 */
@Component
public class LinkWriter {

  private static final String CODE_UNIQUE = "links_code_key";
  private static final String IDEMPOTENCY_UNIQUE = "links_owner_idempotency_key";

  private final LinkRecordRepository rows;

  LinkWriter(LinkRecordRepository rows) {
    this.rows = rows;
  }

  @Transactional(propagation = Propagation.REQUIRES_NEW)
  public LinkEntity insert(String code, String targetUrl, String ownerId,
                           String idempotencyKey, Instant createdAt, Instant expiresAt) {
    var row = new LinkEntity(code, targetUrl, ownerId, idempotencyKey, createdAt, expiresAt);
    try {
      // saveAndFlush, not save. save() only queues the insert; without the
      // flush the violation surfaces when the transaction commits, which
      // is after this method returns and outside this try block.
      return rows.saveAndFlush(row);
    } catch (DataIntegrityViolationException e) {
      // Translate infrastructure into domain here, so that nothing above
      // this package has to know Hibernate exists. Java 21's switch over
      // a String with a null label makes the three cases explicit.
      throw switch (constraintOf(e)) {
        case CODE_UNIQUE -> new CodeTaken(code);
        case IDEMPOTENCY_UNIQUE -> new IdempotencyClash(idempotencyKey);
        case null, default -> e;   // some other constraint: not ours to explain
      };
    }
  }

  private static String constraintOf(DataIntegrityViolationException e) {
    return e.getCause() instanceof ConstraintViolationException violation
        ? violation.getConstraintName()
        : null;
  }
}

Why not just check first?

Because findByOwnerIdAndIdempotencyKey followed by insert is two statements with a gap, and under READ COMMITTED — Postgres’ default and almost certainly yours — another transaction can commit inside that gap. The check is still worth doing as the fast path, because the overwhelmingly common case is a retry seconds later and a read is cheaper than a failed insert; it just cannot be the guarantee. The guarantee is the index. Everything else is an optimisation, and describing it that way in an interview is most of the answer.

import info.jaspreet.shortlink.error.ShortlinkException.IdempotencyClash;
import info.jaspreet.shortlink.error.ShortlinkException.LinkExpired;
import info.jaspreet.shortlink.error.ShortlinkException.LinkNotFound;
import info.jaspreet.shortlink.error.ShortlinkException.NoCodeAvailable;
import info.jaspreet.shortlink.persistence.LinkStore;
import java.time.Clock;
import java.time.Duration;
import java.time.Instant;
import java.util.List;

/**
 * The use cases, and the only place the business rules are sequenced.
 * No HttpServletRequest, no ResponseEntity, no status codes -- everything
 * here would work unchanged from a message consumer or a CLI, which is the
 * test for whether a service layer is worth having at all.
 *
 * There is no @Service on it either, and no Spring import in this file at
 * all. It is a plain object with four constructor arguments; the
 * configuration class decides what those are. That costs four lines there
 * and buys a rule ArchUnit can state without exceptions -- the service
 * package does not depend on the framework -- plus a constructor a test
 * can call with a fake clock and no context at all.
 */
public class LinkService {

  private static final int MAX_CODE_ATTEMPTS = 5;

  private final LinkStore links;
  private final CodeGenerator codes;
  private final Clock clock;
  private final Duration defaultTtl;

  public LinkService(LinkStore links, CodeGenerator codes, Clock clock, Duration defaultTtl) {
    this.links = links;
    this.codes = codes;
    this.clock = clock;          // injected, so a test can freeze time
    this.defaultTtl = defaultTtl;
  }

  /** Everything one create needs, so the signature cannot be called wrong. */
  public record NewLink(String ownerId, TargetUrl target,
                        ShortCode alias, Duration ttl, String idempotencyKey) {}

  public Link shorten(NewLink request) {
    // The fast path: a client retrying after a timeout, seconds later.
    if (request.idempotencyKey() != null) {
      var existing = links.findByIdempotencyKey(request.ownerId(), request.idempotencyKey());
      if (existing.isPresent()) {
        return existing.get();
      }
    }

    Instant now = clock.instant();
    Instant expiresAt = now.plus(request.ttl() == null ? defaultTtl : request.ttl());

    for (int attempt = 1; attempt <= MAX_CODE_ATTEMPTS; attempt++) {
      ShortCode code = request.alias() != null ? request.alias() : codes.next();
      try {
        return links.insert(code, request, now, expiresAt);
      } catch (IdempotencyClash clash) {
        // The slow path: a genuine race. The other request won, and its
        // link is the correct answer to both of them.
        return links.findByIdempotencyKey(request.ownerId(), request.idempotencyKey())
            .orElseThrow(() -> new IllegalStateException("clash with no winner", clash));
      } catch (CodeTaken taken) {
        // A caller's chosen alias is a 409 they can act on. A generated
        // code that collided is our problem, and the fix is another code.
        if (request.alias() != null) {
          throw new AliasTaken(code);
        }
      }
    }
    throw new NoCodeAvailable(MAX_CODE_ATTEMPTS);
  }

  public Link resolve(ShortCode code) {
    Link link = links.findByCode(code).orElseThrow(() -> new LinkNotFound(code));
    if (link.isExpired(clock.instant())) {
      // Deliberately not 404: a client that gets "gone" can stop retrying,
      // and an operator reading the logs can tell the two apart.
      throw new LinkExpired(code);
    }
    return link;
  }

  public Link readOwned(String ownerId, ShortCode code) {
    return links.findByCode(code)
        .filter(link -> link.ownerId().equals(ownerId))
        .orElseThrow(() -> new LinkNotFound(code));
  }

  public List<Link> listOwned(String ownerId, int limit) {
    return links.listOwned(ownerId, Math.clamp(limit, 1, 500));
  }

  public void delete(String ownerId, ShortCode code) {
    if (links.deleteOwned(ownerId, code) == 0) {
      // Zero rows means it does not exist or it is not yours, and the API
      // says the same thing for both. Telling an unauthorised caller that
      // a code exists is how you enumerate a database.
      throw new LinkNotFound(code);
    }
  }
}

LinkStore is a small interface in the persistence package — findByCode, findByIdempotencyKey, insert, deleteOwned — implemented by a class that owns the repository and the writer and does the entity-to-domain mapping. It exists so that the service depends on four methods it defined rather than on the twenty JpaRepository supplies, and so that ArchitectureTest can say the service package does not import Spring Data at all.

302 and no-store, not 301 — and this is not a style preference

A 301 is permanent, and browsers treat it that way: Chrome will cache it, often for the life of the profile, and will not ask you again. Ship a 301 and you have given away the three things a link shortener exists to have. You can never re-point the link, because the browser stops asking. You can never expire or delete it, for the same reason. And your click metrics fall off a cliff, because after the first visit each user redirects locally and you never see it. The 301 is faster for the user by exactly one round trip and costs you the product. Send 302 with Cache-Control: no-store, and if the latency ever genuinely matters, buy it back at the CDN where you can still purge.

Failure is part of the contract

A service has two APIs and only one of them is documented. The other is what happens when things go wrong, and it is the one a client actually integrates against: which status codes mean retry, which mean stop, and whether the body is parseable when it is not a 200. Spring gives you ProblemDetail for the shape; a sealed hierarchy gives you a compiler that will not let you forget a case.

// src/main/java/info/jaspreet/shortlink/error/ShortlinkException.java
package info.jaspreet.shortlink.error;

import info.jaspreet.shortlink.domain.ShortCode;

/**
 * Every failure this service raises on purpose, in one sealed hierarchy.
 *
 * Sealed is the point. The handler switches over this type, and because
 * the compiler knows the complete list of subclasses it will reject the
 * switch the moment somebody adds a seventh -- so a new failure mode
 * cannot reach a client as an unmapped 500 six weeks later. That is the
 * same guarantee the sealed-interfaces topic promised, applied to the one
 * place in a service where "I forgot a case" is most expensive.
 *
 * Note what is not here: no status codes, no HTTP. This package is
 * importable from a batch job.
 */
public abstract sealed class ShortlinkException extends RuntimeException {

  protected ShortlinkException(String message) {
    // No cause, no stack trace filled in for the expected ones: these are
    // control flow, not incidents, and a stack trace per 404 is a bill.
    super(message, null, false, false);
  }

  public static final class LinkNotFound extends ShortlinkException {
    public LinkNotFound(ShortCode code) {
      super("no link with code " + code.value());
    }
  }

  public static final class LinkExpired extends ShortlinkException {
    public LinkExpired(ShortCode code) {
      super("link " + code.value() + " has expired");
    }
  }

  public static final class AliasTaken extends ShortlinkException {
    public AliasTaken(ShortCode code) {
      super("the alias " + code.value() + " is already in use");
    }
  }

  public static final class CodeTaken extends ShortlinkException {
    public CodeTaken(String code) {
      super("code " + code + " is already in use");
    }
  }

  public static final class IdempotencyClash extends ShortlinkException {
    public IdempotencyClash(String key) {
      super("concurrent request with idempotency key " + key);
    }
  }

  public static final class NoCodeAvailable extends ShortlinkException {
    public NoCodeAvailable(int attempts) {
      super("no free code after " + attempts + " attempts");
    }
  }
}

A sealed class whose subclasses are nested inside it needs no permits clause — the compiler takes the enclosing file as the permitted set, which is exactly the boundary you want here. Now the one place that knows these are HTTP.

import info.jaspreet.shortlink.error.ShortlinkException;
import info.jaspreet.shortlink.error.ShortlinkException.AliasTaken;
import info.jaspreet.shortlink.error.ShortlinkException.CodeTaken;
import info.jaspreet.shortlink.error.ShortlinkException.IdempotencyClash;
import info.jaspreet.shortlink.error.ShortlinkException.LinkExpired;
import info.jaspreet.shortlink.error.ShortlinkException.LinkNotFound;
import info.jaspreet.shortlink.error.ShortlinkException.NoCodeAvailable;
import java.net.URI;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

/**
 * One advice, one media type, one shape. RFC 9457 problem+json, which is
 * what Spring's ProblemDetail already produces, so the framework's own
 * 404s and 415s match the ones written here instead of being a second,
 * undocumented error format the client also has to parse.
 */
@RestControllerAdvice
class ApiExceptionHandler {

  private static final Logger log = LoggerFactory.getLogger(ApiExceptionHandler.class);
  private static final String TYPES = "https://study.jaspreet.info/problems/";

  @ExceptionHandler(ShortlinkException.class)
  ProblemDetail onDomainFailure(ShortlinkException failure) {
    // Exhaustive over a sealed type: no default branch, and adding a
    // subclass to the hierarchy breaks this build rather than production.
    ProblemDetail problem = switch (failure) {
      case LinkNotFound e -> of(HttpStatus.NOT_FOUND, "Link not found", e, "link-not-found");
      case LinkExpired e -> of(HttpStatus.GONE, "Link expired", e, "link-expired");
      case AliasTaken e -> of(HttpStatus.CONFLICT, "Alias taken", e, "alias-taken");
      case CodeTaken e -> of(HttpStatus.CONFLICT, "Code taken", e, "code-taken");
      case IdempotencyClash e -> of(HttpStatus.CONFLICT, "Request in flight", e, "in-flight");
      case NoCodeAvailable e -> of(HttpStatus.SERVICE_UNAVAILABLE, "Try again", e, "no-code");
    };
    return problem;
  }

  // Bean validation failures: 400, and say which field, because "invalid
  // request" costs the caller an hour and costs you a support ticket.
  @ExceptionHandler(MethodArgumentNotValidException.class)
  ProblemDetail onInvalidBody(MethodArgumentNotValidException invalid) {
    ProblemDetail problem = ProblemDetail.forStatusAndDetail(
        HttpStatus.BAD_REQUEST, "One or more fields are invalid");
    problem.setTitle("Invalid request");
    problem.setType(URI.create(TYPES + "invalid-request"));
    problem.setProperty("errors", invalid.getBindingResult().getFieldErrors().stream()
        .map(field -> java.util.Map.of(
            "field", field.getField(),
            "message", String.valueOf(field.getDefaultMessage())))
        .toList());
    return problem;
  }

  // The value objects reject bad input by throwing this, and a rejected
  // URL is the caller's mistake, not ours.
  @ExceptionHandler(IllegalArgumentException.class)
  ProblemDetail onIllegalArgument(IllegalArgumentException bad) {
    ProblemDetail problem =
        ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, bad.getMessage());
    problem.setTitle("Invalid request");
    problem.setType(URI.create(TYPES + "invalid-request"));
    return problem;
  }

  // The catch-all. Log everything, tell the client nothing: a stack trace
  // in a response body is a map of your dependencies and their versions.
  @ExceptionHandler(Exception.class)
  ProblemDetail onUnexpected(Exception unexpected) {
    log.error("unhandled exception", unexpected);
    ProblemDetail problem = ProblemDetail.forStatusAndDetail(
        HttpStatus.INTERNAL_SERVER_ERROR, "Unexpected error");

The catch-all advice will swallow your framework’s errors if you let it

package info.jaspreet.shortlink.security;

import info.jaspreet.shortlink.persistence.ApiKeyStore;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.HexFormat;
import java.util.List;
import org.springframework.http.MediaType;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

@Component
public class ApiKeyFilter extends OncePerRequestFilter {

  private static final String SCHEME = "Bearer ";

  private final ApiKeyStore keys;
  private final RateLimiter limiter;

  ApiKeyFilter(ApiKeyStore keys, RateLimiter limiter) {
    this.keys = keys;
    this.limiter = limiter;
  }

  @Override
  protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                  FilterChain chain) throws ServletException, IOException {
    String header = request.getHeader("Authorization");
    if (header != null && header.startsWith(SCHEME)) {
      String presented = header.substring(SCHEME.length()).trim();
      String digest = sha256Hex(presented);

      // The lookup is by hash, so a database that leaks tells an attacker
      // nothing usable: they get the digests, and a 256-bit random key is
      // not coming back out of one.
      keys.findActiveByHash(digest)
          // Redundant on its face -- we found the row by this hash -- and
          // kept anyway, because it is the line that stays correct if the
          // lookup ever becomes a prefix scan or a cache. Constant time,
          // so no attacker learns anything from how long a miss took.
          .filter(stored -> MessageDigest.isEqual(
              stored.keyHash().getBytes(StandardCharsets.UTF_8),
              digest.getBytes(StandardCharsets.UTF_8)))
          .ifPresent(stored -> authenticate(new ApiKey(stored.ownerId(), stored.label())));
    }

    // No key, or a key we do not know: the context stays empty and the
    // authorization rules decide. This filter has no opinion about 401.
    var caller = SecurityContextHolder.getContext().getAuthentication();
    if (caller != null && caller.getPrincipal() instanceof ApiKey key
        && !limiter.tryAcquire(key.ownerId())) {
      tooManyRequests(response);
      return;
    }
    try {
      chain.doFilter(request, response);
    } finally {
      // A pooled thread outlives the request. Clearing is not optional.
      SecurityContextHolder.clearContext();
    }
  }

  private static void authenticate(ApiKey key) {
    var token = new UsernamePasswordAuthenticationToken(
        key, null, List.of(new SimpleGrantedAuthority("ROLE_API")));
    SecurityContextHolder.getContext().setAuthentication(token);
  }

  private void tooManyRequests(HttpServletResponse response) throws IOException {
    response.setStatus(429);
    response.setHeader("Retry-After", "60");   // seconds, and mean it
    response.setContentType(MediaType.APPLICATION_PROBLEM_JSON_VALUE);
    response.getWriter().write("""
        {"type":"https://study.jaspreet.info/problems/rate-limited",\
        "title":"Too many requests","status":429,\
        "detail":"the per-minute quota for this key is spent"}""");
  }

  private static String sha256Hex(String value) {
    try {
      var sha256 = MessageDigest.getInstance("SHA-256");
      return HexFormat.of().formatHex(sha256.digest(value.getBytes(StandardCharsets.UTF_8)));
    } catch (NoSuchAlgorithmException impossible) {
      throw new IllegalStateException("every JVM has SHA-256", impossible);
    }
  }
}

SHA-256 for an API key, bcrypt for a password — and swapping them is a bug both ways

A password is a low-entropy secret a human chose, so the defence against a stolen hash table is to make each guess expensive: bcrypt, scrypt or argon2, deliberately slow, with a per-row salt. An API key is 256 bits from SecureRandom; there is no dictionary to run against it and no amount of GPU that gets through the search space, so a plain SHA-256 is enough. It is also necessary — put bcrypt on the API key path and you have added a hundred milliseconds of CPU to every single request, which at any real rate is a fleet of pods spent hashing. Use a fast hash for high-entropy secrets and a slow one for human-chosen ones, and be able to say why in one sentence, because this is asked constantly.

The other half of the rule is the key’s life: generate it with SecureRandom, show the plaintext to the user exactly once at creation, store only the digest, and give every key a revoked_at so revocation is an update rather than a delete you cannot audit. A prefix like sl_live_ costs nothing and lets a secret scanner find it in a public repository before an attacker does.

package info.jaspreet.shortlink.security;

import info.jaspreet.shortlink.config.ShortlinkProperties;
import java.time.Duration;
import java.util.List;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.data.redis.core.script.DefaultRedisScript;
import org.springframework.data.redis.core.script.RedisScript;
import org.springframework.stereotype.Component;

/**
 * A fixed window counter in Redis. Not a HashMap: four replicas each with
 * their own map give a caller four times the quota, and a deploy resets
 * everyone's limit to zero -- which is exactly when you least want it.
 */
@Component
public class RateLimiter {

  private static final Logger log = LoggerFactory.getLogger(RateLimiter.class);

  // Two commands as one round trip and one atomic step. INCR then EXPIRE
  // as separate calls has a window where the process dies in between and
  // leaves a key with no TTL -- which bans that caller permanently.
  private static final RedisScript<Long> INCREMENT = new DefaultRedisScript<>("""
      local hits = redis.call('INCR', KEYS[1])
      if hits == 1 then
        redis.call('PEXPIRE', KEYS[1], ARGV[1])
      end
      return hits
      """, Long.class);

  private final StringRedisTemplate redis;
  private final int permitted;
  private final Duration window;

  RateLimiter(StringRedisTemplate redis, ShortlinkProperties properties) {
    this.redis = redis;
    this.permitted = properties.rateLimit().perMinute();
    this.window = properties.rateLimit().window();
  }

  public boolean tryAcquire(String ownerId) {
    // The key carries the window, so the old window's key expires on its
    // own and there is nothing to clean up.
    long bucket = System.currentTimeMillis() / window.toMillis();
    String key = "rl:" + ownerId + ":" + bucket;
    try {
      Long hits = redis.execute(INCREMENT, List.of(key), String.valueOf(window.toMillis()));
      return hits == null || hits <= permitted;
    } catch (RuntimeException redisIsDown) {
      // Fail open, and say so loudly. A limiter that fails closed turns a
      // Redis blip into a total outage, which is a worse day than a minute
      // of unlimited traffic. If the limit is protecting something that
      // cannot survive that -- a payment endpoint, a third-party quota --
      // then fail closed instead, on purpose, and write that down.
      log.warn("rate limiter unavailable, allowing request", redisIsDown);
      return true;
    }
  }
}

@Component
@Order(Ordered.HIGHEST_PRECEDENCE)
public class RequestIdFilter extends OncePerRequestFilter {

  private static final String HEADER = "X-Request-Id";
  // An id from outside goes into every log line. Unvalidated, that is a
  // log injection: a newline in the header writes a fake log entry.
  private static final Pattern SAFE = Pattern.compile("[A-Za-z0-9._-]{1,64}");

  @Override
  protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                  FilterChain chain) throws ServletException, IOException {
    String inbound = request.getHeader(HEADER);
    String requestId = inbound != null && SAFE.matcher(inbound).matches()
        ? inbound
        : UUID.randomUUID().toString();

    MDC.put("requestId", requestId);
    // Echo it, so support can paste the header from a customer's HAR file
    // straight into the log search.
    response.setHeader(HEADER, requestId);
    try {
      chain.doFilter(request, response);
    } finally {
      // Mandatory. MDC is a ThreadLocal, threads are reused, and an id left
      // behind attaches somebody else's request to this customer's trace.
      MDC.remove("requestId");
    }
  }

The moment you submit to an ExecutorService, the pool’s thread has an empty context and those log lines lose the id, which is precisely when you needed it most. Logback’s MDC.getCopyOfContextMap() copied into the task is the manual fix, Micrometer’s ContextSnapshot is the framework one, and structured concurrency’s ScopedValue is where this is going. Whichever you pick, decide it once, in one wrapper, and never call executor.submit directly again.

Delete the index from V1 and run it: sixteen rows, sixteen codes, and the API cheerfully told sixteen callers they had each created something. Now put the index back and delete the catch (IdempotencyClash) branch instead: fifteen callers get a 500, which is worse than the first failure in every way that matters to a client. The test tells the two apart, which is the property you want — and it is why it is worth the eight seconds a container costs. This is also, almost word for word, a question you will be asked: how do you make this endpoint idempotent. The answer is a constraint, a translated violation, and a re-read — in that order.

The image, the pipeline, and the last mile

The packaging topic already covered layered extraction, the actuator probes and graceful shutdown, and none of that changes here. What is left is the part that only appears when there is a whole repository: an image built from source so that CI needs nothing installed, a pipeline that runs the same four commands a developer runs, and the short list of things that are still not done when the tests are green.

Before it is “done”Why it is on this list
Flyway runs as a separate step, not on start-upFour replicas starting together run four migrations. Postgres’ advisory lock means three of them wait rather than corrupt anything, but they wait through their readiness deadline. Run migrations once, in a job, before the new version rolls.
readiness wired to the readiness probe, liveness to the liveness probeThey are different endpoints because they answer different questions. Pointing both at /actuator/health restarts your pods every time the database hiccups.
Memory request equal to the limit, and the limit above MaxRAMPercentage of the heap plus overheadA JVM is heap plus metaspace plus thread stacks plus direct buffers plus the code cache. Size the container for all of it or the kernel kills the process with no stack trace and no log line.
Logs to stdout, and nowhere elseThe platform collects stdout. A log file inside a container is a disk that fills and an incident nobody can explain.
The dependency graph audited on every build, not on a calendarTwo of the last decade’s worst Java incidents were a transitive dependency nobody had listed. ./mvnw dependency:tree is how you find out you have it.
Alerts on the 500 rate and on p99 latency, not just dashboardsA dashboard is for after somebody noticed. An alert is for before.
A rollback that is one command, and that somebody has runEvery deploy plan has one. The ones that work have been rehearsed on a Tuesday afternoon rather than discovered at 2am.

Read this part next to the Python page’s and the differences are smaller than the languages suggest. Both put the rules in a layer that imports nothing, both make idempotency a database constraint rather than a check, both keep one error shape, both hash the API key and share the rate limit, and both fail the boot rather than the tenth request. What Java adds is enforcement: the sealed hierarchy makes the error switch exhaustive, the type system makes a ShortCode impossible to confuse with a String, and ArchUnit makes the layering a failing build rather than a convention. What it costs is the file count on this page. That trade — more ceremony up front, more caught by the compiler — is the entire argument for Java in a service, and it is the answer to give when somebody asks why you would choose it.
