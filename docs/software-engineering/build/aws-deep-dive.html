Part one

The contract every service shares

Before any single service, three things are true of all of them: your code gets credentials from a chain it did not write, every call is wrapped in retries and signing you cannot see, and the packet has to physically leave your subnet. Most “the SDK is broken” incidents are one of these three.

AWS · 01

The client, the credential chain and the retry

An AWS client is not a connection. It is a credential provider, a retryer, a signer and an HTTP pool bolted together — and each of those four has a default that is wrong for a busy service.

Snippets below in Go and Python — switch with the control in the bar, or press g / p.

// config.go — built once at start-up, shared by every client in the process.
cfg, err := config.LoadDefaultConfig(ctx,
    config.WithRegion("eu-west-1"),
    config.WithRetryer(func() aws.Retryer {
        // Standard: 3 attempts, exponential backoff with full jitter, and a
        // token bucket so a storm of retries cannot amplify an outage.
        // retry.NewAdaptiveMode wraps it with a client-side rate limiter that
        // slows you down when the service starts throttling.
        return retry.NewStandard(func(o *retry.StandardOptions) {
            o.MaxAttempts = 5
            o.MaxBackoff = 3 * time.Second
        })
    }),
    config.WithHTTPClient(awshttp.NewBuildableClient().
        WithTimeout(10*time.Second).                // PER ATTEMPT, not per call
        WithTransportOptions(func(t *http.Transport) {
            t.MaxIdleConnsPerHost = 100             // the SDK client defaults to 10
        })),
)
if err != nil {
    return fmt.Errorf("aws config: %w", err)        // fail the process, not the request
}

Errors: the code matters more than the message

Every AWS error carries a code, an HTTP status and a request ID. Branch on the code — never on the message text, which AWS reserves the right to reword. The request ID is what support asks for, so log it.

Pagination and waiters, without the loop you always get wrong

Every list-shaped AWS API is paginated, and the page you get back is capped by size as well as count — a Query can return zero items and still hand you a continuation token because it scanned 1 MB of non-matching rows. Never treat an empty page as the end. Both SDKs ship paginators that get this right; use them.

p := s3.NewListObjectsV2Paginator(app.s3, &s3.ListObjectsV2Input{
    Bucket: aws.String("orders-archive"),
    Prefix: aws.String("2026/08/"),
})
for p.HasMorePages() {
    page, err := p.NextPage(ctx)          // ctx cancels mid-listing
    if err != nil {
        return err
    }
    for _, o := range page.Contents {
        handle(aws.ToString(o.Key), aws.ToInt64(o.Size))
    }
}

// Waiters poll for you, with the service’s own recommended interval —
// and, crucially, with a maximum wait, so a stuck resource fails the deploy.
w := rds.NewDBInstanceAvailableWaiter(app.rds)
err = w.Wait(ctx, &rds.DescribeDBInstancesInput{
    DBInstanceIdentifier: aws.String("orders-prod"),
}, 20*time.Minute)
for page in S3.get_paginator("list_objects_v2").paginate(
    Bucket="orders-archive",
    Prefix="2026/08/",
    PaginationConfig={"PageSize": 1000},          # per request, not a total cap
):
    for obj in page.get("Contents", []):          # .get: an empty page has no key
        handle(obj["Key"], obj["Size"])

# Server-side filtering beats client-side: JMESPath runs in botocore, but
# search() still downloads every page — use Prefix/StartAfter where you can.
keys = S3.get_paginator("list_objects_v2").paginate(
    Bucket="orders-archive", Prefix="2026/08/"
).search("Contents[?Size > `0`].Key")

# Waiters: the service’s own polling loop, with a bounded maximum.
RDS.get_waiter("db_instance_available").wait(
    DBInstanceIdentifier="orders-prod",
    WaiterConfig={"Delay": 30, "MaxAttempts": 40},   # 20 minutes, then raise
)

Region is not a formality

The region decides the endpoint, the signing scope and the price. A client with no region falls back to the environment, then the profile, then fails — and in Lambda it silently inherits the function’s region, which is why code that works deployed fails on a laptop.

The retry you did not order

SDK retries are invisible in your traces unless you look for them. In Go, retry.AddWithMaxAttempts and the attempt metrics; in Python, ResponseMetadata.RetryAttempts. A p99 that is exactly 3× your p50 is a retry story, not a slow-service story.

AWS · 02

IAM: the evaluation order, and how a process gets a role

IAM is not a list of permissions. It is a decision function run per request over up to six policy types, and it answers “deny” unless something explicitly allows — and nothing explicitly denies.

PrincipalA user has long-lived keys. A role has none — it is assumed, and hands out credentials that expire. Production code should only ever use roles.
Trust policyThe resource policy of the role itself. Names the principal allowed to assume it: a service, an account, or an OIDC provider with a sub condition.
BoundaryA ceiling attached to an identity. Lets you delegate “you may create roles” without letting the delegate create an admin role.
Condition keysWhere real least privilege lives: aws:PrincipalOrgID, aws:SourceVpce, s3:prefix, aws:SecureTransport, sts:ExternalId.

Assuming a role from code — and refreshing it

The one detail people miss: AssumeRole returns credentials with a fixed expiry. If your process outlives it and you did not wrap the call in something that refreshes, you get a clean, confusing ExpiredToken an hour after deploy.

AWS · 03

Where your code sits in the network

A private subnet has no route to the internet. Everything that follows — NAT bills, timing-out Lambdas, endpoints, security-group loops — is a consequence of that one sentence.

Make the network failure legible at boot

The worst version of this bug is a service that starts healthy, passes its health check, and only fails when the first real request needs S3. A ten-line probe at start-up turns a 3 a.m. mystery into a log line.

// reachable dials the service endpoint and separates the failure modes:
// name resolution (DNS / private DNS) from the TCP handshake (route / SG).
func reachable(ctx context.Context, host string) error {
    ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
    defer cancel()

    ips, err := net.DefaultResolver.LookupHost(ctx, host)
    if err != nil {
        // private DNS off on the interface endpoint, or DNS support off on the VPC
        return fmt.Errorf("dns %s: %w", host, err)
    }

    var d net.Dialer
    conn, err := d.DialContext(ctx, "tcp", net.JoinHostPort(host, "443"))
    if err != nil {
        // resolved but unreachable: no route, no egress rule, or no endpoint
        return fmt.Errorf("dial %s (%v): %w", host, ips[0], err)
    }
    _ = conn.Close()
    return nil
}

// At start-up, before the health check goes green:
for _, h := range []string{
    "sts.eu-west-1.amazonaws.com",              // credentials
    "dynamodb.eu-west-1.amazonaws.com",         // gateway endpoint or NAT
    "secretsmanager.eu-west-1.amazonaws.com",   // interface endpoint only
} {
    if err := reachable(ctx, h); err != nil {
        return fmt.Errorf("startup connectivity: %w", err)   // crash loudly, now
    }
}

import socket


def reachable(host: str, port: int = 443, timeout: float = 3.0) -> None:
    try:
        infos = socket.getaddrinfo(host, port, proto=socket.IPPROTO_TCP)
    except socket.gaierror as e:
        # private DNS off on the interface endpoint, or DNS support off on the VPC
        raise Unreachable(f"dns {host}: {e}") from e

    family, kind, proto, _, addr = infos[0]
    with socket.socket(family, kind, proto) as s:
        s.settimeout(timeout)
        try:
            s.connect(addr)
        except OSError as e:
            # resolved but unreachable: no route, no egress rule, or no endpoint
            raise Unreachable(f"dial {host} ({addr[0]}): {e}") from e

Plan addresses before you plan anything else

A VPC CIDR cannot be shrunk, and every workload that uses awsvpc networking — Fargate tasks, EKS pods with the VPC CNI, VPC Lambdas — consumes real subnet addresses. A /16 split into three /20 private subnets gives you about 4,000 usable addresses per zone, which sounds infinite until a pod-per-request architecture arrives. Part two

Relational: RDS and Aurora

RDS is your database with the operations attached. Aurora is a different storage engine wearing the same wire protocol. The distinction decides your failover time, your bill, and how much of your recovery plan is a button versus a weekend.

AWS · 04

RDS: every knob, and which ones cost you an outage

An RDS instance is a normal Postgres or MySQL server plus six configuration surfaces — compute, storage, parameters, backups, availability and maintenance. Changing three of them is instant; changing the other three restarts your database.

Storage · gp33,000 IOPS and 125 MB/s baseline included, both independently provisionable. The default for almost everything, and it removed gp2’s burst-credit cliff.
Storage · io2Up to 256,000 IOPS with a five-nines durability claim. You want it when a sustained write workload is IOPS-bound, and you will feel the price.
AutoscalingGrows storage when free space drops below 10%. Set a maximum — without one a runaway write can grow you into a very large bill.
T-classBurstable CPU credits. Fine for dev, dangerous in production: when credits run out the instance is throttled to baseline and everything queues at once.

A pre-deploy guard for the database

Three RDS facts should block a release: pending maintenance that will reboot you mid-deploy, a certificate authority about to expire, and storage close to the autoscaling ceiling. All three are one API call each.

// preflight fails the pipeline if the database is about to move under us.
func preflight(ctx context.Context, c *rds.Client, id string) error {
    d, err := c.DescribeDBInstances(ctx, &rds.DescribeDBInstancesInput{
        DBInstanceIdentifier: aws.String(id),
    })
    if err != nil {
        return err
    }
    in := d.DBInstances[0]

    // 1. a modification already queued for the next window (class, storage, params)
    if p := in.PendingModifiedValues; p != nil && p.DBInstanceClass != nil {
        return fmt.Errorf("pending class change to %s", aws.ToString(p.DBInstanceClass))
    }

    // 2. static parameters saved but not yet live — the reboot is still owed
    for _, g := range in.DBParameterGroups {
        if aws.ToString(g.ParameterApplyStatus) == "pending-reboot" {
            return fmt.Errorf("parameter group %s awaits a reboot",
                aws.ToString(g.DBParameterGroupName))
        }
    }

    // 3. maintenance AWS will apply for us, whether or not we are deploying
    m, err := c.DescribePendingMaintenanceActions(ctx,
        &rds.DescribePendingMaintenanceActionsInput{
            ResourceIdentifier: in.DBInstanceArn,
        })
    if err != nil {
        return err
    }
    for _, r := range m.PendingMaintenanceActions {
        for _, a := range r.PendingMaintenanceActionDetails {
            log.Warn("pending maintenance",
                "action", aws.ToString(a.Action),                 // system-update, ca-certificate-rotation…
                "auto_applied_after", a.AutoAppliedAfterDate)
        }
    }
    log.Info("db ok", "ca", aws.ToString(in.CACertificateIdentifier),
        "engine", aws.ToString(in.EngineVersion),
        "multi_az", aws.ToBool(in.MultiAZ))
    return nil
}

RDS Blue/Green clones the instance, keeps it in sync by logical replication, lets you upgrade and test the green copy, then switches over in about a minute with the endpoint names swapped. It is the only sane way to do a major version upgrade on a database you care about.

Aurora DSQL is a different product with a familiar name

Aurora DSQL is a serverless, distributed, active-active SQL database with a Postgres-compatible wire protocol and optimistic concurrency control. DynamoDB: the partition key is the design

S3: a flat namespace with strong opinions

There are no directories, no rename, and no partial update: an object is written whole or not at all. Everything S3 gives you — versioning, lifecycle, presigned access, event notification — is built on that immutability.

Events are at-least-once and unordered

An S3 notification can arrive twice and out of order, and a rapid overwrite can deliver the second event first. Carry the versionId in the event and fetch that version, or make the handler idempotent on the key. Routing events through EventBridge instead gives you filtering, replay and multiple consumers for the same cost.

Requests are not free

Roughly $0.0004 per thousand GETs sounds like nothing until a job lists a million-key prefix in a loop. On a bucket of small objects, request charges and per-object overheads regularly exceed storage. Aggregate small files before you archive them.

ElastiCache: a cache is a load-bearing dependency

Adding a cache changes your failure modes as much as your latency. The two questions that matter are what happens on a miss storm, and what happens when the cache itself is gone.

// Cache-aside with single flight and fail-open. golang.org/x/sync/singleflight
// collapses concurrent misses of the same key into one origin call.
type Cache struct {
    rdb *redis.Client
    sf  singleflight.Group
}

func (c *Cache) Order(ctx context.Context, id string) (*Order, error) {
    key := "order:" + id

    // A cache read gets a much tighter deadline than the request itself.
    rctx, cancel := context.WithTimeout(ctx, 50*time.Millisecond)
    defer cancel()

    if b, err := c.rdb.Get(rctx, key).Bytes(); err == nil {
        var o Order
        if json.Unmarshal(b, &o) == nil {
            return &o, nil
        }
    } else if !errors.Is(err, redis.Nil) {
        cacheErrors.Inc()          // FAIL OPEN: log it, fall through to origin
    }

    v, err, _ := c.sf.Do(key, func() (any, error) {
        o, err := loadFromDB(ctx, id)
        if err != nil {
            return nil, err
        }
        b, _ := json.Marshal(o)
        // Jitter: 10 minutes +/- 10%, so a batch cached together does not
        // expire together and rebuild the stampede you just prevented.
        ttl := 10*time.Minute + time.Duration(rand.Int63n(int64(2*time.Minute))) - time.Minute
        _ = c.rdb.Set(ctx, key, b, ttl).Err()
        return o, nil
    })
    if err != nil {
        return nil, err
    }
    return v.(*Order), nil
}

import asyncio, json, random

_inflight: dict[str, asyncio.Future] = {}


async def get_order(order_id: str) -> Order:

        raw = await asyncio.wait_for(redis.get(key), timeout=0.05)
        if raw is not None:
            return Order(**json.loads(raw))
    except (asyncio.TimeoutError, RedisError):
        CACHE_ERRORS.inc()      # FAIL OPEN: count it, fall through to origin

    # Single flight: first caller creates the future, the rest await it.
    fut = _inflight.get(key)
    if fut is not None:
        return await asyncio.shield(fut)

    fut = asyncio.get_running_loop().create_future()
    _inflight[key] = fut
    try:
        order = await load_from_db(order_id)
        # Jitter: 10 minutes +/- 10%, so a batch cached together does not
        # expire together and rebuild the stampede you just prevented.
        ttl = int(600 * random.uniform(0.9, 1.1))
        await redis.set(key, json.dumps(order.dict()), ex=ttl)
        fut.set_result(order)
        return order
    except Exception as exc:
        fut.set_exception(exc)
        raise
    finally:
        _inflight.pop(key, None)

Part four

Compute: Lambda and ECS

Two ways to run your code, with different units of scaling: Lambda scales the number of concurrent invocations, ECS scales the number of long-lived processes. Almost every difference in cost, latency and operational feel follows from that.

AWS · 10

Lambda: the execution environment is the whole model

A Lambda function is not invoked — an execution environment is created, initialised, then used for many invocations, frozen between them, and eventually destroyed. Cold starts, connection reuse, background threads and half the surprises all live in that lifecycle.

Reserved concurrencyBoth a floor and a ceiling for one function: it is guaranteed that much, and can never exceed it. The blast-radius control — set it on anything that talks to a database.
Provisioned concurrencyEnvironments kept initialised and warm, billed by the hour. The only real fix for cold-start-sensitive user-facing paths, and it can be scheduled or autoscaled.
SnapStartSnapshots the environment after init and restores from it — large cold-start wins for Java, Python and .NET. Your init must not bake in anything unique, such as a random seed or an open socket.
Scaling rateA function can add on the order of 1,000 concurrent executions every 10 seconds, up to the account limit. A genuine spike is throttled at the edge of that ramp, not at the account cap.

The handler shape that gets everything right

Clients built at module scope, per-invocation deadlines derived from the remaining time, and partial batch failure reporting so one poison message does not replay the other nine.

func handle(ctx context.Context, ev events.SQSEvent) (events.SQSEventResponse, error) {
    // Leave headroom: finish, flush and return before Lambda kills us.
    if dl, ok := ctx.Deadline(); ok {
        var cancel context.CancelFunc
        ctx, cancel = context.WithDeadline(ctx, dl.Add(-500*time.Millisecond))
        defer cancel()
    }

    // Partial batch response: without this, ONE bad message redelivers all ten,
    // which is how a single poison record becomes a permanent replay loop.
    var failures []events.SQSBatchItemFailure

    for _, m := range ev.Records {
        if err := process(ctx, m); err != nil {
            log.Error("record failed", "message_id", m.MessageId, "err", err)
            failures = append(failures, events.SQSBatchItemFailure{
                ItemIdentifier: m.MessageId,
            })
        }
    }
    // Return nil error: the batch itself succeeded. Only the listed ids return
    // to the queue. Requires ReportBatchItemFailures on the event source mapping.
    return events.SQSEventResponse{BatchItemFailures: failures}, nil
}

The DLQ is not a graveyard

Alarm on ApproximateNumberOfMessagesVisible on the dead letter queue — any non-zero value is a bug report with the payload attached. When you have fixed the cause, the redrive API moves messages back to the source queue without a custom script.

FIFO ordering costs you parallelism

Messages in one group are delivered strictly in order, which means strictly one at a time. If your throughput target divided by your per-message time exceeds one, you need many groups — usually one per customer or entity, never one per queue.

Kinesis Data Streams: an ordered log with a cursor

A stream is not a queue. Records are not deleted when read — each consumer keeps its own position, records stay for as long as retention says, and ordering holds within a shard. That buys replay and multiple readers, and costs you the ability to skip a bad record for free.

// PutRecords is a batch of up to 500 records — and it returns 200 with
// individual failures inside. Resending the WHOLE batch duplicates the
// records that succeeded, so resend only the failed indexes.
func putAll(ctx context.Context, k *kinesis.Client, stream string,
    recs []types.PutRecordsRequestEntry) error {

    for attempt := 0; attempt < 5 && len(recs) > 0; attempt++ {
        out, err := k.PutRecords(ctx, &kinesis.PutRecordsInput{
            StreamName: aws.String(stream),
            Records:    recs,
        })
        if err != nil {
            return err
        }
        if aws.ToInt32(out.FailedRecordCount) == 0 {
            return nil
        }

        var retry []types.PutRecordsRequestEntry
        for i, r := range out.Records {
            if r.ErrorCode != nil {
                // ProvisionedThroughputExceededException — this shard is hot
                retry = append(retry, recs[i])
            }
        }
        recs = retry
        time.Sleep(time.Duration(1<<attempt) * 100 * time.Millisecond)
    }
    return fmt.Errorf("%d records never accepted", len(recs))
}

Static IP addresses per zone, source IP preserved to the target, millions of connections, and no HTTP awareness at all. Choose it for non-HTTP protocols, for clients that must allow-list an IP, and for extreme connection counts. Everything else wants an ALB, where routing rules and WAF live.

Secrets, parameters and KMS

KMS never gives you a key — it gives you a key encrypted under a key, and a decrypted copy to use immediately. Everything above it, Secrets Manager included, is that trick plus a place to keep the ciphertext.

// Cache with a TTL, and refresh on demand when authentication fails.
// Both halves matter: the cache saves money, the invalidation survives rotation.
type SecretCache struct {
    mu    sync.RWMutex
    sm    *secretsmanager.Client
    ttl   time.Duration
    value string
    at    time.Time
}

func (c *SecretCache) Get(ctx context.Context, force bool) (string, error) {
    c.mu.RLock()
    if !force && c.value != "" && time.Since(c.at) < c.ttl {
        v := c.value
        c.mu.RUnlock()
        return v, nil
    }
    c.mu.RUnlock()

    c.mu.Lock()
    defer c.mu.Unlock()
    if !force && c.value != "" && time.Since(c.at) < c.ttl {
        return c.value, nil                    // another goroutine refreshed it
    }

    out, err := c.sm.GetSecretValue(ctx, &secretsmanager.GetSecretValueInput{
        SecretId:     aws.String("orders/db"),
        VersionStage: aws.String("AWSCURRENT"),   // never pin a version id
    })
    if err != nil {
        return "", err
    }
    c.value, c.at = aws.ToString(out.SecretString), time.Now()
    return c.value, nil
}

import threading, time

SM = boto3.client("secretsmanager", config=CFG)


class SecretCache:
    def __init__(self, secret_id: str, ttl: float = 900.0):
        self._id, self._ttl = secret_id, ttl
        self._lock = threading.Lock()
        self._value: str | None = None
        self._at = 0.0

    def get(self, force: bool = False) -> str:
        fresh = self._value is not None and time.monotonic() - self._at < self._ttl
        if fresh and not force:
            return self._value
        with self._lock:
            # re-check: another thread may have refreshed while we waited
            fresh = self._value is not None and time.monotonic() - self._at < self._ttl
            if fresh and not force:
                return self._value
            res = SM.get_secret_value(
                SecretId=self._id,
                VersionStage="AWSCURRENT",     # never pin a version id
            )
            self._value, self._at = res["SecretString"], time.monotonic()
            return self._value

# into a single failed connection.

try:
    connect(cache.get())
except AuthError:

Key policies come first

A KMS key’s own policy is authoritative: an IAM policy granting kms:Decrypt does nothing unless the key policy delegates to IAM in that account. This is the reason cross-account S3 reads fail with a KMS error that names a role which visibly has the permission.

Never put a secret in a task definition

Plain environment values are visible to anyone with ecs:DescribeTaskDefinition, and they live in every revision for ever. Use the secrets block, which resolves an ARN at task start using the execution role — the value never appears in the definition, the API, or the console.

// POST /orders — the handler, with every failure mode from this page in it.
func (a *App) PlaceOrder(w http.ResponseWriter, r *http.Request) {
    ctx, cancel := context.WithTimeout(r.Context(), 8*time.Second)
    defer cancel()

    key := r.Header.Get("Idempotency-Key")
    if key == "" {
        writeErr(w, 400, "idempotency_key_required")
        return
    }

    var req PlaceOrderRequest
    if err := json.NewDecoder(http.MaxBytesReader(w, r.Body, 1<<20)).Decode(&req); err != nil {
        writeErr(w, 400, "bad_json")
        return
    }

    // 1. Claim the key. Conditional put: whoever wins does the work, and the
    //    TTL means abandoned claims clean themselves up.
    claimed, prior, err := a.claim(ctx, key, 24*time.Hour)
    switch {
    case err != nil:
        writeErr(w, 503, "try_again")
        return
    case !claimed && prior != nil:
        w.Header().Set("Idempotent-Replay", "true")
        _, _ = w.Write(prior)                    // byte-identical to the first reply
        return
    case !claimed:
        writeErr(w, 409, "in_progress")          // claimed, not finished: retry later
        return
    }

    // 2. Order and outbox row commit together, or neither exists.
    tx, err := a.pool.Begin(ctx)
    if err != nil {
        writeErr(w, 503, "try_again")
        return
    }
    defer tx.Rollback(ctx)                        // no-op after a successful commit

    order, err := insertOrder(ctx, tx, req)
    if err != nil {
        writeErr(w, 500, "internal")
        return
    }
    event, _ := json.Marshal(OrderPlaced{Version: "1", OrderID: order.ID})
    if err := insertOutbox(ctx, tx, order.ID, "OrderPlaced", event); err != nil {
        writeErr(w, 500, "internal")
        return
    }
    if err := tx.Commit(ctx); err != nil {
        // A commit that fails after a failover may still have applied. The
        // idempotency key is what makes the client’s retry safe here.
        writeErr(w, 503, "try_again")
        return
    }

    // 3. Store the reply against the key, so the retry gets THIS body.
    body, _ := json.Marshal(order)
    _ = a.completeClaim(ctx, key, body)
    w.WriteHeader(201)
    _, _ = w.Write(body)
}

The claim, in DynamoDB

One conditional write does all of it: reserve the key if nobody has it, return the stored response if the work is finished, and allow a re-attempt if a previous holder died before completing.

// claim reserves the idempotency key, or hands back the finished response.
func (a *App) claim(ctx context.Context, key string, ttl time.Duration) (bool, []byte, error) {
    now := time.Now()
    _, err := a.ddb.PutItem(ctx, &dynamodb.PutItemInput{
        TableName: aws.String("idempotency"),
        Item: map[string]types.AttributeValue{
            "pk":       &types.AttributeValueMemberS{Value: key},
            "state":    &types.AttributeValueMemberS{Value: "in_progress"},
            "expires":  &types.AttributeValueMemberN{Value: fmt.Sprint(now.Add(ttl).Unix())},
            "lockedAt": &types.AttributeValueMemberN{Value: fmt.Sprint(now.Unix())},
        },
        // Win if the key is unknown, OR if a previous holder crashed mid-flight
        // and its lock is stale. A FINISHED claim is never retaken — without the
        // state check, a retry 30s later re-runs the order instead of replaying it.
        // ("state" is a DynamoDB reserved word, hence the #st alias.)
        ConditionExpression: aws.String(
            "attribute_not_exists(pk) OR (#st = :inprog AND lockedAt < :stale)"),
        ExpressionAttributeNames: map[string]string{"#st": "state"},
        ExpressionAttributeValues: map[string]types.AttributeValue{
            ":inprog": &types.AttributeValueMemberS{Value: "in_progress"},
            ":stale": &types.AttributeValueMemberN{
                Value: fmt.Sprint(now.Add(-30 * time.Second).Unix())},
        },
        ReturnValuesOnConditionCheckFailure: types.ReturnValuesOnConditionCheckFailureAllOld,
    })
    if err == nil {
        return true, nil, nil
    }

    var failed *types.ConditionalCheckFailedException
    if !errors.As(err, &failed) {
        return false, nil, err
    }
    // We lost. The existing item comes back with the failure, so a completed
    // request needs no second read.
    if resp, ok := failed.Item["response"].(*types.AttributeValueMemberB); ok {
        return false, resp.Value, nil
    }
    return false, nil, nil                 // still in progress elsewhere
}

async def claim(key: str, ttl: timedelta) -> tuple[bool, bytes | None]:

    try:
        DDB.put_item(
            TableName="idempotency",
            Item={
                "pk": {"S": key},
                "state": {"S": "in_progress"},
                "expires": {"N": str(now + int(ttl.total_seconds()))},
                "lockedAt": {"N": str(now)},
            },
            # Win if the key is unknown, OR if a previous holder crashed mid-flight
            # and its lock is stale. A FINISHED claim is never retaken — without the
            # state check, a retry 30s later re-runs the order instead of replaying it.
            # ("state" is a DynamoDB reserved word, hence the #st alias.)
            ConditionExpression=(
                "attribute_not_exists(pk) OR (#st = :inprog AND lockedAt < :stale)"
            ),
            ExpressionAttributeNames={"#st": "state"},
            ExpressionAttributeValues={":inprog": {"S": "in_progress"},
                                       ":stale": {"N": str(now - 30)}},
            ReturnValuesOnConditionCheckFailure="ALL_OLD",
        )
        return True, None
    except DDB.exceptions.ConditionalCheckFailedException as e:
        # We lost. The existing item comes back with the failure, so a completed
        # request needs no second read.
        item = e.response.get("Item") or {}
        stored = item.get("response", {}).get("B")
        return False, stored          # stored is None while still in progress

The checklist, and one script that proves it

// preflight runs before the readiness probe goes green. Everything it checks
// is something that has silently broken a production deploy at least once.
func preflight(ctx context.Context, a *App) error {
    ctx, cancel := context.WithTimeout(ctx, 10*time.Second)
    defer cancel()

    // 1. Am I who the deployment thinks I am?
    who, err := a.sts.GetCallerIdentity(ctx, nil)
    if err != nil {
        return fmt.Errorf("no usable credentials: %w", err)
    }
    if !strings.Contains(aws.ToString(who.Arn), expectedRole) {
        return fmt.Errorf("wrong role: %s", aws.ToString(who.Arn))
    }

    // 2. Does the table exist, in this region, with a TTL as designed?
    tt, err := a.ddb.DescribeTimeToLive(ctx, &dynamodb.DescribeTimeToLiveInput{
        TableName: aws.String("idempotency"),
    })
    if err != nil {
        return fmt.Errorf("idempotency table: %w", err)
    }
    if tt.TimeToLiveDescription.TimeToLiveStatus != types.TimeToLiveStatusEnabled {
        return errors.New("idempotency table has no TTL: it will grow for ever")
    }

    // 3. Does every queue we consume have somewhere for poison to go?
    for _, q := range a.queues {
        at, err := a.sqs.GetQueueAttributes(ctx, &sqs.GetQueueAttributesInput{
            QueueUrl:       aws.String(q),
            AttributeNames: []sqstypes.QueueAttributeName{"RedrivePolicy"},
        })
        if err != nil {
            return err
        }
        if at.Attributes["RedrivePolicy"] == "" {
            return fmt.Errorf("queue %s has no dead letter queue", q)
        }
    }

    // 4. Can we actually write, with the timeout we promised?
    return a.pool.QueryRow(ctx, "SELECT 1").Scan(new(int))
}

The four sentences worth remembering

Every call can be retried, so every effect must be idempotent. Every managed service has a limit that is per-partition, per-shard or per-connection, not per-account — find yours before it finds you. The default configuration is optimised for getting started, not for running. And the bill is mostly data movement: bytes crossing a boundary you did not think about cost more than the compute that produced them.
