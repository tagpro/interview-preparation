Part eight

The ecosystem, and the taste that goes with it

Python’s standard library is famously large and famously not enough. Almost every job has a conventional answer — knowing which one, and what arrives in your image alongside it, is most of what “experienced in Python” means in practice.

The library map

There is a default choice for nearly every job. Deviating from it is completely fine — it just needs a reason you can say out loud, because the default is what the next person on the team will already know how to debug.

L1 · Beginner

Reach for the standard library first

  • It is genuinely large — pathlib, dataclasses, itertools, functools, collections, json, datetime, subprocess, sqlite3, secrets.
  • collections earns its keep: Counter, defaultdict, deque for an O(1) queue.
  • pathlib over os.path — path / "sub" / "file.txt" reads better and handles platforms for you.
  • A dependency is a permanent cost. Ten lines you own beat a package you must patch, audit and upgrade forever.
  • Check when a package was last released before adopting it. Python has a long tail of dead but well-ranked libraries.
L2 · Intermediate

Know the default and why it won

  • FastAPI + pydantic + SQLAlchemy + pytest is the modern service stack; Django is the other coherent answer, and mixing the halves of the two is the usual mistake.
  • Async is all-or-nothing per call path. One synchronous database driver inside an async handler blocks the whole event loop — see the earlier asyncio topic.
  • Set timeouts on every client — HTTP, database, cache. A default of “wait forever” is how one slow dependency takes down a whole fleet.
  • Pin the framework major version and read its migration guide before bumping. Pydantic v1→v2 was a genuine rewrite.
  • Prefer libraries that ship py.typed; untyped dependencies punch holes straight through your type checking.
L3 · Advanced

Evaluate before you adopt

  • Read the release notes and the issue tracker, not the landing page. Open-issue age and maintainer count predict your next two years better than benchmarks do.
  • Rust-backed cores (pydantic-core, ruff, polars, orjson) are the defining shift of the last few years: Python at the edges, native code where the loop is hot.
  • C extensions constrain you — wheels for your platform, ABI compatibility, and how the package behaves under free-threaded builds.
  • Wrap third-party clients behind your own thin interface at the boundaries you expect to churn. Not everywhere — only where you have a real reason to think the library will change.
  • Measure before adopting a “faster” library. orjson is genuinely quicker, and irrelevant if you spend 40 ms in the database and 0.4 ms in JSON.
Python · 00

The dependencies you did not choose

You pick six packages and install eighty-four. Every one of the other seventy-eight runs arbitrary code at install time and at import time, with your credentials in the environment. That is not paranoia, it is just what pip install does.

# the supply-chain job, in about six lines of CI
- run: uv sync --frozen                # fail if the lock is stale
- run: uv run pip-audit                # known CVEs in the whole tree
- run: uv run ruff check --select S    # shell=True, weak hashes, secrets
- run: uv run mypy .
- run: uv run pytest --cov --cov-fail-under=80

# and in the Dockerfile: resolve in one stage, run in a slim one
FROM python:3.13-slim AS runtime
COPY --from=build /app/.venv /app/.venv
USER 1000                              # never root
L1 · Beginner

Know what installing actually does

  • Installing runs code. A source distribution executes its build script; every package executes its __init__ on first import.
  • Check the name character by character. Typosquats live on PyPI on purpose — python-dateutil is real, plausible neighbours are not.
  • Never commit a secret, even in a test fixture; use .env files that are git-ignored, and a real secret manager in production.
  • Do not pip install as root in an image, and do not run the container as root either.
  • pip list --outdated once a month beats a two-year upgrade in one sitting.
L2 · Intermediate

Automate the boring three

  • pip-audit checks the resolved tree against the Python advisory database; run it in CI and on a schedule, since new CVEs land against code you have not touched.
  • Dependabot or Renovate for grouped, automatic upgrade PRs. Small and frequent, so the diff is readable.
  • Slim base images — python:3.13-slim over full, and be wary of alpine: musl means no manylinux wheels and long source builds.
  • Separate build and runtime stages so compilers never ship to production.
  • SBOM generation (CycloneDX) is increasingly a procurement requirement, and is one CI step.
L3 · Advanced

Reduce what you have to trust

  • Hash-pinned installs (--require-hashes, or a lockfile that stores digests) mean a compromised index cannot substitute an artefact for a version you already approved.
  • A private index with an allowlist removes dependency confusion — the attack where an internal package name is registered publicly at a higher version.
  • Trusted publishing via OIDC replaces long-lived PyPI tokens in CI; Sigstore attestations are the emerging provenance layer on top.
  • Count what you actually import. Dropping one convenience wrapper often removes a dozen transitive packages.
  • Vendoring is a legitimate answer for a small, stable, rarely-updated dependency — you trade upgrades for a tree you can read.
Python · 00

What “idiomatic” means in review

Idiomatic Python is not a style preference. Each of these rewrites removes a way for the code to be wrong — an index that can drift, a resource that can leak, an exception that can vanish. That is why reviewers keep asking for them.

The Zen, minus the poetry

import this prints nineteen lines. Three of them do real work in review. Explicit is better than implicit — pass the dependency, do not reach for a global. Flat is better than nested — guard clauses and early returns instead of an arrowhead of ifs. Errors should never pass silently — the one that except Exception: pass violates every time.

Idioms that have quietly expired

% and .format() → f-strings. os.path → pathlib. typing.List[int] → list[int], and Optional[X] → X | None. datetime.utcnow() → datetime.now(UTC), because the old one returned a naïve datetime that merely claimed to be UTC. setup.py → pyproject.toml. Ruff’s UP rules fix most of this for you.

L1 · Beginner

Let the language do the work

  • Iterate objects, not indices; enumerate when you genuinely need the position, zip when you have two sequences.
  • Comprehensions for transform-and-filter, a loop for anything with side effects. If it needs a comment to read, make it a loop.
  • Unpack: a, b = b, a, first, *rest = items.
  • f-strings for everything, including f"{value=}" for debugging, which prints the expression and its result.
  • t-strings (3.14+) — t"where id = {user_id}" builds a Template object instead of a string, so a library can escape or parameterise each interpolation before anything is joined. The answer to injection wherever an f-string would leave your program (SQL, HTML, shell).
  • Name things for what they are. data, result and temp tell the next reader nothing.
L2 · Intermediate

Structure the function itself

  • Guard clauses first. Handle the impossible cases and return, so the happy path is at one indent level and reads top to bottom.
  • Return one type. A function that returns a dict, or None, or raises, has three contracts and no callers who handle all of them.
  • Keyword-only arguments (* in the signature) for booleans and options — charge(amount, retry=True) reads; charge(amount, True) does not.
  • Small, pure core; thin, effectful shell. Push I/O to the edges and the middle becomes trivial to test.
  • Docstring the why. The what is in the signature and the types; the why is the only thing a reader cannot reconstruct.
L3 · Advanced

Know when to stop being clever

  • Metaclasses, __getattr__ magic and dynamic imports all work, and all defeat the type checker, the IDE and the next reader. The bar is high and it is rarely met.
  • Prefer composition and Protocol to deep inheritance; Python’s MRO is well defined and still nobody wants to reason about it at 3am.
  • Make illegal states unrepresentable — frozen dataclasses, enums instead of string flags, and a parsed type at the boundary rather than a validated dict passed onward.
  • Consistency beats personal preference. In an existing codebase, the local convention wins; change it deliberately and everywhere, or not at all.
  • Optimise for the reader who is on call. The next person to open this file will be tired, in a hurry and looking for one specific thing. Clever code charges them at exactly the worst moment.
