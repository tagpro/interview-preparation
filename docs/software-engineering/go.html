Part one

Go essentials

The language surface you need to read a diff without pausing. None of it is hard; all of it has one detail that turns into a bug when you assume it works like the last language you used.

Go deep · 01

Zero values, nil, and what is usable uninitialised

Every Go variable starts at its zero value, and the standard library is designed so that most zero values are already usable. The exception — maps — is the one that panics in production.

var (
	i  int            // 0
	s  string         // "" — a string is never nil
	p  *User          // nil
	m  map[string]int // nil: reads work, writes panic
	sl []int          // nil: len 0, and append still works
	ch chan int       // nil: send and receive block forever
	mu sync.Mutex     // ready to use — that is the whole point
)

fmt.Println(m["missing"])   // 0, no panic — reads of a nil map are fine
m["k"] = 1                  // panic: assignment to entry in nil map
sl = append(sl, 1)          // fine: append allocates on first use

// so this struct is usable with no constructor at all …
type Counter struct {
	mu sync.Mutex
	n  int
}
var c Counter; c.mu.Lock()  // … which is why NewCounter() often earns nothing
Go deep · 02

defer, panic, recover — exact semantics

defer looks like a finally block and behaves differently in three ways that matter: when its arguments are evaluated, when it runs, and what it can do to the return value.

// The loop trap and its fix.
for _, name := range files {
    f, err := os.Open(name)
    if err != nil { return err }
    defer f.Close()          // piles up: nothing closes until the function ends
    process(f)
}

for _, name := range files {
    if err := func() error { // give each iteration its own scope
        f, err := os.Open(name)
        if err != nil { return err }
        defer f.Close()      // runs at the end of THIS iteration
        return process(f)
    }(); err != nil { return err }
}
Go deep · 03

Strings, runes, bytes — and maps

A Go string is an immutable sequence of bytes, not characters. Indexing gives you a byte; ranging gives you a rune. Confusing the two is how emoji and accented names get corrupted.

s := "café"
len(s)                      // 5 — bytes, not characters
utf8.RuneCountInString(s)   // 4 — characters
s[3]                        // 195 — one byte, mid-rune, almost never useful

for i, r := range s {       // range over a string yields runes …
	fmt.Printf("%d %c\n", i, r)   // … and i is the BYTE offset: 0 1 2 3
}

b := []byte(s)              // a copy
r := []rune(s)              // a copy — 4 runes of 4 bytes each

// the only right way to build a string in a loop; += is quadratic
var sb strings.Builder
sb.Grow(len(parts) * 8)     // one allocation if you know the size
for _, p := range parts {
	sb.WriteString(p)
}
return sb.String()          // no copy: Builder hands over its buffer
Go deep · 04

Structs, embedding, and tags

Go has composition and no inheritance. Embedding promotes the inner type's methods onto the outer type, which looks like inheritance right up to the moment you try to override something.

type Audit struct {
	CreatedAt time.Time `json:"created_at"`
	CreatedBy string    `json:"created_by"`
}

type Order struct {
	Audit                            // embedded: o.CreatedAt works directly
	ID     uuid.UUID `json:"id"`
	Secret string    `json:"-"`      // never marshalled
	Note   string    `json:"note,omitempty"`
	Total  Money     `json:"total,string"`
}

var o Order
o.CreatedAt = time.Now()             // promoted field, not inheritance

// embedding promotes methods too — and a method on Order SHADOWS the
// embedded one rather than overriding it: Audit's own methods still call
// Audit's version. There is no virtual dispatch here.

// tags are just strings; the compiler does not check them. A typo in
// `json:"crated_at"` is a silent wrong field name at run time.
Part two

Values in memory

Go has no hidden references — assignment always copies the value. The catch is that some values contain pointers, so copying them shares what they point at. Knowing which is which prevents a whole class of bug.

Go deep · 05

A slice is three words over an array you cannot see

Pointer, length, capacity. Slicing makes a new header over the same array; append writes in place when capacity allows and reallocates when it does not. That conditional is where the bugs live.

// Looks harmless. Hands two callers a view of the same memory.
func (s *Store) Recent() []Item { return s.items[:10] }   // caller can append into s.items[10]

// Two safe alternatives, depending on intent.
func (s *Store) Recent() []Item { return s.items[0:10:10] }        // share reads, forbid in-place append
func (s *Store) Recent() []Item { return slices.Clone(s.items[:10]) } // hand over an independent copy
Go deep · 06

What copying actually copies

Assignment, arguments and channel sends all copy the value. For a struct that means a deep-ish copy of its fields; for a slice, map or channel it means copying a small header that points at shared state.

type Big struct{ Data [1024]int }        // an array, not a slice: 8 KB

func byValue(b Big)    { b.Data[0] = 1 } // copies 8 KB, mutates nothing
func byPointer(b *Big) { b.Data[0] = 1 } // copies 8 bytes, mutates the caller's

// the range-copy trap — the single most common Go bug in review
for _, o := range orders {
	o.Status = "sent"                    // o is a COPY; this is discarded
}
for i := range orders {
	orders[i].Status = "sent"            // this one actually writes
}

// method sets are the same rule wearing a different hat
func (o Order) Cancel()  { o.Status = "cancelled" }   // silently useless
func (o *Order) Cancel() { o.Status = "cancelled" }   // what you meant

// and a struct containing a sync.Mutex must never be copied at all —
// `go vet` will tell you: passes lock by value
Go deep · 07

Stack or heap: escape analysis

Go decides at compile time where a value lives. Stack allocation is nearly free and reclaimed on return; heap allocation costs a little now and GC work later. You do not control it directly — you control the shapes that force it.

// go build -gcflags='-m' ./...   prints every decision the compiler made

func stays() int {
	x := 42
	return x            // stack: freed by moving the stack pointer
}

func escapes() *int {
	x := 42
	return &x           // ./main.go:9:2: moved to heap: x
}

func alsoEscapes(w io.Writer) {
	buf := make([]byte, 64)
	w.Write(buf)        // escapes: it is passed to an interface method,
}                       // and the compiler cannot see the implementation

// the useful fix is usually reuse, not avoidance:
var bufs = sync.Pool{New: func() any { return new(bytes.Buffer) }}

b := bufs.Get().(*bytes.Buffer)
b.Reset()
defer bufs.Put(b)       // measure first — a pool can easily be slower
Part three

Concurrency in practice

Five patterns cover almost all production Go. What separates them from textbook examples is that each one has an owner, a bound, and an exit path.

Go deep · 08

The pattern catalogue

Worker pool, pipeline, fan-in, semaphore, single-flight. Recognising which one a diff is reaching for — and which one it should have reached for — is most of reviewing concurrent Go.

// Semaphore: 1,000 requests in flight, but only 5 touch the fragile API.
var sem = make(chan struct{}, 5)

func callVendor(ctx context.Context, id string) (*Quote, error) {
    select {
    case sem <- struct{}{}:            // acquire a token
        defer func() { <-sem }()      // release, always
    case <-ctx.Done():
        return nil, ctx.Err()         // give up rather than queue forever
    }
    return vendor.Quote(ctx, id)
}
// worker pool: N goroutines pull from one channel until it is closed
func workers(ctx context.Context, jobs <-chan Job, n int) <-chan Result {
    out := make(chan Result)
    var wg sync.WaitGroup
    wg.Add(n)
    for range n {
        go func() {
            defer wg.Done()
            for j := range jobs {          // ends when jobs is closed
                select {
                case out <- process(ctx, j):
                case <-ctx.Done():         // consumer gone — return, don't block forever
                    return
                }
            }
        }()
    }
    go func() { wg.Wait(); close(out) }()  // close out only after every worker is done
    return out
}

// pipeline + fan-in: each stage is its own goroutine, joined by unbuffered channels
// (in production every send below wants the same select-on-ctx.Done() as above)
func pipeline(ctx context.Context, ids <-chan string) <-chan Order {
    fetched := make(chan Raw)
    go func() { defer close(fetched); for id := range ids { fetched <- fetch(ctx, id) } }()

    parsed := make(chan Order)
    go func() { defer close(parsed); for r := range fetched { parsed <- parse(r) } }()
    return parsed                           // the caller ranges over this like any channel
}
// single-flight: 40 goroutines ask for the same key, the vendor sees ONE call
var g singleflight.Group   // golang.org/x/sync/singleflight

func GetQuote(ctx context.Context, id string) (*Quote, error) {
    v, err, shared := g.Do(id, func() (any, error) {
        return vendor.Quote(ctx, id)        // only the first caller actually runs this —
    })                                      // and with the FIRST caller's ctx: if that one
                                            // cancels, every waiter shares its error
    if shared {
        metrics.Inc("quote.dedup")          // the other 39 waited and got a copy of the same answer
    }
    if err != nil {
        return nil, err
    }
    return v.(*Quote), nil
}
Go deep · 09

Context is a tree, and cancellation flows down it

Every request builds a tree of contexts. A deadline is inherited and can only get tighter; a cancel signal propagates to every descendant at once. Getting this right is what makes a Go service shed work correctly under stress.

// ctx is the first parameter, always named ctx, never stored in a struct
func (s *Service) Get(ctx context.Context, id string) (Order, error) {
	ctx, cancel := context.WithTimeout(ctx, 2*time.Second)
	defer cancel()          // always — skipping it leaks the timer until it fires

	select {
	case <-ctx.Done():
		return Order{}, ctx.Err()     // Canceled or DeadlineExceeded
	case r := <-s.results:
		return r, nil
	}
}

// values are for request-scoped data only, with an unexported key type
type ctxKey struct{}                  // unexported: nobody else can collide

ctx = context.WithValue(ctx, ctxKey{}, reqID)
id, _ := ctx.Value(ctxKey{}).(string) // always comma-ok; it can be missing

// a deadline is inherited, never extended: a child can only be stricter
Go deep · 10

Mutex or channel: the actual decision

"Share memory by communicating" is good advice about ownership, not a rule about performance. The honest version: channels move ownership, mutexes protect state. Choose by which one you are doing.

SituationReach forWhy
Handing work to another goroutinechanTransfers ownership and creates the happens-before edge in one operation.
Protecting a shared map or countersync.Mutex / sync/atomicSimpler, faster, and no extra goroutine to own the state.
Waiting for several things to finishsync.WaitGroup or errgroupExpresses "all of them", and errgroup adds first-error plus cancellation.
One-time initialisationsync.OnceCorrect under concurrency and cheaper than a mutex on every read.
Read-mostly shared stateRWMutex, measuredOnly wins with genuinely long read sections; otherwise the extra bookkeeping loses to a plain Mutex.
Signalling "stop" to many goroutinescontext or a closed channelA closed channel broadcasts — every receiver unblocks at once.
Reusing short-lived bufferssync.PoolCuts allocation pressure on hot paths. Not a cache — entries vanish at GC.

The review smell

A goroutine whose only job is to own a variable and serve it over two channels is usually a mutex written the long way — more code, more allocation, one more thing to shut down. Conversely, a mutex held across a network call is a channel-shaped problem being solved with a lock, and it will serialise your whole service behind the slowest dependency.

// shared state that several goroutines read: a mutex is simply clearer
type Cache struct {
	mu sync.RWMutex                // RW: many readers, occasional writer
	m  map[string]Entry
}

func (c *Cache) Get(k string) (Entry, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()           // defer here costs ~1 ns and never leaks
	e, ok := c.m[k]
	return e, ok
}

// a channel is right when OWNERSHIP moves, not when state is shared
jobs := make(chan Job, 64)         // the buffer size IS the queue depth
for range 8 {                      // 1.22+: range over an int
	go func() {
		for j := range jobs {      // ends when the channel is closed
			handle(j)
		}
	}()
}
close(jobs)                        // the SENDER closes; a receiver never does
Part four

Interfaces and generics

Both let one piece of code work with many types. They do it at opposite ends of the compile/run boundary, which is exactly how you choose between them.

Go deep · 11

What an interface value costs

An interface value is two words: a pointer to a type descriptor with a method table, and a pointer to the data. Calling through it means an indirect jump the compiler usually cannot inline — and storing a value in one usually means an allocation.

// an interface value is two words: (type, value). Both must be nil to be nil.
type MyErr struct{}

func (e *MyErr) Error() string { return "boom" }

func bad() error {
	var e *MyErr        // nil *MyErr
	return e            // interface holds (*MyErr, nil) — NOT nil
}

func good() error {
	return nil          // interface holds (nil, nil) — nil
}

if bad() != nil  { /* fires — the classic typed-nil bug */ }
if good() != nil { /* does not fire */ }

// so a function that can fail returns a bare nil, never a typed nil pointer:
func find(id string) (*Order, error) {
	o, err := lookup(id)
	if err != nil {
		return nil, err          // literal nil, not a nil *Order variable
	}
	return o, nil
}
Go deep · 12

Generics: the syntax you will read

Type parameters arrived in Go 1.18 and the syntax is small: square brackets, a constraint per parameter, and inference at the call site so you rarely write the types out.

func Map[T, U any](in []T, f func(T) U) []U {
	out := make([]U, 0, len(in))     // pre-sized: one allocation
	for _, v := range in {
		out = append(out, f(v))
	}
	return out
}

// a constraint is an interface used as a type set. ~ means "underlying type",
// so a `type Celsius float64` satisfies it too.
type Number interface{ ~int | ~int64 | ~float64 }

func Sum[T Number](xs []T) T {
	var total T                      // the zero value of whatever T is
	for _, x := range xs {
		total += x
	}
	return total
}

ids := Map(orders, func(o Order) uuid.UUID { return o.ID })  // T, U inferred
n   := Sum([]float64{1.5, 2.5})                              // 4.0
Go deep · 13

Generics or interfaces

An interface asks "what can this value do?" and resolves it at run time. A type parameter asks "what type is this?" and resolves it at compile time. They answer different questions, so the choice is rarely close once you name the question.

// good: one algorithm, many element types, no interface{} and no reflection
func Keys[K comparable, V any](m map[K]V) []K

// bad: a type parameter where an ordinary interface says it better
func Handle[T Handler](h T)      // just take the Handler interface

// bad: generics to avoid writing two clear functions once
func Get[T any](url string) (T, error)   // the caller must now annotate T

// and most of what you were about to write already exists:
slices.Sort(xs)
slices.Contains(xs, x)
slices.SortFunc(orders, func(a, b Order) int {
	return cmp.Compare(a.Total, b.Total)     // -1, 0, +1
})
idx, found := slices.BinarySearch(sorted, target)
keys := slices.Collect(maps.Keys(m))         // 1.23+: an iterator, materialised
Part five

Errors that carry decisions

An error is only useful if someone can act on it. The design question is not "what message" but "what will the caller do differently" — and the answer connects straight back to the retry, breaker and DLQ machinery from Pillar A.

Go deep · 14

The taxonomy that drives behaviour

Four categories, four different reactions. If your error types do not let a caller tell these apart, every failure gets the same treatment — usually a retry, which is the wrong answer three times out of four.

// Wrap with context going up. Classify once, at the boundary that knows.
func (r *Repo) Get(ctx context.Context, id string) (*Order, error) {
    row := r.db.QueryRowContext(ctx, q, id)
    var o Order
    switch err := row.Scan(&o.ID, &o.Email, &o.Total); {
    case err == nil:
        return &o, nil
    case errors.Is(err, sql.ErrNoRows):
        return nil, &Error{Code: Terminal, Op: "repo.Get", Err: err}
    case errors.Is(err, context.DeadlineExceeded), isConnErr(err):
        return nil, &Error{Code: Transient, Op: "repo.Get", Err: err}
    default:
        return nil, fmt.Errorf("repo.Get %s: %w", id, err)   // unknown: don't guess
    }
}

// errors.Join reports several independent failures without picking a winner.
func (c *Config) Validate() error {
    var errs []error
    if c.Port == 0 { errs = append(errs, errors.New("port is required")) }
    if c.DSN == "" { errs = append(errs, errors.New("dsn is required")) }
    return errors.Join(errs...)   // nil when the slice is empty
}
// the four categories, made machine-readable -- Invalid was missing above
type Code int

const (
    Transient Code = iota   // timeout, 503, connection reset -- retry, if idempotent
    Terminal                // not found, forbidden -- fail fast, retrying is pure load
    Invalid                 // bad input -- a 4xx and a message, never an alert
)

func (r *Repo) validate(id string) error {
    if id == "" {
        return &Error{Code: Invalid, Op: "repo.Get", Err: errors.New("id is required")}
    }
    return nil
}
// the fourth category is not a Code at all -- a bug is not a value to return, it is a panic
func (s *Server) handle(w http.ResponseWriter, r *http.Request) {
    defer func() {
        if v := recover(); v != nil {
            log.Error("panic recovered", "route", r.URL.Path, "panic", v, "stack", string(debug.Stack()))
            http.Error(w, "internal error", http.StatusInternalServerError)
            metrics.Inc("panics")   // page someone -- this is a bug, not a retryable condition
        }
    }()
    s.routeFor(r)(w, r)
}
Part six

The service toolkit

What a Go service is actually built from. Go's answer to most framework features is a standard library package, which is why Go services have short dependency lists and why knowing the stdlib matters more here than elsewhere.

Go deep · 15

database/sql is a pool, not a connection

One *sql.DB is a connection pool with four knobs, and those knobs are the join between your Go process and the database limits from the cloud page. Getting them wrong is the most common cause of "the database is slow" that turns out not to be the database.

db, err := sql.Open("pgx", dsn)   // does not connect yet — Ping() does
db.SetMaxOpenConns(20)
db.SetMaxIdleConns(20)            // match, or you churn connections
db.SetConnMaxLifetime(30 * time.Minute)

// Always the ...Context variants, always close rows, always check rows.Err().
rows, err := db.QueryContext(ctx, `SELECT id, note FROM orders WHERE tenant = $1`, id)
if err != nil { return nil, err }
defer rows.Close()                // otherwise the connection never returns to the pool

for rows.Next() {
    var o Order
    var note sql.NullString       // a nullable column is not a plain string
    if err := rows.Scan(&o.ID, &note); err != nil { return nil, err }
    o.Note = note.String
    out = append(out, o)
}
return out, rows.Err()            // the loop can end because of an error, not just the data

The three-line bug

A missing defer rows.Close() leaks a connection per call. It does not fail immediately — it fails minutes later, everywhere at once, when the pool is exhausted and every handler is blocked waiting for a slot. If you take one habit from this section, make it that line.

Go deep · 17

Time, timers, and the two clocks

A time.Time carries a wall clock and a monotonic reading. Using the wrong one, or leaking a timer in a loop, produces bugs that only appear under load or when NTP adjusts the clock.

// measuring: monotonic, and immune to NTP steps and DST
start := time.Now()
defer func() { metrics.Observe(time.Since(start)) }()

// wall-clock arithmetic: a different thing entirely
t := time.Now().UTC()        // store and compare in UTC, always
t.Add(24 * time.Hour)        // exactly 24h — NOT "tomorrow" across a DST change
t.AddDate(0, 0, 1)           // calendar-aware "tomorrow"

// durations are a type, so the units are checked at compile time
timeout := 500 * time.Millisecond   // not the integer 500

// a ticker holds a runtime timer until you stop it
tk := time.NewTicker(time.Second)
defer tk.Stop()

// t1 == t2 compares the monotonic reading too; use Equal for wall clocks
t1.Equal(t2)                 // and t.Round(0) strips the monotonic part

Part seven

The service around the code

Two pieces of a Go service are almost always under-specified in review, and both are pure configuration: the timeouts on the HTTP server, and what the process does between SIGTERM and exit.

Go deep · 19

Five timeouts on one connection

A default http.Server has no timeouts at all. Each of the five below guards a different phase, and a slow client only needs one of them missing to hold a connection — and a goroutine — indefinitely.

srv := &http.Server{
	Addr:              ":8080",
	Handler:           mux,
	ReadHeaderTimeout: 5 * time.Second,   // header trickle — the Slowloris one
	ReadTimeout:       15 * time.Second,  // headers + body
	WriteTimeout:      30 * time.Second,  // end of headers → end of response
	IdleTimeout:       60 * time.Second,  // keep-alive between requests
	MaxHeaderBytes:    1 << 20,
}

// one route legitimately needs longer than the rest — but WriteTimeout above
// still cuts the connection at 30s, so a route allowed 60s needs the server's
// WriteTimeout raised past it (or a dedicated server for slow routes):
mux.Handle("/report", http.TimeoutHandler(reportHandler, 60*time.Second, "timed out"))

// none of the above reaches your database call. Only this does:
func handler(w http.ResponseWriter, r *http.Request) {
	ctx, cancel := context.WithTimeout(r.Context(), 3*time.Second)
	defer cancel()
	rows, err := db.QueryContext(ctx, q)   // cancelled when the client hangs up
	// …
}
Go deep · 20

Shutdown, in the right order

A deploy replaces every pod. Whether that is invisible or drops a slice of requests comes down to a sequence of about fifteen lines, and to pausing before you stop accepting.

func main() {
    srv := &http.Server{Addr: ":8080", Handler: h,
        ReadHeaderTimeout: 5 * time.Second, IdleTimeout: 60 * time.Second}

    go func() { _ = srv.ListenAndServe() }()

    ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGTERM, os.Interrupt)
    defer stop()
    <-ctx.Done()

    ready.Store(false)              // 1. readiness probe starts failing
    time.Sleep(5 * time.Second)     // 2. let endpoints propagate

    sdCtx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
    defer cancel()
    _ = srv.Shutdown(sdCtx)         // 3. drain in-flight requests
    workers.Stop()                  // 4. cancel context, wg.Wait(), flush
}
Part eight

Five things you will actually be asked to write

Everything up to here was mechanism. This part is the code — five ordinary backend jobs written the way a Go reviewer would want them, with the reasoning attached. The L2 column of each says why it is written that way rather than the shorter way.

Go deep · 21

A service main(), start to finish

The job: wire up a service so it fails loudly at start-up and quietly on the way down. The shape is always the same — main does nothing but call run and exit, because a function that returns an error is testable and a function that calls os.Exit is not.

func main() {
	if err := run(context.Background()); err != nil {
		slog.Error("fatal", "err", err)
		os.Exit(1)                      // the only Exit in the programme
	}
}

func run(ctx context.Context) error {
	cfg, err := config.Load()               // fails now, not at 3am
	if err != nil {
		return fmt.Errorf("config: %w", err)
	}
	ctx, stop := signal.NotifyContext(ctx, syscall.SIGINT, syscall.SIGTERM)
	defer stop()

	db, err := sql.Open("pgx", cfg.DatabaseURL)
	if err != nil {
		return fmt.Errorf("open db: %w", err)
	}
	defer db.Close()
	db.SetMaxOpenConns(cfg.DBMaxConns)      // default is unlimited
	db.SetConnMaxLifetime(30 * time.Minute) // survives a failover
	if err := db.PingContext(ctx); err != nil {
		return fmt.Errorf("ping db: %w", err)
	}
	srv := &http.Server{
		Addr:              cfg.Addr,
		Handler:           routes(db),
		ReadHeaderTimeout: 5 * time.Second,   // the anti-Slowloris one
		ReadTimeout:       15 * time.Second,
		WriteTimeout:      30 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	errc := make(chan error, 1)               // buffered: the goroutine never blocks
	go func() { errc <- srv.ListenAndServe() }()

	select {
	case err := <-errc:
		return fmt.Errorf("serve: %w", err)   // could not bind, or a real failure
	case <-ctx.Done():
		slog.Info("signal received, draining")
	}

	grace, cancel := context.WithTimeout(context.Background(), 25*time.Second)
	defer cancel()                            // NOT ctx — that one is cancelled
	return srv.Shutdown(grace)
}
L1 · Beginner

What the code does

  • run returns error; main prints it and exits. Everything else is ordinary code.
  • signal.NotifyContext gives you a context that is cancelled when SIGTERM arrives — no channel plumbing needed.
  • defer db.Close() immediately after a successful open, so there is no path that forgets it.
  • %w wraps: the caller can still match the underlying error with errors.Is.
  • ListenAndServe blocks, so it goes in a goroutine and reports back on a channel.
L2 · Intermediate

Why it is written this way

  • log.Fatal skips every defer. It is os.Exit with a print — connections stay open, buffers stay unflushed, and the function cannot be tested.
  • The shutdown context is a fresh one. Deriving it from the cancelled ctx makes Shutdown return instantly and kills in-flight requests, which is the exact bug this code is avoiding.
  • errc is buffered with capacity one so the serving goroutine can send and exit even after select has already taken the shutdown branch. Unbuffered, it leaks.
  • ReadHeaderTimeout is the one that matters for an exposed service; without it a client can hold a connection open with a slow trickle of header bytes.
  • SetMaxOpenConns defaults to unlimited, which means one traffic spike can exhaust the database’s own connection limit.
L3 · Advanced

What bites in production

  • Shutdown does not touch hijacked or long-lived connections — WebSockets and SSE streams need their own cancellation, usually a context stored per connection.
  • Readiness must flip before the drain starts. Fail the readiness probe, wait one probe interval so the load balancer stops sending traffic, and only then call Shutdown.
  • defer stop() restores default signal handling; a second SIGTERM after that kills the process immediately, which is usually what an impatient operator wants.
  • Background workers need the same treatment. Give them the same ctx and wait for them with an errgroup, or the process exits with work half-done.
  • sql.Open does not connect. Without the explicit PingContext, a bad password becomes a run-time error on the first request rather than a start-up failure.

Bounded fan-out with errgroup

The job: call a service once per item for a few hundred items. Unbounded goroutines are cheap for you and expensive for whoever you are calling — and errgroup gives you the bound, the error and the cancellation in one type.

func enrichAll(ctx context.Context, ids []string) (map[string]Result, error) {
	g, ctx := errgroup.WithContext(ctx)   // shadowing ctx is idiomatic here
	g.SetLimit(20)                        // at most 20 in flight, ever

	var mu sync.Mutex
	out := make(map[string]Result, len(ids))

	for _, id := range ids {              // Go 1.22+: id is per-iteration
		g.Go(func() error {
			r, err := enrich(ctx, id)     // the cancellable ctx, not the outer one
			if err != nil {
				return fmt.Errorf("enrich %s: %w", id, err)
			}
			mu.Lock()
			defer mu.Unlock()
			out[id] = r
			return nil
		})
	}
	return out, g.Wait()                  // blocks until every goroutine is done
}
// when a partial answer is the right answer, collect instead of cancelling:
	var (
		mu   sync.Mutex
		errs []error
	)
	g := new(errgroup.Group)              // no WithContext — no sibling cancellation
	g.SetLimit(20)
	for _, id := range ids {
		g.Go(func() error {
			r, err := enrich(ctx, id)
			mu.Lock()
			defer mu.Unlock()
			if err != nil {
				errs = append(errs, fmt.Errorf("%s: %w", id, err))
				return nil                // nil: do not stop the others
			}
			out[id] = r
			return nil
		})
	}
	_ = g.Wait()
	return out, errors.Join(errs...)      // one error holding all of them
L1 · Beginner

What the code does

  • errgroup.WithContext returns a group and a derived context that the group cancels as soon as any goroutine returns a non-nil error.
  • g.Go(fn) starts a goroutine; g.Wait() blocks until they have all finished and returns the first error.
  • SetLimit(n) makes g.Go itself block once n are running — the backpressure is at the submission point.
  • A mutex around the map because concurrent map writes are a run-time crash in Go, not a race you get away with.
  • errors.Join combines several errors into one that errors.Is can still search.
L2 · Intermediate

Why it is written this way

  • Pass the group’s ctx to the work, not the original. Using the outer context means the cancellation you carefully set up reaches nobody.
  • Two shapes, chosen deliberately: WithContext for “all of it or none”, a bare Group plus errors.Join for “do as much as you can and tell me what failed”.
  • Pre-size the map with make(..., len(ids)) so it does not rehash while twenty goroutines contend for the lock.
  • Wrap with the id. enrich 8fa3: context deadline exceeded is actionable; context deadline exceeded alone is not.
  • The loop-variable capture bug is gone in Go 1.22+ — but on an older module version this exact code silently enriches the last id n times.
L3 · Advanced

What bites in production

  • SetLimit after Go panics, and a limit of zero deadlocks immediately. Set it once, before the loop.
  • Cancellation does not unblock everything. A CPU-bound loop, a call without a context, or a sync.Mutex wait ignores it entirely — Wait then hangs for as long as that call does.
  • The first error wins, the rest are dropped. If several failures are diagnostically different, collect them; the default hides everything after the first.
  • A panic in a g.Go goroutine takes down the process — errgroup does not recover for you. Recover at the top of the closure if the work is untrusted.
  • Bound by the downstream’s capacity divided by your replica count. A limit of 20 on 30 pods is 600 concurrent calls arriving at one service.

An outbound call that cannot hang

The job: call an internal API safely. Go gives you five separate deadlines and two easy ways to leak a connection — and the default http.Client, which has no timeout at all, is the one thing you must never use.

// one client for the process; it is safe for concurrent use by design
var client = &http.Client{
	Timeout: 5 * time.Second,                 // dial + TLS + headers + body
	Transport: &http.Transport{
		DialContext:           (&net.Dialer{Timeout: time.Second}).DialContext,
		TLSHandshakeTimeout:   time.Second,
		ResponseHeaderTimeout: 2 * time.Second,
		MaxIdleConnsPerHost:   32,            // default is 2 — the silent bottleneck
		IdleConnTimeout:       90 * time.Second,
	},
}

var (
	ErrRetryable = errors.New("upstream unavailable")
	ErrRejected  = errors.New("upstream rejected the request")
)
func postEntry(ctx context.Context, e Entry, idem string) (Ref, error) {
	body, err := json.Marshal(e)
	if err != nil {
		return Ref{}, fmt.Errorf("marshal entry: %w", err)
	}
	req, err := http.NewRequestWithContext(ctx, http.MethodPost,
		baseURL+"/entries", bytes.NewReader(body))
	if err != nil {
		return Ref{}, fmt.Errorf("build request: %w", err)
	}
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("Idempotency-Key", idem)   // same key on every retry

	resp, err := client.Do(req)
	if err != nil {
		return Ref{}, fmt.Errorf("post entry: %w", err)  // wraps ctx deadlines
	}
	defer func() {
		_, _ = io.Copy(io.Discard, resp.Body) // drain, then close, in that order
		_ = resp.Body.Close()
	}()

	switch {
	case resp.StatusCode >= 500:
		return Ref{}, fmt.Errorf("ledger %d: %w", resp.StatusCode, ErrRetryable)
	case resp.StatusCode >= 400:
		return Ref{}, fmt.Errorf("ledger %d: %w", resp.StatusCode, ErrRejected)
	}

	var ref Ref
	if err := json.NewDecoder(resp.Body).Decode(&ref); err != nil {
		return Ref{}, fmt.Errorf("decode ref: %w", err)
	}
	return ref, nil
}
L1 · Beginner

What the code does

  • One package-level client, reused. It holds the connection pool; a new one per call throws that pool away.
  • NewRequestWithContext, never http.Post — the context is how a cancelled request actually stops.
  • defer drain-then-close on the body, immediately after checking err.
  • Sentinel errors wrapped with %w so the caller writes errors.Is(err, ErrRetryable) instead of re-parsing a status code.
  • A non-2xx is not an err from Do. You have to check StatusCode yourself.
L2 · Intermediate

Why it is written this way

  • Timeouts are layered on purpose. client.Timeout is the backstop; the transport’s three let you fail fast on a dead host while still allowing a slow response.
  • The context deadline beats them all, because it also propagates: the callee learns how long the caller is still willing to wait.
  • MaxIdleConnsPerHost defaults to 2. On a service that talks mostly to one host, that is the single most common cause of unexplained latency.
  • Retryable versus rejected is decided here, at the boundary, not by every caller inspecting numbers.
  • Wrapping preserves context.DeadlineExceeded, so a timeout is still matchable several layers up.
L3 · Advanced

What bites in production

  • A leaked body leaks a goroutine and a socket. It shows up as a slow climb in goroutine count — pprof will point straight at net/http.
  • Draining a huge body is worse than dropping it. Cap it: io.CopyN(io.Discard, resp.Body, 64<<10), then close.
  • Retrying is only safe with a body you can rewind. A bytes.Reader can be re-read; an io.Pipe or a file stream cannot, so build the request inside the retry loop.
  • client.Timeout cannot be overridden per request — that is exactly what the request context is for.
  • Sharing a Transport across clients is good; creating a Transport per request is a connection-pool leak with a slow, confusing failure mode.

A repository over database/sql

The job: write two rows in one transaction and read one back. The interesting parts are the exits — a deferred rollback that is a no-op after a successful commit, and sql.ErrNoRows, which is the standard library asking you to decide what “missing” means in your domain.

func (r *Repo) Place(ctx context.Context, o Order) (uuid.UUID, error) {
	tx, err := r.db.BeginTx(ctx, &sql.TxOptions{Isolation: sql.LevelReadCommitted})
	if err != nil {
		return uuid.Nil, fmt.Errorf("begin: %w", err)
	}
	defer tx.Rollback() //nolint:errcheck // no-op once Commit has run

	var id uuid.UUID
	err = tx.QueryRowContext(ctx,
		`INSERT INTO orders (email, total) VALUES ($1, $2) RETURNING id`,
		o.Email, o.Total,
	).Scan(&id)
	if err != nil {
		return uuid.Nil, fmt.Errorf("insert order: %w", err)
	}

	// one INSERT per item is one network round trip per item — fine for small
	// baskets; batch with a multi-row VALUES or pgx.CopyFrom when they grow
	for _, it := range o.Items {
		if _, err := tx.ExecContext(ctx,
			`INSERT INTO items (order_id, sku, qty) VALUES ($1, $2, $3)`,
			id, it.SKU, it.Qty,
		); err != nil {
			return uuid.Nil, fmt.Errorf("insert item %s: %w", it.SKU, err)
		}
	}
	return id, tx.Commit()
}
func (r *Repo) Get(ctx context.Context, id uuid.UUID) (Order, error) {
	var o Order
	err := r.db.QueryRowContext(ctx,
		`SELECT id, email, total FROM orders WHERE id = $1`, id,
	).Scan(&o.ID, &o.Email, &o.Total)

	switch {
	case errors.Is(err, sql.ErrNoRows):
		return Order{}, ErrNotFound       // a domain error, not a driver one
	case err != nil:
		return Order{}, fmt.Errorf("get order %s: %w", id, err)
	}
	return o, nil
}

// rows.Err() is not optional — a Rows loop that ends early because the
// connection dropped looks exactly like one that ran out of rows:
	for rows.Next() { /* … */ }
	if err := rows.Err(); err != nil {
		return nil, fmt.Errorf("iterate items: %w", err)
	}
L1 · Beginner

What the code does

  • Every call takes a ctx — QueryContext, ExecContext, BeginTx. The non-context versions exist only for compatibility.
  • Placeholders, always. $1 on Postgres, ? on MySQL — never string concatenation, which is how injection happens.
  • QueryRow(...).Scan(&x) is the one-row shape; it defers the error until Scan.
  • RETURNING id gets the generated key back in the same round trip.
  • sql.ErrNoRows is a normal outcome of a lookup, not a failure of the database.
L2 · Intermediate

Why it is written this way

  • The deferred rollback is written on the line after BeginTx, so no future early return can escape it.
  • Translate ErrNoRows at the repository boundary. The layer above should not import database/sql to know a thing was missing.
  • rows.Err() after every rows.Next() loop — and defer rows.Close(), or the connection never returns to the pool.
  • Wrap with identifying detail: which order, which SKU. The stack trace is not in the error, so the context has to be.
  • Keep transactions short and free of network calls. Every millisecond inside BeginTx is a millisecond of held locks.
L3 · Advanced

What bites in production

  • A Tx pins one connection for its whole life. Long transactions plus a small pool is a deadlock waiting for traffic.
  • Retry on serialisation failure if you use LevelSerializable: Postgres returns 40001 and expects the application to try again, which means the whole function must be safe to re-run.
  • Prepared statements are per-connection. db.Prepare re-prepares on whichever connection it lands on; under a pool that is rarely the win people expect.
  • context cancellation mid-transaction leaves the driver to roll back asynchronously — the row locks can outlive your handler by a moment.
  • SetConnMaxLifetime matters behind a proxy or a failover. Without it, connections pinned to a demoted primary survive the failover and keep failing.

Table-driven tests, fakes and httptest

The job: test the three things above without a network. Go’s answer is unusually consistent — a map of cases, a subtest per case, an interface for the seam, and a real HTTP server when the thing under test is the HTTP client itself.

func TestPlace(t *testing.T) {
	t.Parallel()

	tests := map[string]struct {
		order   Order
		ledger  fakeLedger        // the seam: an interface, not a mock library
		wantErr error
	}{
		"happy path":     {order: valid, ledger: fakeLedger{ref: "led_1"}},
		"ledger down":    {order: valid, ledger: fakeLedger{err: ErrRetryable}, wantErr: ErrRetryable},
		"ledger rejects": {order: valid, ledger: fakeLedger{err: ErrRejected}, wantErr: ErrRejected},
		"empty basket":   {order: Order{}, wantErr: ErrInvalid},
	}

	for name, tc := range tests {
		t.Run(name, func(t *testing.T) {
			t.Parallel()
			_, err := Place(t.Context(), tc.ledger, tc.order)   // 1.24+: t.Context()
			if !errors.Is(err, tc.wantErr) {
				t.Fatalf("Place() error = %v, want %v", err, tc.wantErr)
			}
		})
	}
}

func TestPostEntry(t *testing.T) {
	srv := httptest.NewServer(http.HandlerFunc(
		func(w http.ResponseWriter, r *http.Request) {
			if got := r.Header.Get("Idempotency-Key"); got == "" {
				t.Errorf("missing idempotency key")   // Errorf: this is the server goroutine
			}
			w.Header().Set("Content-Type", "application/json")
			w.WriteHeader(http.StatusCreated)
			_, _ = io.WriteString(w, `{"ref":"led_123"}`)
		}))
	t.Cleanup(srv.Close)

	ref, err := postEntry(t.Context(), Entry{Amount: 100}, "idem-1")
	if err != nil {
		t.Fatalf("postEntry() = %v", err)
	}
	if ref.ID != "led_123" {
		t.Errorf("ref.ID = %q, want led_123", ref.ID)   // got, want — in that order
	}
}
L1 · Beginner

What the code does

  • A map from case name to inputs and expectations, then one t.Run per entry — the standard Go test shape.
  • t.Fatalf stops this subtest; t.Errorf records a failure and continues. Use Fatal when the rest of the test cannot run.
  • errors.Is, not ==, because the error you get back is wrapped.
  • httptest.NewServer starts a real HTTP server on a random port and hands you its URL.
  • No assertion library needed — if got != want { t.Errorf(...) } is the convention.
L2 · Intermediate

Why it is written this way

  • A map, not a slice, so cases are named, unordered, and impossible to reference by index.
  • t.Parallel() twice — once for the parent, once inside each subtest. Only then do the cases actually overlap.
  • The fake is a struct implementing your own interface. Go’s implicit interfaces make a five-line fake cheaper than any mocking framework.
  • t.Cleanup over defer in helpers: it runs at the end of the test even when registered several frames down.
  • Message order is got, want. Every Go codebase reads it that way, and reversing it costs a reader real time.
L3 · Advanced

What bites in production

  • t.Fatal from a non-test goroutine does nothing useful — it stops that goroutine, not the test. Inside an httptest handler, always t.Errorf.
  • Run the suite with -race in CI. The detector only reports races it actually observes, so parallel subtests make it meaningfully more likely to see one.
  • Interfaces belong to the consumer. Define the narrow one you need where you use it, not next to the implementation — that is what keeps fakes small.
  • testing/synctest (1.25) fakes time for concurrent code, so a test of a one-minute backoff no longer takes a minute.
  • Golden files plus -update for large outputs, and testcontainers or dockertest when only a real database will do — behind testing.Short() so the fast suite stays fast.

-race is the single highest-value flag in the language, and it is off by default

The race detector instruments every memory access and reports the two goroutines, with stacks, the moment one writes what another reads without synchronisation. It costs perhaps five times the CPU and ten times the memory, which is why it is not on in production — and it is why go test -race belongs in CI on every package, every run. A data race in Go is not a hypothetical: an unsynchronised map write is a runtime crash that takes the whole process down, and it will happen for the first time under load, in production, in the middle of the night. The detector only reports races it actually observes, so it is exactly as good as your test coverage of concurrent paths — which is one more reason the idempotency test later in this part starts sixteen goroutines rather than two.

	var errs []error

		Addr:        optional("SHORTLINK_ADDR", ":8080"),
		DatabaseURL: required(&errs, "DATABASE_URL"),
		RedisURL:    required(&errs, "REDIS_URL"),
		CodeLength:  integer(&errs, "SHORTLINK_CODE_LENGTH", 7),
		DefaultTTL:  duration(&errs, "SHORTLINK_DEFAULT_TTL", 90*24*time.Hour),
		RateLimit:   integer(&errs, "SHORTLINK_RATE_LIMIT", 60),
		RateWindow:  duration(&errs, "SHORTLINK_RATE_WINDOW", time.Minute),
	}

	if raw := required(&errs, "SHORTLINK_PUBLIC_BASE_URL"); raw != "" {
		u, err := url.Parse(raw)
		switch {
		case err != nil:
			errs = append(errs, fmt.Errorf("SHORTLINK_PUBLIC_BASE_URL: %w", err))
		case u.Scheme == "" || u.Host == "":
			errs = append(errs, errors.New("SHORTLINK_PUBLIC_BASE_URL: want an absolute URL"))
		default:
			cfg.PublicBaseURL = u
		}
	}
	if cfg.CodeLength < 4 || cfg.CodeLength > 32 {
		errs = append(errs, fmt.Errorf("SHORTLINK_CODE_LENGTH: want 4..32, got %d", cfg.CodeLength))
	}

	// One error listing every problem, not the first one. A deploy that fails
	// four times because four variables are missing is four deploys; this is
	// one, and the log line names all four.
	return cfg, errors.Join(errs...)
}

func optional(key, fallback string) string {
	if v := os.Getenv(key); v != "" {
		return v
	}
	return fallback
}

func required(errs *[]error, key string) string {
	v := os.Getenv(key)
	if v == "" {
		*errs = append(*errs, fmt.Errorf("%s is required", key))
	}
	return v
}

	raw := os.Getenv(key)
	if raw == "" {
		return fallback
	}
	n, err := strconv.Atoi(raw)
	if err != nil {
		*errs = append(*errs, fmt.Errorf("%s: %w", key, err))

The core, which imports only the standard library

This package knows nothing about HTTP, SQL or Redis, which is why its tests run in milliseconds and why the rules survive the day somebody swaps the database. It is also where Go differs most honestly from the other two languages in this series: Go cannot make an invalid value unconstructable, so the discipline is one parse function at the edge, a re-check in the domain, and a constraint in the database.

// internal/shortlink/link.go
package shortlink

import (
	"fmt"
	"net/url"
	"regexp"
	"strings"
	"time"
)

// Code is the code in the short URL. A named string type, not a bare
// string: it costs nothing at run time and it means the compiler rejects
// ParseCode(ownerID) even though both are strings underneath.
//
// Be honest about the limit. Code("") and Code("NOT A CODE") both compile,
// because a conversion between a named type and its underlying type is
// always legal in Go. There is no equivalent of a private constructor. So
// the invariant is held by convention -- ParseCode is the only way values
// enter -- backed by a re-check wherever it matters and a unique, checked
// column in Postgres. That is weaker than a Java record and it is worth
// knowing that it is weaker.
type Code string

func (c Code) String() string { return string(c) }

var codeShape = regexp.MustCompile(`^[a-z0-9]{4,32}$`)

func ParseCode(raw string) (Code, error) {
	c := strings.ToLower(strings.TrimSpace(raw))
	if !codeShape.MatchString(c) {
		return "", fmt.Errorf("%w: %q is not a short code", ErrInvalid, raw)
	}
	return Code(c), nil
}

// Link is the thing itself. No struct tags: this type is not the wire
// format and it is not the table either, and the day somebody adds
// `json:"..."` here is the day the API and the schema became the same
// object and can no longer change independently.
type Link struct {
	Code      Code
	Target    *url.URL
	OwnerID   string
	CreatedAt time.Time
	ExpiresAt time.Time
}

func (l Link) Expired(now time.Time) bool {
	return !l.ExpiresAt.IsZero() && !now.Before(l.ExpiresAt)
}

const maxTargetLen = 2048

// ParseTarget is a security control wearing the clothes of a format check.
// url.Parse is deliberately permissive: it will parse "javascript:alert(1)"
// without complaint and hand you a URL whose Scheme is "javascript". If you
// then put that in a Location header, you have built an XSS vector on your
// own domain and handed out short links to it.
func ParseTarget(raw string) (*url.URL, error) {
	raw = strings.TrimSpace(raw)
	switch {
	case raw == "":
		return nil, fmt.Errorf("%w: url is required", ErrInvalid)
	case len(raw) > maxTargetLen:
		return nil, fmt.Errorf("%w: url longer than %d bytes", ErrInvalid, maxTargetLen)
	}

	u, err := url.Parse(raw)
	if err != nil {
		return nil, fmt.Errorf("%w: %s", ErrInvalid, err)
	}
	switch strings.ToLower(u.Scheme) {
	case "http", "https":
	default:
		return nil, fmt.Errorf("%w: only http and https can be shortened", ErrInvalid)
	}
	if u.Host == "" {
		return nil, fmt.Errorf("%w: url has no host", ErrInvalid)
	}
	if u.User != nil {
		// http://user:pass@host is a credential in a database column.
		return nil, fmt.Errorf("%w: credentials in a url are not stored", ErrInvalid)
	}
	return u, nil
}

package shortlink

import (
	"crypto/rand"
	"fmt"
)

// Thirty-two characters, not thirty-six: 0/o, 1/l and their friends are
// gone so a code read off a slide or down a phone survives the trip.
//
// Thirty-two is also a power of two, and that is not a coincidence. Folding
// a random byte into an alphabet with `b % len(alphabet)` is only uniform
// when the length divides 256. With 36 characters the first four would come
// up about 12% more often than the rest -- a bias that is invisible in
// testing, real in aggregate, and entirely avoidable by choosing 32.
const alphabet = "23456789abcdefghijkmnpqrstuvwxyz"

func NewCode(n int) (Code, error) {
	b := make([]byte, n)
	if _, err := rand.Read(b); err != nil {   // crypto/rand, never math/rand
		return "", fmt.Errorf("read random bytes: %w", err)
	}
	for i := range b {
		b[i] = alphabet[int(b[i])%len(alphabet)]
	}
	return Code(b), nil
}

// math/rand would be a real vulnerability rather than a style mistake: its
// output is predictable from a handful of observations, so anybody who
// created three links could enumerate everybody else's. Recent Go has
// crypto/rand.Text() for the case where you do not care which alphabet you
// get, which is most cases -- this one cares, so it does the fold itself.
//
// 32^7 is about 34 billion codes. With ten million links already stored, a
// fresh code collides roughly once in 3,400 inserts. Rare, but not never,
// and "rare" is the failure mode that reaches production untested. The

Validating the host is not the same as blocking a private address

It is tempting to add a check here that refuses 127.0.0.1, 10.0.0.0/8 and 169.254.169.254, and for a service that ever fetches the target — to unfurl a preview, to check the link is alive — you must, or your shortener is a proxy into your own VPC with the cloud metadata endpoint one request away. // One pool for the process, and it is the real concurrency limit of this
// service. Goroutines are free; Postgres connections are not, and a
// thousand goroutines behind a pool of ten means nine hundred and ninety
// of them are waiting -- which is the correct design, because a database
// has a ceiling and a pool is how you respect it rather than discover it.
func NewPool(ctx context.Context, dsn string) (*pgxpool.Pool, error) {
	cfg, err := pgxpool.ParseConfig(dsn)
	if err != nil {
		return nil, fmt.Errorf("parse dsn: %w", err)
	}

	cfg.MaxConns = 10
	cfg.MinConns = 2                          // survive a burst without a handshake
	cfg.MaxConnLifetime = 25 * time.Minute    // under any proxy's idle timeout
	cfg.MaxConnIdleTime = 5 * time.Minute
	cfg.HealthCheckPeriod = 30 * time.Second

	pool, err := pgxpool.NewWithConfig(ctx, cfg)
	if err != nil {
		return nil, fmt.Errorf("create pool: %w", err)
	}

	// Fail the start-up, not the first request. A service that comes up
	// green and then 500s for ninety seconds while DNS settles is a
	// service whose readiness probe is lying.
	pingCtx, cancel := context.WithTimeout(ctx, 5*time.Second)
	defer cancel()
	if err := pool.Ping(pingCtx); err != nil {
		pool.Close()
		return nil, fmt.Errorf("ping: %w", err)
	}
	return pool, nil
}

The store, and the race you cannot check for

Two requests arrive in the same millisecond with the same Idempotency-Key. Both look for an existing link, both find none, both insert. Reading before writing does not fix that and no amount of application code can, because the gap between the read and the write is where the other request lives. The database closes it. What Go contributes is that closing it costs one errors.As and no transaction gymnastics at all.

package postgres

// The constraint names from 0001. They are part of this file's contract
// with that migration, which is why they are constants with a comment
// rather than string literals three functions down.
const (
	codeUnique        = "links_code_key"
	idempotencyUnique = "links_owner_idempotency_key"
)

type Store struct{ pool *pgxpool.Pool }

func NewStore(pool *pgxpool.Pool) *Store { return &Store{pool: pool} }

func (s *Store) Insert(ctx context.Context, l shortlink.Link, idempotencyKey string) error {
	const q = `
		INSERT INTO links (code, target_url, owner_id, idempotency_key, created_at, expires_at)
		VALUES ($1, $2, $3, $4, $5, $6)`

	_, err := s.pool.Exec(ctx, q,
		string(l.Code), l.Target.String(), l.OwnerID,
		nullable(idempotencyKey), l.CreatedAt, l.ExpiresAt)
	if err == nil {
		return nil
	}

	// Translate infrastructure into domain here, so that nothing above this
	// package has to know pgx exists. errors.As unwraps until it finds a
	// *pgconn.PgError -- which is why the sentinel comparison in the caller
	// keeps working however many times this error gets wrapped on the way up.
	var pgErr *pgconn.PgError
	if errors.As(err, &pgErr) && pgErr.Code == pgerrcode.UniqueViolation {
		switch pgErr.ConstraintName {
		case codeUnique:
			return shortlink.ErrCodeTaken
		case idempotencyUnique:
			return shortlink.ErrIdempotencyClash
		}
	}
	return fmt.Errorf("insert link: %w", err)
}

func (s *Store) ByCode(ctx context.Context, code shortlink.Code) (shortlink.Link, error) {
	const q = `
		SELECT code, target_url, owner_id, created_at, expires_at
		FROM links WHERE code = $1`
	return s.one(ctx, q, string(code))
}

func (s *Store) ByIdempotencyKey(ctx context.Context, ownerID, key string) (shortlink.Link, error) {
	const q = `
		SELECT code, target_url, owner_id, created_at, expires_at
		FROM links WHERE owner_id = $1 AND idempotency_key = $2`
	return s.one(ctx, q, ownerID, key)
}

func (s *Store) DeleteOwned(ctx context.Context, ownerID string, code shortlink.Code) error {
	const q = `DELETE FROM links WHERE code = $1 AND owner_id = $2`
	tag, err := s.pool.Exec(ctx, q, string(code), ownerID)
	if err != nil {
		return fmt.Errorf("delete link: %w", err)
	}
	if tag.RowsAffected() == 0 {
		// Nought rows means it does not exist or it is not yours, and the
		// API says the same thing for both. Telling an unauthorised caller
		// that a code exists is how a database gets enumerated.
		return shortlink.ErrNotFound
	}
	return nil
}

func (s *Store) one(ctx context.Context, q string, args ...any) (shortlink.Link, error) {
	var (
		l    shortlink.Link
		code string
		raw  string
		exp  *time.Time
	)
	err := s.pool.QueryRow(ctx, q, args...).
		Scan(&code, &raw, &l.OwnerID, &l.CreatedAt, &exp)
	switch {
	case errors.Is(err, pgx.ErrNoRows):
		return shortlink.Link{}, shortlink.ErrNotFound
	case err != nil:
		return shortlink.Link{}, fmt.Errorf("query link: %w", err)
	}

	target, err := url.Parse(raw)
	if err != nil {
		// A row that cannot be parsed is corruption, not a 404. Say so.
		return shortlink.Link{}, fmt.Errorf("stored url for %s: %w", code, err)
	}
	l.Code = shortlink.Code(code)
	l.Target = target
	if exp != nil {
		l.ExpiresAt = *exp
	}
	return l, nil
}

func nullable(s string) *string {
	if s == "" {
		return nil   // NULL, so the partial index ignores this row
	}
	return &s
}

Go had nothing to undo here, and that is the whole difference

The Java version of this file needs a separate bean, annotated REQUIRES_NEW, purely so that the failed insert does not poison a transaction the caller was in the middle of. Go has no ambient transaction: pool.Exec outside a Begin is its own implicit transaction, so a unique violation rolls back exactly one statement and the caller simply tries a different code. The trap has not gone away, it has become visible — the moment this Exec is inside a pgx.Tx, Postgres marks that transaction aborted and every later statement in it fails with current transaction is aborted until you roll back. The fix there is a savepoint (tx.Begin nested inside a transaction is one) or doing the insert outside the transaction, which is what this code does by default rather than by accident.

	"net/url"
	"time"

// Store is declared here, in the package that uses it, and not in the
// package that implements it. That is the Go convention and it is not a
// stylistic one: it means the domain names the four methods it needs
// rather than depending on the thirty a database library offers, a test
// can satisfy it with a fifteen-line fake, and internal/postgres does not
// import this interface at all -- it simply happens to satisfy it.
type Store interface {
	Insert(ctx context.Context, l Link, idempotencyKey string) error
	ByCode(ctx context.Context, code Code) (Link, error)
	ByIdempotencyKey(ctx context.Context, ownerID, key string) (Link, error)
	DeleteOwned(ctx context.Context, ownerID string, code Code) error
}

const maxCodeAttempts = 5

type Service struct {
	store      Store
	now        func() time.Time   // injected, so a test can be about expiry
	codeLength int
	defaultTTL time.Duration
}

func NewService(store Store, now func() time.Time, codeLength int, ttl time.Duration) *Service {
	return &Service{store: store, now: now, codeLength: codeLength, defaultTTL: ttl}
}

// NewLink is everything one create needs, so the call cannot be made with
// the arguments the wrong way round -- four of them are strings.
type NewLink struct {
	OwnerID        string
	Target         *url.URL
	Alias          Code           // optional: a caller's chosen code
	TTL            time.Duration  // zero means the default
	IdempotencyKey string
}

func (s *Service) Shorten(ctx context.Context, req NewLink) (Link, error) {
	// The fast path: a client retrying after a timeout, seconds later. It
	// is an optimisation and not the guarantee -- see the note above.
	if req.IdempotencyKey != "" {
		switch existing, err := s.store.ByIdempotencyKey(ctx, req.OwnerID, req.IdempotencyKey); {
		case err == nil:
			return existing, nil
		case !errors.Is(err, ErrNotFound):
			return Link{}, err
		}
	}

	now := s.now()
	ttl := req.TTL
	if ttl == 0 {
		ttl = s.defaultTTL
	}

	for attempt := 0; attempt < maxCodeAttempts; attempt++ {
		code := req.Alias
		if code == "" {
			generated, err := NewCode(s.codeLength)
			if err != nil {
				return Link{}, err
			}
			code = generated
		}

		link := Link{
			Code: code, Target: req.Target, OwnerID: req.OwnerID,
			CreatedAt: now, ExpiresAt: now.Add(ttl),
		}
		err := s.store.Insert(ctx, link, req.IdempotencyKey)
		switch {
		case err == nil:
			return link, nil

		case errors.Is(err, ErrIdempotencyClash):
			// The slow path: a genuine race. The other request won, and
			// its link is the correct answer to both of them.
			return s.store.ByIdempotencyKey(ctx, req.OwnerID, req.IdempotencyKey)

		case errors.Is(err, ErrCodeTaken) && req.Alias != "":
			// A caller's chosen alias is a 409 they can act on. A
			// generated code that collided is our problem, not theirs.
			return Link{}, fmt.Errorf("%w: %s", ErrCodeTaken, code)

		case errors.Is(err, ErrCodeTaken):
			continue   // try another code

		default:
			return Link{}, err
		}
	}
	return Link{}, ErrNoCode
}

func (s *Service) Resolve(ctx context.Context, code Code) (Link, error) {
	link, err := s.store.ByCode(ctx, code)
	if err != nil {
		return Link{}, err
	}
	if link.Expired(s.now()) {
		// Deliberately not ErrNotFound: a client that is told "gone" can
		// stop retrying, and an operator reading logs can tell them apart.
		return Link{}, ErrExpired
	}
	return link, nil
}

func (s *Service) Delete(ctx context.Context, ownerID string, code Code) error {
	return s.store.DeleteOwned(ctx, ownerID, code)
}

func (s *Server) Handler() http.Handler {
	mux := http.NewServeMux()

	// Method and path parameter in the pattern, matched by the standard
	// library. The specific pattern wins over the general one, so
	// "GET /healthz" is not swallowed by "GET /{code}" -- ServeMux picks
	// the most specific match rather than the first registered, which is
	// the behaviour that made third-party routers necessary before 1.22.
	mux.Handle("POST /v1/links", s.authenticate(http.HandlerFunc(s.createLink)))
	mux.Handle("GET /v1/links/{code}", s.authenticate(http.HandlerFunc(s.readLink)))
	mux.Handle("DELETE /v1/links/{code}", s.authenticate(http.HandlerFunc(s.deleteLink)))

	mux.HandleFunc("GET /healthz", s.healthz)
	mux.HandleFunc("GET /readyz", s.readyz)

	// The only unauthenticated route, and the only one with real traffic.
	mux.HandleFunc("GET /{code}", s.redirect)

	// Outermost first: a panic in the logger should still be recovered,
	// and the request id has to exist before anything logs.
	return requestID(logging(s.log, recovery(s.log, mux)))
}

// The wire contract. It exists separately from shortlink.Link because the
// two change for different reasons: this one when a consumer needs
// something, that one when the rules do.
type createRequest struct {
	URL     string `json:"url"`
	Alias   string `json:"alias,omitempty"`
	TTLDays int    `json:"ttl_days,omitempty"`
}

type linkResponse struct {
	Code      string     `json:"code"`
	ShortURL  string     `json:"short_url"`
	URL       string     `json:"url"`
	CreatedAt time.Time  `json:"created_at"`
	ExpiresAt *time.Time `json:"expires_at,omitempty"`
}

func (s *Server) createLink(w http.ResponseWriter, r *http.Request) {
	caller, _ := callerFrom(r.Context())

	var body createRequest
	dec := json.NewDecoder(http.MaxBytesReader(w, r.Body, 16<<10))
	dec.DisallowUnknownFields()   // a typo in a field name is a 400, not a shrug
	if err := dec.Decode(&body); err != nil {
		s.problem(w, r, invalid(err))
		return
	}

	target, err := shortlink.ParseTarget(body.URL)
	if err != nil {
		s.problem(w, r, err)
		return
	}
	req := shortlink.NewLink{
		OwnerID:        caller.OwnerID,
		Target:         target,
		TTL:            time.Duration(body.TTLDays) * 24 * time.Hour,
		IdempotencyKey: r.Header.Get("Idempotency-Key"),
	}
	if body.Alias != "" {
		alias, err := shortlink.ParseCode(body.Alias)
		if err != nil {
			s.problem(w, r, err)
			return
		}
		req.Alias = alias
	}

	// The write gets its own deadline rather than inheriting the client's
	// patience. r.Context() is cancelled the moment the client hangs up,
	// and a write cancelled halfway is a request nobody can answer
	// afterwards; WithoutCancel keeps the values -- the request id, the
	// trace -- and drops only the cancellation.
	ctx, cancel := context.WithTimeout(context.WithoutCancel(r.Context()), 3*time.Second)
	defer cancel()

	link, err := s.links.Shorten(ctx, req)
	if err != nil {
		s.problem(w, r, err)
		return
	}

	short := s.base.JoinPath(link.Code.String())
	w.Header().Set("Location", short.String())
	s.writeJSON(w, http.StatusCreated, s.response(link))
}

func (s *Server) readLink(w http.ResponseWriter, r *http.Request) {
	caller, _ := callerFrom(r.Context())
	code, err := shortlink.ParseCode(r.PathValue("code"))   // Go 1.22
	if err != nil {
		s.problem(w, r, err)
		return
	}
	link, err := s.links.Resolve(r.Context(), code)
	if err != nil || link.OwnerID != caller.OwnerID {
		// Not yours reads as not found, on purpose.
		s.problem(w, r, orNotFound(err))
		return
	}
	s.writeJSON(w, http.StatusOK, s.response(link))
}

func (s *Server) deleteLink(w http.ResponseWriter, r *http.Request) {
	caller, _ := callerFrom(r.Context())
	code, err := shortlink.ParseCode(r.PathValue("code"))
	if err != nil {
		s.problem(w, r, err)
		return
	}
	ctx, cancel := context.WithTimeout(context.WithoutCancel(r.Context()), 3*time.Second)
	defer cancel()

	if err := s.links.Delete(ctx, caller.OwnerID, code); err != nil {
		s.problem(w, r, err)
		return
	}
	// 204: it is gone, there is nothing to say about it, and a body on a
	// delete is something clients start depending on.
	w.WriteHeader(http.StatusNoContent)
}

func (s *Server) response(l shortlink.Link) linkResponse {
	out := linkResponse{
		Code:      l.Code.String(),
		ShortURL:  s.base.JoinPath(l.Code.String()).String(),
		URL:       l.Target.String(),
		CreatedAt: l.CreatedAt,
	}
	if !l.ExpiresAt.IsZero() {
		out.ExpiresAt = &l.ExpiresAt
	}
	return out
}

func (s *Server) writeJSON(w http.ResponseWriter, status int, v any) {
	// Marshal before writing the header. json.NewEncoder(w).Encode writes
	// the 200 first and then discovers the value will not marshal, which
	// leaves the client a truncated body under a success status.
	buf, err := json.Marshal(v)
	if err != nil {
		s.log.Error("marshal response", "error", err)
		http.Error(w, `{"title":"Internal server error"}`, http.StatusInternalServerError)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	_, _ = w.Write(buf)
}

func (s *Server) redirect(w http.ResponseWriter, r *http.Request) {
	code, err := shortlink.ParseCode(r.PathValue("code"))
	if err != nil {
		s.problem(w, r, shortlink.ErrNotFound)   // a malformed code is simply not a link
		return
	}
	link, err := s.links.Resolve(r.Context(), code)
	if err != nil {
		s.problem(w, r, err)
		return
	}

	// 302 and no-store, not 301, and this is not a style preference. A 301
	// is permanent and browsers treat it that way: Chrome caches it, often
	// for the life of the profile, and stops asking. Ship a 301 and you
	// have given away the three things a shortener exists to have -- you
	// can never re-point the link, never expire or delete it, and your
	// click metrics fall off a cliff because every repeat visit redirects
	// locally and you never see it. The 301 buys the user one round trip
	// and costs you the product. Buy the latency back at a CDN, where you
	// can still purge.
	w.Header().Set("Cache-Control", "no-store")
	http.Redirect(w, r, link.Target.String(), http.StatusFound)
}

	// error is testable; a function calling os.Exit is not, because
	// os.Exit skips every deferred call in the process including the
	// test framework's.
	if err := run(ctx); err != nil {
		fmt.Fprintf(os.Stderr, "shortlinkd: %v\n", err)
		os.Exit(1)
	}

package main

import (
	"context"
	"errors"
	"fmt"
	"log/slog"
	"net/http"
	"os"
	"time"

	"github.com/redis/go-redis/v9"

	"github.com/jaspreet/shortlink/internal/httpapi"
	"github.com/jaspreet/shortlink/internal/postgres"
	"github.com/jaspreet/shortlink/internal/ratelimit"
	"github.com/jaspreet/shortlink/internal/shortlink"
)

func run(ctx context.Context) error {
	cfg, err := config.Load()
	if err != nil {
		return fmt.Errorf("load config: %w", err)
	}

	log := slog.New(httpapi.ContextHandler{
		Handler: slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo}),
	}).With("service", "shortlink")
	slog.SetDefault(log)

	if err := postgres.Migrate(ctx, cfg.DatabaseURL); err != nil {
		return err
	}

	pool, err := postgres.NewPool(ctx, cfg.DatabaseURL)
	if err != nil {
		return err
	}
	defer pool.Close()

	redisOpts, err := redis.ParseURL(cfg.RedisURL)
	if err != nil {
		return fmt.Errorf("parse redis url: %w", err)
	}
	rdb := redis.NewClient(redisOpts)
	defer rdb.Close()

	store := postgres.NewStore(pool)
	svc := shortlink.NewService(store, time.Now, cfg.CodeLength, cfg.DefaultTTL)

	api := httpapi.New(httpapi.Deps{
		Links:   svc,
		Keys:    postgres.NewKeyStore(pool),
		Limiter: ratelimit.NewRedis(rdb, cfg.RateLimit, cfg.RateWindow),
		BaseURL: cfg.PublicBaseURL,
		Log:     log,
		Ready: func(ctx context.Context) error {
			if err := pool.Ping(ctx); err != nil {
				return fmt.Errorf("postgres: %w", err)
			}
			if err := rdb.Ping(ctx).Err(); err != nil {
				return fmt.Errorf("redis: %w", err)
			}
			return nil
		},
	})

	srv := httpapi.NewHTTPServer(ctx, cfg.Addr, api.Handler(), log)

	// The listener goes on its own goroutine so that this one can wait on
	// whichever happens first: the server failing, or the signal arriving.
	// The channel is buffered so that goroutine can exit either way and
	// does not leak when we return through the other branch.
	serverFailed := make(chan error, 1)
	go func() {
		log.Info("listening", "addr", cfg.Addr)
		serverFailed <- srv.ListenAndServe()
	}()

	select {
	case err := <-serverFailed:
		if !errors.Is(err, http.ErrServerClosed) {
			return fmt.Errorf("serve: %w", err)
		}
	case <-ctx.Done():
		log.Info("signal received, draining")
	}

	// WithoutCancel is load-bearing and this is the bug it prevents: ctx is
	// already cancelled by the time we get here, so context.WithTimeout(ctx,
	// 20s) would hand back a context that is cancelled at birth, Shutdown
	// would return immediately, and every in-flight request would be cut
	// off -- a graceful shutdown that drains nothing, on every deploy,
	// silently.
	shutdownCtx, cancel := context.WithTimeout(context.WithoutCancel(ctx), 20*time.Second)
	defer cancel()

	if err := srv.Shutdown(shutdownCtx); err != nil {
		return fmt.Errorf("shutdown: %w", err)
	}
	log.Info("stopped cleanly")
	return nil
}

The order of the deferred closes is the order of the dependencies, backwards

defer pool.Close() runs after defer rdb.Close(), which runs after srv.Shutdown returns, because deferred calls run last-in first-out. That is exactly right and it is free: the pool was created before Redis, Redis before the server, so the teardown unwinds in the reverse order without anybody maintaining a list. Get it wrong — close the pool before the server drains — and every request still in flight gets use of closed connection instead of an answer, on every single deploy. This is the one place where Go’s least fashionable feature quietly does a job that other languages need a lifecycle framework and an annotation for.

// One table, walked by errors.Is in order. Go has no exhaustive switch
// over a sealed set, so the guarantee the Java version gets from its
// compiler is bought here by a test: problem_test.go walks shortlink.All
// and fails if any sentinel is missing from this slice.
var catalogue = []struct {
	err    error
	status int
	slug   string
	title  string
}{
	{shortlink.ErrInvalid, http.StatusBadRequest, "invalid-request", "Invalid request"},
	{shortlink.ErrNotFound, http.StatusNotFound, "link-not-found", "Link not found"},
	{shortlink.ErrExpired, http.StatusGone, "link-expired", "Link expired"},
	{shortlink.ErrCodeTaken, http.StatusConflict, "code-taken", "Code taken"},
	{shortlink.ErrIdempotencyClash, http.StatusConflict, "in-flight", "Request in flight"},
	{shortlink.ErrNoCode, http.StatusServiceUnavailable, "no-code", "Try again"},
}

func (s *Server) problem(w http.ResponseWriter, r *http.Request, err error) {
	for _, entry := range catalogue {
		if errors.Is(err, entry.err) {
			write(w, problemDetail{
				Type:   problemBase + entry.slug,
				Title:  entry.title,
				Status: entry.status,
				Detail: err.Error(),
			})
			return
		}
	}

	// Anything unmatched. Log everything, tell the client nothing: a Go
	// error string routinely contains a DSN, a hostname or a driver
	// version, and none of that belongs in a response body.
	s.log.ErrorContext(r.Context(), "unhandled error",
		"error", err, "method", r.Method, "path", r.URL.Path)
	write(w, problemDetail{
		Type:   problemBase + "internal",
		Title:  "Internal server error",
		Status: http.StatusInternalServerError,
	})
}

func write(w http.ResponseWriter, p problemDetail) {
	w.Header().Set("Content-Type", "application/problem+json")
	w.WriteHeader(p.Status)
	_ = json.NewEncoder(w).Encode(p)
}

Who is calling, and how often

Two controls that fail in opposite directions. Authentication decides whether a request happens at all, so it must be impossible to skip — which is why it wraps the handler rather than being a call at the top of one. // APIKey is who is calling. KeyStore and Limiter are declared here, in the
// package that uses them, so internal/postgres and internal/ratelimit do
// not import this package at all -- they just happen to satisfy it.
type APIKey struct {
	OwnerID string
	Label   string
	Digest  string
}

type KeyStore interface {
	ByDigest(ctx context.Context, digest string) (APIKey, error)
}

type Limiter interface {
	Allow(ctx context.Context, ownerID string) (bool, error)
}

// The context key is an unexported empty struct type, not a string. A
// string key can collide with one set by any other package in the process
// -- including a library you did not write -- and the collision is silent.
// An unexported type cannot be named from outside this package, so it
// cannot collide, and it costs nothing at run time.
type callerKey struct{}

func withCaller(ctx context.Context, k APIKey) context.Context {
	return context.WithValue(ctx, callerKey{}, k)
}

func callerFrom(ctx context.Context) (APIKey, bool) {
	k, ok := ctx.Value(callerKey{}).(APIKey)
	return k, ok
}

func (s *Server) authenticate(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		presented, ok := strings.CutPrefix(r.Header.Get("Authorization"), "Bearer ")
		if !ok || presented == "" {
			s.unauthorized(w)
			return
		}

		sum := sha256.Sum256([]byte(presented))
		digest := hex.EncodeToString(sum[:])

		// The lookup is by digest, so a database that leaks tells an
		// attacker nothing usable: they get hashes, and a 256-bit random
		// key does not come back out of one.
		key, err := s.keys.ByDigest(r.Context(), digest)
		if err != nil {
			if !errors.Is(err, shortlink.ErrNotFound) {
				s.log.ErrorContext(r.Context(), "key lookup failed", "error", err)
			}
			s.unauthorized(w)
			return
		}
		// Redundant on its face -- the row was found by this digest -- and
		// kept anyway, because it stays correct the day the lookup becomes
		// a cache or a prefix scan. Constant time, so no attacker learns
		// anything from how long a miss took.
		if subtle.ConstantTimeCompare([]byte(key.Digest), []byte(digest)) != 1 {
			s.unauthorized(w)
			return
		}

		allowed, err := s.limiter.Allow(r.Context(), key.OwnerID)
		if err != nil {
			// Fail open, loudly. See the note under the limiter.
			s.log.WarnContext(r.Context(), "rate limiter unavailable", "error", err)
		} else if !allowed {
			s.tooManyRequests(w)
			return
		}

		next.ServeHTTP(w, r.WithContext(withCaller(r.Context(), key)))
	})
}

func (s *Server) unauthorized(w http.ResponseWriter) {
	// The header is not optional: without it a client cannot tell "you
	// need a key" from "your key is wrong from the wrong scheme".
	w.Header().Set("WWW-Authenticate", "Bearer")
	write(w, problemDetail{
		Type: problemBase + "unauthorized", Title: "Unauthorized",
		Status: http.StatusUnauthorized, Detail: "a valid API key is required",
	})
}

func (s *Server) tooManyRequests(w http.ResponseWriter) {
	w.Header().Set("Retry-After", "60")   // seconds, and mean it
	write(w, problemDetail{
		Type: problemBase + "rate-limited", Title: "Too many requests",
		Status: http.StatusTooManyRequests, Detail: "the per-minute quota for this key is spent",
	})
}

package ratelimit

import (
	"context"
	"fmt"
	"time"

// Two commands as one round trip and one atomic step. INCR and PEXPIRE
// sent separately have a window in which the process dies between them,
// which leaves a key with no TTL -- and that bans the caller permanently.
var increment = redis.NewScript(`
	local hits = redis.call('INCR', KEYS[1])
	if hits == 1 then
		redis.call('PEXPIRE', KEYS[1], ARGV[1])
	end
	return hits
`)

type Redis struct {
	client    *redis.Client
	permitted int
	window    time.Duration
}

func NewRedis(client *redis.Client, permitted int, window time.Duration) *Redis {
	return &Redis{client: client, permitted: permitted, window: window}
}

func (r *Redis) Allow(ctx context.Context, ownerID string) (bool, error) {
	// The key carries the window, so the previous window's key expires on
	// its own and there is nothing to sweep up.
	bucket := time.Now().UnixMilli() / r.window.Milliseconds()
	key := fmt.Sprintf("rl:%s:%d", ownerID, bucket)

	// A limiter that is slow is worse than no limiter: it adds its latency
	// to every request it permits. This deadline is separate from the
	// request's and much shorter.
	ctx, cancel := context.WithTimeout(ctx, 250*time.Millisecond)
	defer cancel()

	hits, err := increment.Run(ctx, r.client, []string{key}, r.window.Milliseconds()).Int64()
	if err != nil {
		return false, fmt.Errorf("rate limit: %w", err)
	}
	return hits <= int64(r.permitted), nil
}

// able to say exactly why in an interview. Four replicas each with their
// own map give one caller four times the quota. A deploy resets everyone's
// counter to zero, which is precisely when you least want it. And the map
// grows forever unless somebody writes the sweeper, which nobody does.
//
// A fixed window lets a caller spend twice the quota across a boundary --
// sixty at 11:59:59 and sixty more at 12:00:00. For an API key that is
// fine and the simplicity is worth it. When it is not, a sliding window
// log or a token bucket is the same INCR-in-Lua shape with more
// arithmetic, and both still live in Redis for the same reason.

SHA-256 for an API key, bcrypt for a password — and swapping them is a bug both ways

A password is a low-entropy secret a human chose, so the defence against a stolen table is to make each guess expensive: bcrypt, scrypt or argon2, deliberately slow, salted per row. An API key is 256 bits out of crypto/rand; there is no dictionary to run against it and no amount of GPU that gets through the space, so a plain SHA-256 is enough. It is also necessary: put bcrypt on this path and you have added a hundred milliseconds of CPU to every authenticated request, which at any real rate is a fleet of pods spent hashing. Fast hash for high-entropy secrets, slow hash for human-chosen ones, and be able to say why in one sentence — this gets asked constantly.

The other half is the key’s life: generate it with crypto/rand, show the plaintext exactly once at creation, store only the digest, and give every key a revoked_at so revocation is an update you can audit rather than a delete you cannot. A prefix like sl_live_ costs nothing and lets a secret scanner find it in a public repository before an attacker does.

Failing open is a decision, and it has to be made on purpose

The middleware above logs and continues when Redis is unreachable, which means a Redis outage becomes unlimited traffic rather than a total outage. That is the right trade for this service and the wrong one for a limiter protecting something that genuinely cannot absorb the load — a payment endpoint, a third-party quota you are billed for, a login path being credential-stuffed. Whichever you choose, choose it in the code with a comment saying so, because the version that gets chosen by accident is always fail-open, and it is discovered during the incident.

// Handler the context, so a handler can pull values out of it -- which
// means no thread-local, no MDC, nothing to clear in a defer, and nothing
// that can leak one request's id onto another's log line.
//
// The catch, and it is a real one: this only fires for the *Context
// variants. log.Info("x") and log.InfoContext(ctx, "x") produce different
// lines, and the first is missing the id. Make the reviewer's rule "no
// bare slog calls inside a handler" and it stays honest.
type ContextHandler struct{ slog.Handler }

func (h ContextHandler) Handle(ctx context.Context, r slog.Record) error {
	if id, ok := ctx.Value(requestIDKey{}).(string); ok {

	}

// write a convincing fake log entry.
var safeID = regexp.MustCompile(`^[A-Za-z0-9._-]{1,64}$`)

func requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-Id")
		if !safeID.MatchString(id) {
			var b [16]byte
			_, _ = rand.Read(b[:])
			id = hex.EncodeToString(b[:])
		}
		// Echoed, so support can paste the header out of a customer's HAR
		// file straight into the log search.
		w.Header().Set("X-Request-Id", id)
		next.ServeHTTP(w, r.WithContext(context.WithValue(r.Context(), requestIDKey{}, id)))
	})
}

// written. Note it embeds the interface rather than reimplementing it, so
// it stays a valid ResponseWriter -- but embedding also hides Flush and

	status int
	bytes  int
}

	s.ResponseWriter.WriteHeader(code)
}

	s.bytes += n
	return n, err
}

func logging(log *slog.Logger, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(rec, r)

		// Attributes, never a formatted sentence. "link %s expired" is a
		// string you can grep; separate keys are fields you can filter,
		// group and alert on.
		log.InfoContext(r.Context(), "request",
			"method", r.Method,
			"path", r.URL.Path,
			"status", rec.status,
			"bytes", rec.bytes,
			"duration_ms", time.Since(start).Milliseconds(),
		)
	})
}

func recovery(log *slog.Logger, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			v := recover()
			switch {
			case v == nil:
				return
			case v == http.ErrAbortHandler:
				// The standard library's own signal that a handler is
				// deliberately abandoning the connection. Re-panic, or
				// net/http cannot do what it was asked.
				panic(v)
			default:
				log.ErrorContext(r.Context(), "panic in handler", "value", v, "path", r.URL.Path)
				write(w, problemDetail{
					Type: problemBase + "internal", Title: "Internal server error",
					Status: http.StatusInternalServerError,
				})
			}
		}()
		next.ServeHTTP(w, r)
	})
}

The image, the pipeline, and two runtime settings

Go’s deployment story is the best of the three languages in this series and it is almost entirely down to one property: the output is a single static binary with no runtime to install, so the runtime image can contain that binary and nothing else. Two settings the Go runtime does not read from the container, and both cost you real money

GOMAXPROCS. For most of Go’s life the runtime sized its scheduler from the number of CPUs it could see on the host, not from the cgroup CPU quota the container was given. On a 64-core node with a 0.5-CPU limit that means 64 scheduler threads and 64 garbage-collector workers fighting for half a core, and the symptom is latency that gets worse when you scale the node up. go.uber.org/automaxprocs is the standard fix — a blank import that reads the cgroup and sets the value — and recent Go versions have started doing this in the runtime itself, so check what your version does rather than assuming either way. Whichever it is, log the value at start-up; it is one line and it settles the argument.

GOMEMLIMIT. Go’s collector runs when the heap has doubled, which means a service that is idle for ten minutes and then allocates hard can sail past the container’s memory limit before a collection was due — and the kernel’s OOM killer does not negotiate. GOMEMLIMIT is a soft limit: set it to about 90% of the container limit and the collector works harder as you approach it instead of the process being killed with no stack trace and no log line. It is one environment variable and it converts a hard crash into a CPU cost.

govulncheck on every build, not on a calendarIt is call-graph aware, so it is one of the few security gates whose output is short enough that people keep reading it.
Alerts on the 500 rate and on p99, not just dashboardsA dashboard is for after somebody noticed. An alert is for before.
A rollback that is one command, and that somebody has runEvery deploy plan has one. The ones that work were rehearsed on a Tuesday afternoon rather than discovered at 2am.

Read this part beside the Python and Java ones and the differences are smaller than the languages suggest. All three put the rules in a package that imports nothing, make idempotency a database constraint rather than a check, keep one error shape, hash the API key, share the rate limit, and fail the boot rather than the tenth request. What Go changes is the amount of machinery in between. There is no container, no proxy, no annotation and no reflection: run is the dependency graph, defer is the lifecycle, context carries the deadline and the request id that the other two need a framework and a thread-local for, and the deployable artefact is one file. What that costs is the guarantees a richer type system was giving you — Code("") compiles, the error switch is not exhaustive, and the layering is a linter rather than a compiler — so each of those is bought back here with a test. That trade, and being able to name both halves of it, is the answer to give when somebody asks why you would choose Go for a service.
