Part one

The object model

Python has no variables in the C sense. It has names bound to objects, and almost every beginner surprise — the function that mutated your list, the default argument that remembered, the is that worked until it did not — follows from that one fact. Learn the binding model first and the rest stops being folklore.

Python · 01

Names, objects and references

Assignment never copies. It points a name at an object that already exists. Two names can reach the same object, and only one of the two operations you can perform — rebinding a name, mutating an object — is visible to the other name.

a = [1, 2, 3]
b = a                           # one object, two names
b.append(4)
print(a)                        # [1, 2, 3, 4] -- a sees it
print(a is b, id(a) == id(b))   # True True

def rebind(lst):
    lst.append(99)              # mutates the caller's object
    lst = [0]                   # rebinds the LOCAL name only
    return lst

x = [1]
rebind(x)
print(x)                        # [1, 99] -- append survived, rebind did not
L1 · Beginner

Bindings, not boxes

  • Assignment binds a name — x = obj makes x refer to obj. Nothing is copied and no storage is reserved for x.
  • == vs is — equal value versus the same object. Use == unless you specifically mean identity.
  • Everything is an object: integers, functions, modules, classes and exceptions all have a type, attributes and an id().
  • Because functions are objects, you can put one in a list, pass it as an argument, or return it — no special syntax required.
  • type(x) tells you what it is; id(x) tells you which one it is.
L2 · Intermediate

What a call actually passes

  • Argument passing is name binding — the parameter becomes another name for the caller’s object. Not by value, not by reference in the Pascal sense.
  • So a function can mutate your list, dict or set, and cannot rebind your name. lst.append(x) escapes; lst = [] does not.
  • del x removes the name, not the object. Any other name still bound to it keeps it alive.
  • Rebinding in a loop, a comprehension or an except ... as e block follows the same rule — and e is deleted at the end of the except block.
  • Take a copy at the boundary if the caller must not see your edits; say so in the docstring either way.
L3 · Advanced

Lifetime, and why is lies

  • Reference counting frees an object the moment its last reference goes; a cycle detector handles the rest. What keeps an object alive is a reference, from anywhere — a list, a frame, a closure cell, a traceback.
  • id() is reused. It is the address in CPython, so a freed object’s id can be handed straight to the next one. Never store an id as a key.
  • is on ints and strings is a bug that passes its own test. Interning is an implementation detail that varies between literal, computed, and interactive contexts.
  • A traceback holds a reference to every frame, and every frame holds its locals — this is how exception handling keeps large objects alive longer than expected.
  • sys.getrefcount, gc.get_referrers and weakref are the tools when something will not die.
Python · 02

Mutability, copying, and the default-argument trap

A default value is evaluated once, when the def statement runs — not once per call. If that value is mutable, every call shares it, and the function quietly accumulates state across the life of the process.

def add(item, bucket=[]):        # bucket is created ONCE, at def time
    bucket.append(item)
    return bucket

add("a")            # ["a"]
add("b")            # ["a", "b"]  <- the same list, still there
add.__defaults__    # (["a", "b"],)  the evidence, on the function object

def add(item, bucket=None):      # the None-sentinel fix
    if bucket is None:
        bucket = []              # a fresh list per call
    bucket.append(item)
    return bucket
L1 · Beginner

Know which builtins bite

  • Mutable: list, dict, set, bytearray, and instances of most classes you write.
  • Immutable: int, float, str, bytes, tuple, frozenset, bool, None.
  • The default-argument trap — never write def f(x=[]) or def f(x={}). Use None and build inside the body.
  • list.copy() / dict.copy() hand out an independent top level; x[:] does the same for sequences.
  • A linter catches this one — ruff rule B006 exists precisely because it is so common.
L2 · Intermediate

Copy depth and hashability

  • Shallow vs deep — copy.copy duplicates one level; copy.deepcopy duplicates the whole reachable graph and keeps a memo so shared nodes stay shared and cycles terminate.
  • deepcopy costs — it is recursive, pickle-adjacent, and easily the slowest line in a hot loop. Prefer restructuring so you do not need it.
  • Mutable objects are unhashable because a dict places a key by its hash and would lose it if the hash moved.
  • A tuple containing a list is immutable at the top and still unhashable — hash((1, [2])) raises TypeError.
  • Dataclasses: field(default_factory=list) is the same fix, spelled for a class.
L3 · Advanced

Contracts and boundaries

  • The __hash__/__eq__ contract: equal objects must hash equal, and the hash must be stable for the object’s lifetime. Defining __eq__ alone sets __hash__ to None.
  • Freeze deliberately — frozenset, tuple, @dataclass(frozen=True), or a NamedTuple, when a value must be a key or crosses a thread boundary.
  • Defensive copying at API edges: copy on the way in if you will store it, on the way out if the caller might mutate it. Document the choice; do not make callers guess.
  • Copy-on-write is a myth here. Python has none — not for lists, not across fork() (refcount updates dirty the pages anyway).
  • __copy__ and __deepcopy__ let a type control its own duplication; use them for handles that must not be cloned.
Python · 03

The data model: protocols, not inheritance

Syntax is a call. len(x) is x.__len__(), x[k] is x.__getitem__(k), with x is x.__enter__(). Nothing checks a base class — the interpreter looks for the method and calls it.

class Money:
    __slots__ = ("amount", "currency")

    def __init__(self, amount, currency):
        self.amount, self.currency = amount, currency

    def __repr__(self):          # what logs, reprs and tracebacks show
        return f"Money({self.amount!r}, {self.currency!r})"

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented    # let the other type try
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __hash__(self):          # define WITH __eq__ or the type is unhashable
        return hash((self.amount, self.currency))
# the container and context-manager protocols -- no base class, just the methods
class Basket:
    def __init__(self):
        self._items: list[str] = []

    def __len__(self) -> int:                 # bool(basket), len(basket)
        return len(self._items)

    def __getitem__(self, i: int) -> str:      # basket[0], and makes it iterable for free
        return self._items[i]

    def __iadd__(self, item: str) -> "Basket": # basket += "eggs"
        self._items.append(item)
        return self

class transaction:                             # with transaction(conn): ...
    def __init__(self, conn):
        self.conn = conn

    def __enter__(self):
        self.conn.execute("BEGIN")
        return self.conn

    def __exit__(self, exc_type, exc, tb) -> bool:
        self.conn.execute("ROLLBACK" if exc_type else "COMMIT")
        return False                           # False: never swallow the exception
L1 · Beginner

The dunders you write first

  • __init__ initialises an object that already exists; __new__ is what actually creates it, and you almost never touch it.
  • __repr__ is for you — unambiguous, ideally something you could paste back in. __str__ is for the user.
  • Logs and tracebacks use __repr__, and lists of objects print their repr. A default <Order object at 0x7f...> is a wasted debugging session.
  • If you define only one, define __repr__ — str() falls back to it.
  • Dunder names are called by the interpreter. You define them; you rarely call them.
L2 · Intermediate

Implementing the protocols

  • __eq__ and __hash__ travel together; return NotImplemented (not False) for a type you do not understand, so the other operand gets its turn.
  • Iteration: __iter__ returns an iterator, whose __next__ raises StopIteration when done. A generator function gives you both for free.
  • __getitem__ alone makes an object indexable and, as a legacy fallback, iterable — which is why some old classes work in for without __iter__.
  • Operator overloading is for types where the operator already means something — vectors, money, paths. Not for cleverness.
  • functools.total_ordering fills in the other comparisons from __eq__ plus one of __lt__.
L3 · Advanced

Attribute machinery

  • Descriptors are the mechanism under @property, methods, classmethod and __slots__: an object with __get__/__set__ stored on the class.
  • __slots__ removes the per-instance __dict__ — less memory, faster attribute access, no ad-hoc attributes. Worth it for millions of small objects.
  • __getattr__ vs __getattribute__: the first runs only after normal lookup fails, the second intercepts every access and is easy to make infinitely recursive.
  • Metaclasses exist; __init_subclass__ and __set_name__ cover most of what people reach for them for. Learn them, deploy them rarely.
  • Say the protocol out loud. An ABC or a typing.Protocol turns “must have read and close” from a comment into something a checker enforces.
Part two

Functions and flow

Python’s function machinery is unusually rich: five kinds of parameter, laziness as a first-class control-flow tool, and closures that make decorators an ordinary consequence rather than a feature. All three shape how your API reads at the call site — and two of them have a trap that only shows up under load.

Python · 04

Arguments: positional, keyword, and the star operators

A signature has five zones, separated by / and by *. Where you put a parameter decides how callers may pass it — and therefore what you are free to change later without breaking them.

def connect(host, /, port=5432, *, timeout=5.0, sslmode="require"):
    ...

connect("db1")                       # host is positional-only
connect("db1", 6432)                 # port may be positional
connect("db1", timeout=1.0)          # timeout MUST be by keyword
connect(host="db1")                  # TypeError: host is positional-only

opts = {"timeout": 1.0, "sslmode": "disable"}
connect("db1", **opts)               # unpack a dict into keyword arguments

args = ("db1", 6432)
connect(*args, timeout=1.0)          # unpack an iterable into positionals
L1 · Beginner

Passing and collecting

  • Defaults make a parameter optional; keyword arguments let the caller name it and skip ordering entirely.
  • *args collects the leftover positionals into a tuple; **kwargs collects the leftover named ones into a dict.
  • Unpacking at the call site: f(*seq) spreads an iterable into positions, f(**mapping) spreads a dict into names.
  • The names args and kwargs are convention only — the stars do the work.
  • Keyword arguments at a call site are documentation: retry(3, True) tells a reader nothing, retry(3, jitter=True) tells them everything.
L2 · Intermediate

Designing the signature

  • Keyword-only parameters (after a bare *) can be reordered, renamed in position, and added to without breaking callers. Use them for every flag and option.
  • Positional-only (before /) frees the name: useful for a first argument like self-ish subjects, and for wrappers that also take **kwargs and must avoid name clashes.
  • Defaults are evaluated once, at def time — the same fact as the mutable-default trap above, and it applies to datetime.now() defaults too.
  • Booleans are almost always keyword-only. send(msg, True, False) is unreadable by construction.
  • *-unpacking works in literals as well: [*a, *b], {**d1, **d2}.
L3 · Advanced

Binding, introspection and restraint

  • functools.partial pre-binds arguments and returns a callable — cheaper and clearer than a lambda, and it keeps a usable repr.
  • inspect.signature reads the real parameter list; sig.bind(*a, **kw) resolves a call the way the interpreter would, which is how frameworks do dependency injection.
  • Accept **kwargs rarely. It defeats type checkers, autocomplete and inspect, turns typos into silent no-ops, and pushes errors down into whatever you forward to.
  • Argument order is API surface and shows up in every caller’s source. Treat a reorder like a rename: it needs a deprecation, not a patch release.
  • typing.ParamSpec and Concatenate exist so a decorator can keep the wrapped signature visible to the checker.
Python · 05

Comprehensions, generators and laziness

A comprehension builds the whole result before anything downstream runs. A generator computes one element per request and forgets it. Same answer, same code shape, and a memory profile that differs by the size of your input.

# Materialises every line: peak memory is the whole file.
total = sum([int(line) for line in open("events.log")])

# Streams: one line resident at a time, same answer.
with open("events.log") as f:
    total = sum(int(line) for line in f)

# A pipeline of generators -- still one element in flight.
def parse(lines):
    for line in lines:
        if line.strip():
            yield json.loads(line)

with open("events.ndjson") as f:
    errors = (e for e in parse(f) if e["level"] == "error")
    first_ten = list(itertools.islice(errors, 10))   # stops reading after 10
L1 · Beginner

Building sequences

  • Comprehensions come in three shapes: [x for ...] list, {k: v for ...} dict, {x for ...} set.
  • They replace the result = [] / append loop and are usually faster, because the append is done in C.
  • range is lazy — range(10**9) costs nothing until you iterate it. So are zip, map, filter and enumerate.
  • yield makes a generator: calling the function runs no code, it hands back an object that runs on demand.
  • One condition and one loop is a comprehension; two of either is a for loop.
L2 · Intermediate

Picking lazy or eager

  • Generator expression vs list comprehension — parentheses instead of brackets. Choose the generator when the result is consumed once, the list when you need len, indexing or a second pass.
  • Generators are single-use. Re-iterating a spent generator silently yields nothing, which looks like missing data, not like an error.
  • itertools is the standard toolkit: islice (take n), chain (concatenate), groupby (needs sorted input), batched (fixed-size chunks, 3.12+).
  • enumerate and zip replace index arithmetic; zip(strict=True) catches length mismatches instead of truncating.
  • A generator that wraps a resource should be consumed inside the with block that owns it.
L3 · Advanced

Pipelines and their cost

  • yield from delegates to a sub-generator, forwarding values, send and exceptions — and flattens recursion without a manual loop.
  • Generators were the original coroutines: send, throw and close predate async/await, which was built on exactly this machinery. Write new async code with async def.
  • A pipeline of generators keeps one item per stage alive, so memory is O(stages), not O(input) — the same shape as a Go channel pipeline, minus the concurrency.
  • __iter__ returning self is what makes an iterator work in for; a re-iterable iterable returns a fresh iterator each time. Confusing the two is why a class works once and then stops.
  • Laziness moves work rather than removing it: tracebacks point at the consumer, and per-element function-call overhead can make a generator slower than one bulk operation.
Python · 06

Scope, closures and decorators

A name is resolved local, enclosing, global, built-in — first match wins. A closure captures the enclosing variable, not its value at capture time, and a decorator is nothing more than a function that takes a function and returns one.

import functools, time

def timed(fn):
    @functools.wraps(fn)                 # keeps __name__, __doc__, __wrapped__
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            ms = (time.perf_counter() - start) * 1000
            log.info("%s took %.1f ms", fn.__name__, ms)
    return wrapper

@timed                                   # charge = timed(charge)
def charge(order_id):
    ...
# the late-binding trap: a closure reads the variable, not a snapshot of it
handlers = []
for route in ["orders", "users", "health"]:
    handlers.append(lambda: log.info("handling %s", route))

[h() for h in handlers]        # "handling health" three times -- route is one shared cell

# the fix: bind it as a default argument, evaluated once, right now
handlers = []
for route in ["orders", "users", "health"]:
    handlers.append(lambda route=route: log.info("handling %s", route))

[h() for h in handlers]        # "handling orders", "handling users", "handling health"
L1 · Beginner

Where names live

  • Local vs global — assigning to a name anywhere in a function makes it local for the whole function, even on lines above the assignment.
  • global and nonlocal are needed only to rebind an outer name. Reading and mutating need neither.
  • A closure keeps its enclosing variables alive after the outer function has returned — that is what makes inner functions useful.
  • @decorator is f = decorator(f), applied right after the def. Nothing more.
  • Module-level mutable state is global state; it will be shared by every import.
L2 · Intermediate

Writing decorators that behave

  • Late binding in loops — closures created in a loop all see the final value. Bind with a default (x=x) or functools.partial.
  • functools.wraps copies __name__, __doc__, __module__, annotations and sets __wrapped__. Without it, every decorated function is called “wrapper” in logs and docs.
  • A decorator with arguments is three nested functions: factory takes the arguments, returns a decorator, which returns the wrapper.
  • functools.lru_cache memoises on the arguments — which requires them to be hashable, and leaks if the key space is unbounded. cache is the unbounded form.
  • Always use try/finally in a timing or resource decorator, or exceptions skip your teardown.
L3 · Advanced

Where decorators get expensive

  • Class-based decorators (__call__) hold state cleanly, but an instance is not a descriptor — decorating a method loses the automatic self binding unless you implement __get__.
  • Order with classmethod/staticmethod matters: those must be outermost, because what they wrap has to be a plain function.
  • Stacking applies bottom-up — the decorator nearest the def wraps first and ends up innermost, which is the opposite of reading order.
  • Decorators hide signatures: a bare *args, **kwargs wrapper erases the parameter list for the type checker and the IDE. ParamSpec restores it.
  • Every decorator adds a frame to the traceback and a call to the hot path. Cheap individually, visible five deep.
Part three

Types and structure

Python will run almost anything you write. The tools in this part are how a team stops it running the wrong thing: annotations a checker reads, record types that say what a value is, and an import system whose rules decide what your process actually loaded.

Python · 07

Type hints: what they do and what they do not

An annotation is data attached to a function object. The interpreter stores it and moves on. Everything useful about hints happens in a second program — mypy or pyright — that you have to run yourself.

from typing import Literal, Protocol, TypedDict

class Row(TypedDict):          # the shape of JSON you do not own
    id: int
    status: Literal["open", "closed"]

class Store(Protocol):         # structural: no base class, no registration
    def get(self, key: str) -> Row | None: ...

def load(store: Store, key: str) -> Row | None:
    return store.get(key)      # any object with a matching get() type-checks

# PEP 695 (3.12+): generic syntax with no import, T scoped to the function
def first[T](xs: list[T]) -> T:
    return xs[0]

# the older spelling, still what most of the ecosystem reads and writes
from typing import TypeVar, cast
U = TypeVar("U")

def last(xs: list[U]) -> U:
    return xs[-1]

from __future__ import annotations   # hints stop being evaluated eagerly; the default on 3.14+ (PEP 649)

def handler(req: Request) -> Response: ...  # forward reference, unquoted -- lazy annotations resolve it

n = cast(int, config.get("timeout"))  # zero run-time effect -- a lie you are asserting is true
L1 · Beginner

Annotate the boundaries first

  • Parameters and returns — def get(uid: int) -> User: is where hints pay for themselves.
  • Containers — list[int], dict[str, int], tuple[str, ...]. Built-in generics since 3.9; no typing.List needed.
  • Maybe-missing — str | None is the honest type for anything that can be absent.
  • No enforcement — passing a str where int is annotated runs exactly as before. Nothing raises.
  • Your editor already uses them — completion and go-to-definition get better the moment you add them.
L2 · Intermediate

Say more than “object”

  • Optional[X] is X | None — and a default of None does not make a parameter optional in the type sense; annotate it.
  • Any is an escape hatch — it silently switches checking off for everything it touches. object is the safe “I do not know”.
  • TypedDict — types a dict you receive from JSON without turning it into a class.
  • Literal["asc", "desc"] — catches the typo in the string argument that would otherwise reach production.
  • Protocol — structural typing: anything with the right methods fits, no inheritance. Duck typing the checker can see.
  • Ramp the strictness — start with --ignore-missing-imports, add disallow_untyped_defs per package as each one is cleaned up.
L3 · Advanced

Generics, laziness and lies

  • PEP 695 — def first[T](xs: list[T]) -> T: in 3.12+; the older TypeVar spelling still fills every codebase you will read.
  • Variance in one sentence — a list[Dog] is not a list[Animal], because you could append a cat to it; immutable Sequence[Dog] is.
  • from __future__ import annotations — annotations become strings, so forward references work and import cost drops. On 3.14+ you rarely need it: PEP 649 defers annotation evaluation by default, and forward references simply work. Anything reading annotations at run time should go through annotationlib / get_type_hints.
  • typing.cast — zero run-time effect, pure assertion to the checker. A lie you own, so leave a comment saying why it is true.
  • Different job, different tool — a checker cannot know what came off a socket. Validate that with pydantic; check the rest statically.
Python · 08

Dataclasses, NamedTuple, TypedDict, Pydantic

Four ways to say “this is a user record”. They differ on exactly four things: whether it can be mutated, whether anything is checked at run time, what it costs per instance, and whether you had to install it.

from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)
class User:
    id: int
    name: str
    tags: list[str] = field(default_factory=list)   # not tags: list = []

    def __post_init__(self) -> None:
        if self.id <= 0:                            # frozen: use object.__setattr__
            raise ValueError("id must be positive") # to normalise fields here

u = User(1, "ada")
u.name = "grace"        # FrozenInstanceError -- hashable, safe as a dict key

# NamedTuple — when tuple-ness IS the point: unpack it, hash it, index it
from typing import NamedTuple

class Point(NamedTuple):
    x: float
    y: float

p = Point(1.0, 2.0)
x, y = p                       # unpacks like any tuple
p[0]                           # 1.0 — still indexable
p._replace(x=9.0)              # returns a NEW Point; p itself never changes
{p: "origin-ish"}              # hashable out of the box, no frozen= needed
# TypedDict — for a JSON shape you do not own; a plain dict at run time
from typing import TypedDict

class UserPayload(TypedDict):
    id: int
    name: str
    tags: list[str]

def greet(u: UserPayload) -> str:
    return f"hello {u['name']}"    # dict access, not attribute access

raw: UserPayload = {"id": 1, "name": "ada", "tags": []}
raw["naem"] = "typo"               # mypy/pyright catch this; nothing does at run time
greet({"id": 1})                   # also only a type-checker error — TypedDict never runs
# BaseModel — the same record, but arriving from outside and needing to be believed
from pydantic import BaseModel, Field, ValidationError

class User(BaseModel):
    id: int = Field(gt=0)
    name: str
    tags: list[str] = []           # pydantic copies the default per instance — safe here

try:
    u = User.model_validate({"id": "1", "name": "ada"})  # "1" coerced to 1
except ValidationError as e:
    log.warning("bad user payload: %s", e.errors())

u.model_dump()                     # -> plain dict, JSON-safe with mode="json"

Records make tagged unions, and match (3.10+) is how you consume one — the checker narrows each arm, and assert_never turns “forgot a variant” into a type error instead of a production bug:

# dispatch on a tagged union: match narrows, assert_never proves exhaustiveness
from dataclasses import dataclass
from typing import assert_never

@dataclass
class Created:
    id: int

@dataclass
class Deleted:
    id: int
    reason: str

def apply(ev: Created | Deleted) -> str:
    match ev:
        case Created(id=i):            return f"created {i}"
        case Deleted(id=i, reason=r):  return f"deleted {i}: {r}"
        case _:                        assert_never(ev)  # unreachable -- or the union grew
L1 · Beginner

Stop passing dicts around

  • A dict has no shape — user["nmae"] is a KeyError at 2am; user.nmae is caught by the checker and your editor.
  • @dataclass — write the fields with their types and you get __init__, __repr__ and __eq__ for free.
  • Defaults work as expected — retries: int = 3, and required fields must come before defaulted ones.
  • The repr matters — a dataclass prints as User(id=1, name='ada'), which is most of a debugging session.
  • It is still a normal class — add methods, inherit, use it anywhere.
L2 · Intermediate

The four arguments that matter

  • field(default_factory=list) — the mutable-default trap again; a bare [] as a class-level default is a ValueError from dataclasses, and a shared list everywhere else.
  • frozen=True — assignment raises, and the instance becomes hashable. Good default for anything you pass between threads.
  • slots=True — no per-instance __dict__: less memory, faster attribute access, no typo-attributes.
  • __post_init__ — derived fields and cheap invariants, run after __init__ assigns.
  • NamedTuple — when tuple-ness is the point: unpacking, use as a dict key, returning from a function that used to return a plain tuple.
  • TypedDict — for a JSON shape you do not own. It is a dict at run time; the types exist only for the checker.
L3 · Advanced

Validate at the edge, trust inside

  • Pydantic belongs at the boundary — HTTP body, queue message, config file, third-party response. Parse once, into a typed object.
  • Do not validate in a loop — re-validating an already-parsed model on every internal hop buys nothing and shows up in profiles.
  • v2 does the work in Rust — much faster than v1, but still far more expensive than a dataclass constructor, which does almost nothing.
  • attrs — the library dataclasses came from; still ahead on validators, converters and __slots__ ergonomics.
  • The rule — untrusted data crosses exactly one line in your codebase. After that line it is a typed record, and no function downstream defends itself.

Modules, packages, imports and environments

import orders is a search, an execution and a cache, in that order. Knowing those three steps explains import side effects, why the second import is free, and why a circular import fails with an attribute error rather than a clear message.

# what `import payments.charge` actually does, once per process
import sys
sys.path       # searched in order; "" means the current directory, first
sys.modules    # the cache — every later import is just a dict lookup

# payments/config.py — a module body runs exactly once, at first import
print("configuring")        # printed once, however many modules import it
SETTINGS = load_settings()  # module-level state is a singleton by accident

# the guard: this file can be imported as a library AND run as a script
if __name__ == "__main__":
    main()

# circular imports fail halfway through, not at the import line:
#   ImportError: cannot import name 'Order' from partially initialized

One environment per project

  • Module vs package — a module is a .py file; a package is a directory of them, importable as a unit.
  • Import forms — import orders, from orders import Order, import orders as o. Avoid from x import *: the reader cannot tell where a name came from.
  • if __name__ == "__main__": — the guard that makes a file both importable and runnable, and stops multiprocessing re-running your script.
  • A virtual environment per project — python -m venv .venv, or let uv manage it. It is a directory with its own interpreter and its own packages.
  • Never install globally — two projects will eventually want two versions of the same library, and system Python belongs to the system.
L2 · Intermediate

Make the environment reproducible

  • Absolute imports — from myproj.orders import Order reads the same from anywhere. Keep relative imports (from .orders import Order) shallow if you use them at all.
  • sys.modules is the cache — re-importing gives you the same object. Monkeypatching in tests and reload tricks both hang off this.
  • Import side effects — anything at module level runs on import. Keep it to constants and definitions; put work in functions.
  • pyproject.toml — one file for dependencies, build backend, and tool config (ruff, mypy, pytest).
  • Pin and lock — loose ranges for a library you publish, an exact lockfile for an application you deploy.
  • pip vs uv — same package format; uv resolves and installs an order of magnitude faster and manages the venv and lockfile itself.

Break the cycle, watch the clock

  • Three fixes for a circular import — move the shared type to its own module, import inside the function that needs it, or accept the dependency is backwards and invert it.
  • if TYPE_CHECKING: — imports needed only for annotations, skipped at run time. Pairs with from __future__ import annotations.
  • The src layout — putting the package under src/ means tests import the installed package, not the working copy that happens to be on sys.path.
  • Editable installs — pip install -e . puts a link on the path, so edits take effect without reinstalling.
  • Namespace packages — a directory without __init__.py can still be a package split across distributions. Usually a surprise rather than a plan.
  • Import time is start-up cost — python -X importtime -c "import myproj" prints the tree with microseconds per module. A lazily imported heavy dependency is often the whole fix.
Part four

Errors and resources

Python asks forgiveness rather than permission: you attempt the operation and handle the exception. That is idiomatic and it is race-free, but it only works if the handler catches what it can actually deal with — and if the file, socket or transaction is released whichever way control leaves the block.

Python · 10

Exceptions, EAFP, and chaining

Four clauses, four different jobs. else is the part of the body that must not be inside the try; finally is the part that runs whatever happens, including on the way out of a return.

import contextlib

class Transient(Exception): ...    # worth a retry: timeout, 503, connection reset
class Terminal(Exception): ...     # never retry: 400, 403, bad payload

def fetch(url: str) -> bytes:
    try:
        return http.get(url)
    except TimeoutError as err:
        raise Transient(f"timeout: {url}") from err
    except PermissionError as err:
        raise Terminal(f"forbidden: {url}") from err

with contextlib.suppress(FileNotFoundError):
    os.remove(tmp)                 # "already gone is fine" -- not a bare except

# all four clauses, each with a job try/except alone cannot do
def load_batch(path: str) -> list[Row]:
    try:
        fh = open(path)
    except FileNotFoundError:
        return []                  # handled: an empty batch is a valid outcome
    else:
        with fh:                   # only runs if open() did NOT raise; the with
            return parse(fh)       # closes fh even if parse() raises -- next topic
    finally:
        log.info("load_batch done: %s", path)    # always -- even on the return above
L1 · Beginner

Catch what you can handle

  • The hierarchy — everything derives from BaseException; the errors you mean are under Exception. ValueError, KeyError, OSError are the ones you meet daily.
  • Be specific — except ValueError:, not except Exception:. A handler that catches everything hides the bug you have not found yet.
  • Never a bare except: — it catches KeyboardInterrupt and SystemExit too, so Ctrl-C stops working.
  • else — runs only when the try raised nothing; keeps the success path out of the guarded block.
  • finally — runs on every exit path. Cleanup goes here, or better, in a with.
L2 · Intermediate

EAFP, and errors with meaning

  • EAFP beats LBYL — try: open(p) against if os.path.exists(p): the check-then-act version has a race, and does the work twice.
  • Custom exception types — one base class per package, so callers can catch your errors without catching everything.
  • raise NewError(...) from err — translation with the cause attached. The default implicit chaining is fine too; the anti-pattern is from None.
  • contextlib.suppress(FileNotFoundError) — says “I expect this and it is fine” in one line, and cannot accidentally swallow more.
  • Exceptions as control flow — StopIteration ends every for loop, KeyError drives defaultdict. Idiomatic here, unlike most languages.
  • Log with the traceback — logging.exception(...) inside the handler; a logged message without a traceback is half an incident report.
L3 · Advanced

Groups, cost, and taxonomy

  • ExceptionGroup and except* — 3.11+. A TaskGroup where three tasks fail raises all three; except* handles each type and re-raises the rest.
  • Cost on hot paths — setting up a try is nearly free; raising is not. Building a traceback in a per-row loop is measurable, so a sentinel return can win there.
  • Taxonomy drives retries — transient (timeout, 503, deadlock) retries with backoff and jitter; terminal (400, 403, schema error) must not, or you have built a retry storm. The same split as the Go and foundations pages.
  • Do not catch BaseException — that is where KeyboardInterrupt, SystemExit and asyncio.CancelledError live. Catching them breaks shutdown and cancellation.
  • Retries need idempotency — a timeout does not tell you whether the write landed. Retry only what carries an idempotency key.

Context managers and deterministic cleanup

with is syntax for a try/finally that someone else wrote and tested. The release runs on the exception path as well as the happy one, which is the entire reason the statement exists.

import contextlib, logging, time

@contextlib.contextmanager
def timed(label: str):
    start = time.perf_counter()
    try:
        yield                       # the body of the with block runs here
    finally:                        # runs on the exception path too
        ms = (time.perf_counter() - start) * 1000
        logging.info("%s took %.1f ms", label, ms)

with timed("query"), conn.transaction():    # left to right in, right to left out
    rows = conn.fetch_all(sql)
L1 · Beginner

Use with for anything you open

  • with open(path) as f: — the file closes when the block ends, however it ends.
  • Why it matters — if json.load(f) raises halfway, the file still closes; a plain f.close() at the end of the function never runs.
  • Not just files — sockets, locks, database connections and transactions, tempfile, subprocess.Popen.
  • Several at once — with open(a) as src, open(b, "w") as dst: in one statement, entered left to right.
  • The as target — is whatever __enter__ returns, which is not always the manager itself.
L2 · Intermediate

Write your own

  • The protocol — __enter__(self) returns the resource; __exit__(self, exc_type, exc, tb) releases it and returns falsy to let any exception through.
  • @contextlib.contextmanager — one function, one yield. Everything before is setup, everything after is teardown.
  • Wrap the yield in try/finally — without it, an exception in the body skips your teardown entirely. This is the bug in most hand-written generators.
  • ExitStack — for a number of resources known only at run time: stack.enter_context(open(p)) in a loop, all unwound together.
  • closing, suppress, redirect_stdout — contextlib already has the adapters you were about to write.
  • Also a decorator — a ContextDecorator can be applied to a whole function with @timed("x").
L3 · Advanced

Reentrancy, async, and suppression

  • Generator-based managers are single-use — re-entering one raises. If you need reuse, write the class, or use contextlib.nullcontext for the optional case.
  • async with — __aenter__ and __aexit__, built with @asynccontextmanager. A connection pool acquire that awaits needs this; a sync manager holding an await is how you block the loop.
  • AsyncExitStack — the same dynamic unwinding for coroutine resources.
  • Returning True suppresses — legitimate for suppress, wrong almost everywhere else: it silently converts a failure into a success.
  • Cleanup can raise — an exception in __exit__ replaces the one in flight, with the original as its context. Keep teardown boring.
  • Refcounting is not a resource policy — deterministic close is a CPython accident that PyPy does not share, and one stray reference removes it on CPython too.
Part five

Concurrency, and where Python is different

Every other page in this series treats threads as the default unit of parallelism. Python does not, because one lock inside the interpreter decides who executes bytecode. Understand that lock and the rest — threads, processes, asyncio — stops being folklore and becomes a straightforward choice.

Python · 12

The GIL: what actually runs in parallel

One lock per interpreter, held by whichever thread is executing bytecode. Threads still interleave, and they still overlap perfectly while waiting on I/O — but four CPU-bound threads on four cores finish no sooner than one.

# the same work, three pools — the numbers are the whole argument
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

# CPU-bound: threads take turns holding the GIL, so nothing is gained
with ThreadPoolExecutor(8) as ex:
    list(ex.map(tokenise_row, rows))      # 4.1 s on 8 cores -- pure Python

# CPU-bound: separate interpreters, separate GILs, real parallelism
with ProcessPoolExecutor(8) as ex:
    list(ex.map(tokenise_row, rows))      # 0.6 s — and pickling costs

# I/O-bound: the GIL is released around the syscall, so threads are fine
with ThreadPoolExecutor(32) as ex:
    list(ex.map(fetch, urls))             # 32 sockets, one core, no problem

# and from async code, the escape hatch for one blocking call:
row = await asyncio.to_thread(legacy_driver.query, sql)
L1 · Beginner

One lock, one runner

  • What it is — a mutex inside CPython that a thread must hold to execute bytecode.
  • Threads do not speed up CPU work — four threads summing numbers take as long as one, plus switching overhead.
  • Threads do help I/O — waiting on a socket or a disk releases the lock, so twenty requests can be in flight at once.
  • They are still real OS threads — pre-emptive, so shared state still needs a lock of your own.
  • Measure before choosing — if the profile is dominated by waiting, you have an I/O problem and the GIL is irrelevant.
L2 · Intermediate

Pick the executor by the profile

  • ThreadPoolExecutor — the answer for I/O: HTTP fan-out, S3 uploads, a few dozen database calls.
  • ProcessPoolExecutor — the answer for CPU: image work, parsing, compression, anything numeric without NumPy.
  • Pickling is the process tax — arguments and results are serialised. Sending a 200MB dataframe to each worker can cost more than the work.
  • concurrent.futures — one API for both, so switching is a one-word change. as_completed for results in finishing order.
  • Chunk the work — per-item tasks in a process pool are dominated by round-trip overhead; hand each worker a batch.
  • Never an unbounded pool — the same rule as everywhere else in this series: fix the worker count, and let the queue absorb the burst.
L3 · Advanced

Escaping the lock

  • C extensions release it — NumPy, Pillow, zlib, hashlib, and most database drivers drop the GIL around their heavy call, so threads over those really are parallel.
  • Free-threaded CPython (PEP 703) — builds with no GIL: experimental in 3.13, officially supported since 3.14 (PEP 779). Real thread parallelism, a single-thread cost that has shrunk to a few percent, and an ecosystem of C extensions still being rebuilt and re-audited for thread safety. Watch it seriously; default production stays on the GIL build for now.
  • Subinterpreters (PEP 734) — a per-interpreter GIL in one process: isolation like processes, without the fork cost. In the stdlib as concurrent.interpreters since 3.14; still young in library support.
  • Shared memory — multiprocessing.shared_memory or memory-mapped arrays move large buffers between processes without pickling them.
  • The honest summary — the GIL serialises bytecode, not I/O. Say which of those your workload is made of before you argue about it.
Python · 13

asyncio: one thread, many waits

The event loop runs one task until it awaits something, then runs another. Thousands of sockets on one thread, with no locks — and one synchronous call in the wrong place freezes every task at once.

import asyncio, httpx

async def fetch_all(urls: list[str]) -> list[bytes]:
    sem = asyncio.Semaphore(20)                  # bound the fan-out

    async with httpx.AsyncClient() as client:
        async def one(u: str) -> bytes:
            async with sem:                      # at most 20 in flight
                r = await client.get(u)
                return r.content

        async with asyncio.timeout(30):          # the whole batch, not each call
            return await asyncio.gather(*(one(u) for u in urls))

asyncio.run(fetch_all(urls))
L1 · Beginner

A coroutine is a plan, not a thread

  • async def returns a coroutine — calling it runs nothing. Forgetting the await is a warning and a function that never happened.
  • await yields control — it says “I am waiting; run someone else”, and resumes when the result is ready.
  • asyncio.run(main()) — one entry point per program: it creates the loop, runs the coroutine, and shuts the loop down.
  • Concurrency, not parallelism — one thread the whole time. It wins by never waiting idly, not by using more cores.
  • Async is contagious — only a coroutine can await, so an async call at the bottom pulls async all the way up the stack.
L2 · Intermediate

Run many, bound them, cancel them

  • gather vs TaskGroup — gather collects results; TaskGroup (3.11+) also guarantees that when one task fails the rest are cancelled and awaited. Prefer it for new code.
  • asyncio.timeout(s) — a context manager that cancels whatever is inside. Cleaner than threading a deadline through every call.
  • Cancellation is an exception — CancelledError is raised at the await point, so cleanup belongs in finally, and you must not swallow it.
  • Never block the loop — no time.sleep, no requests, no big json.loads, no synchronous database driver.
  • asyncio.to_thread(fn, *args) — the one-line adapter for a sync library you cannot replace.
  • Semaphore(n) — launching 10,000 coroutines at a service that handles 50 is not concurrency, it is a denial-of-service test. Bound the fan-out, every time.
L3 · Advanced

The sharp edges

  • Coloured functions — sync and async are two ecosystems: requests and httpx, psycopg sync and async. Choosing async is choosing a dependency stack.
  • Keep a reference to your tasks — the loop holds only a weak one, so a bare asyncio.create_task(...) can be garbage collected mid-flight. Store it in a set and discard on completion, or use a TaskGroup.
  • loop.run_in_executor — what to_thread wraps; use it directly to target a process pool for CPU-bound work.
  • Structured concurrency — a TaskGroup block cannot exit with children still running. The same discipline as an errgroup in Go, enforced by the language.
  • Back-pressure — a bounded asyncio.Queue makes the producer wait when consumers fall behind. An unbounded one turns a slow consumer into a memory leak.
  • Debugging — asyncio.run(main(), debug=True) logs coroutines that hold the loop too long. It finds the blocking call in minutes.

Part six

Memory and speed

Python costs roughly 10–100× a compiled language per operation, and every value is a heap object with a header. Neither fact is fixable by rewriting a loop more cleverly. What is fixable: doing fewer operations, holding fewer objects, and knowing which measurement answers which question.

Python · 15

How CPython holds an object, and what that costs

Every value is a separately allocated heap object carrying a reference count and a type pointer, and every container holds pointers to those objects rather than the values themselves. That is why an int is 28 bytes and a list of a million of them is not eight megabytes.

import sys

sys.getsizeof(1)             # 28   -- refcount, type, size, one digit
sys.getsizeof(2**64)         # 36   -- three 30-bit digits now
sys.getsizeof("hello")       # 54   -- 49 of header, 1 byte per ASCII char
sys.getsizeof([0] * 1000)    # 8056 -- 56 header + 8 per slot, and nothing else

xs = [1234 + i for i in range(1_000_000)]
sys.getsizeof(xs)                    # about 8.4 MB: the pointer array only
sum(sys.getsizeof(x) for x in xs)    # about 28 MB more: what it points at

class Point:                         # a dict per instance, any attribute allowed
    def __init__(self, x: float, y: float) -> None:
        self.x, self.y = x, y

class Slim:

    def __init__(self, x: float, y: float) -> None:
        self.x, self.y = x, y
# a cycle: refcounting alone never frees this pair -- only the collector can
class Node:
    def __init__(self, name: str) -> None:
        self.name, self.parent, self.children = name, None, []

    def add(self, child: "Node") -> None:
        child.parent = self          # parent -> child -> parent: a cycle
        self.children.append(child)

L1 · Beginner

Objects, references, and a shallow ruler

  • Everything is a heap object — an int, a string, a function, a class — each carrying a reference count and a type pointer before any data.
  • Containers hold references. Copying a list copies pointers, which is why b = a[:] gives you a new list of the same objects.
  • sys.getsizeof is shallow: it measures the container itself, not the objects it refers to.
  • Small ints (−5 to 256) and some short strings are cached, so is occasionally looks true by accident. Compare with ==.
  • Two numbers worth memorising: an int is 28 bytes, a list slot is 8.
L2 · Intermediate

Hold fewer objects, and smaller ones

  • __slots__ on classes you create by the hundred thousand: fixed offsets instead of a per-instance dict, and a misspelt attribute becomes an error instead of a new field.
  • Lists over-allocate on growth, which is what makes append amortised O(1) — so append in a loop is rarely the thing to fix.
  • Generators and yield stream a pipeline instead of materialising each stage; peak memory becomes one item rather than n.
  • array.array, bytes, memoryview for homogeneous data: one contiguous buffer of values instead of n pointers to n objects.
  • sys.intern for strings you compare or key on constantly — identical objects short-circuit the character-by-character compare.
L3 · Advanced

Refcounts, cycles, and RSS that never falls

  • Reference counting frees immediately; the generational collector exists only for cycles. Deterministic release is why with works so well and why a stray reference in a traceback keeps a whole object graph alive.
  • gc.freeze() after imports and before fork(): the collector otherwise touches the refcount of every shared object, un-sharing copy-on-write pages until each worker owns a private copy of your imports.
  • weakref and WeakValueDictionary for caches and observer registries, so the cache is not the leak.
  • RSS does not fall after a spike. Freed memory returns to CPython’s arenas, not the OS, and one live object pins a whole arena. Fragmentation looks exactly like a leak on a graph.
  • Where Python stops being the answer: a million small records wants NumPy or a columnar buffer; a leak you cannot find wants a worker process recycled every N requests.

Measure before you change anything

  • Never optimise what you have not timed. Intuition about which Python line is slow is wrong roughly half the time.
  • time.perf_counter() for durations: monotonic, and the highest resolution the platform offers.
  • time.time() is the wrong clock — it is a wall clock that NTP can step backwards, so a duration computed from it can come out negative.
  • timeit for anything under a millisecond: it runs the snippet many times and reports the best, because the mean is mostly noise from other processes.

  • cProfile to a file, then pstats sorted by cumulative time. Cumulative finds the expensive subtree; tottime finds the expensive function itself.
  • Read the call tree downwards. The leaf with the huge tottime is often a stdlib function called two million times — the fix is in the caller, not the leaf.
  • tracemalloc snapshots and compare_to for growth: it names the allocating line, which a total heap size never does.
  • line_profiler (kernprof -l) when the hot function is forty lines and the cost is one of them.

L3 · Advanced

Sampling, the observer effect, and the ladder

  • Deterministic profilers instrument every call. cProfile costs 2–3× and distorts exactly the many-small-calls code you were investigating — you profile the profiler.
  • Sampling profilers read stacks from outside the process at a fixed rate: small constant overhead, nothing imported into your app, safe to attach to a live pod. py-spy record for a flame graph, py-spy dump for a hung process.
  • The ladder, in order: a better algorithm → fewer Python-level operations → vectorise with NumPy → a C extension or Rust via PyO3 → another process or another language.
  • Skipping rungs wastes weeks. A Rust extension wrapped around a quadratic algorithm is still quadratic, and now nobody on the team can change it.
  • The honest baseline: the interpreter costs roughly 10–100× a compiled language per operation. That gap is why the winning move is almost always to perform fewer operations, not faster ones.

Environments, resolution, and lockfiles

A dependency range says what is allowed. A lockfile says what you actually got. Projects that ship only the first one discover the difference when CI and a laptop resolve the same range to different versions on different days.

Never install into the system Python

  • Virtual environment — a directory with its own site-packages; activating it just puts its bin/ first on PATH.
  • One env per project, never shared. Deleting .venv and recreating it should always be safe — if it is not, something is undeclared.

  • .venv/ goes in .gitignore; the lockfile does not. PEP 751’s pylock.toml is the standard lockfile format — uv and pip can export and consume it, so the lock is no longer tool-proprietary.
  • Learn python -m pip, not bare pip — the -m form guarantees you are installing into the interpreter you think you are.
L2 · Intermediate

Commit the lockfile, install from it

  • Ranges in the manifest, exact versions in the lock. Loosen the range when you want an upgrade; regenerate the lock deliberately, in its own commit.
  • --frozen in CI and Docker — installs must fail rather than silently re-resolve when the lock is stale.
  • Extras and groups — test and lint dependencies live in a dev group so they never reach the production image.
  • Applications lock; libraries do not. A library publishes ranges, because pinning inside a library makes it uninstallable alongside anything else.
  • Pin the Python version too — requires-python plus a .python-version file.
L3 · Advanced

Understand what the resolver is doing

  • Resolution is a SAT problem over the whole graph. Backtracking resolvers can take minutes on a conflict, and the error names the pair that is unsatisfiable — read it rather than deleting pins at random.
  • Wheels vs sdists — a wheel is a prebuilt zip; falling back to an sdist means compiling on the target machine and needing a toolchain in your image.
  • Platform tags (manylinux, musllinux, macosx_arm64) decide which wheel you get. Alpine images miss manylinux wheels and rebuild from source — a common reason a Docker build is fifteen minutes.
  • Hash-pinned installs (--require-hashes) make a compromised index unable to substitute an artefact.
  • Multi-stage images — resolve and build in one stage, copy only site-packages into a slim runtime stage.

Formatting stopped being a discussion when black shipped with no options. Linting stopped being five tools when ruff reimplemented them in one binary. What is left to decide is where the checks run — and the answer is all three places, with identical configuration.

The one rule set worth turning on deliberately

L1 · Beginner

Stop formatting by hand

  • Formatter — rewrites layout deterministically. ruff format is black-compatible; the output is not a matter of taste, and that is the feature.
  • Linter — finds likely mistakes: unused imports, undefined names, shadowed builtins, comparisons that are always true.
  • PEP 8 is the style baseline — but you should never be applying it manually.
  • Turn on format-on-save the day you start. Every formatting comment in a review is a wasted one.
  • ruff check --fix applies the safe fixes; read the diff before committing it.
L2 · Intermediate

Make the gate automatic

  • pre-commit — a hook manager with pinned tool versions in .pre-commit-config.yaml. pre-commit autoupdate bumps them in a reviewable commit.
  • Pin the linter version. An unpinned linter turns a new release into a red build on an unrelated PR.
  • Adopt on a large codebase by reformatting everything in one commit, then adding that SHA to .git-blame-ignore-revs so blame still works.
  • Select rules explicitly. select a named set rather than everything — a wall of warnings nobody triages is the same as no linter.
  • noqa needs a code and a reason: # noqa: S105 - test fixture, not a real key.
L3 · Advanced

Know what a linter cannot see

  • Lint is syntactic, types are semantic. Ruff will not tell you a function returns None on one branch; a type checker will. They are different gates, both needed.
  • Custom rules — when a bug class recurs, encode it: an AST check in CI, or a flake8 plugin. A rule that fires automatically beats a convention nobody remembers.
  • Security lint (bandit, ruff’s S rules) flags subprocess(shell=True), weak hashes and hard-coded secrets. High false-positive rate; still worth the triage.
  • Complexity budgets (C901, PLR0912) are blunt but real — they surface the function that needs splitting before a reviewer has to say it.
  • Formatter migrations change diffs, not behaviour. Do them alone, never inside a feature branch.

Type checking as a gate, not a hope

Annotations do nothing at run time. They are worth writing anyway — but only once something actually checks them, in CI, on every commit. The hard part is not the syntax; it is adopting a checker on a codebase that has none without stopping the world.

L1 · Beginner

Annotate the boundaries first

  • Function signatures pay for themselves. Parameters and return type on every public function; local variables almost never need one.
  • Install the checker as a dev dependency and run it locally — mypy . or pyright. Your editor is already running one, quietly.
  • None is a type. str | None is the single most useful annotation in the language, because it forces the caller to handle the missing case.
  • Do not annotate for the sake of it: x: int = 0 tells nobody anything.

L2 · Intermediate

Ratchet, and never go backwards

  • Per-module overrides keep the legacy corner listed by name, so the exceptions are visible and shrinking rather than a blanket ignore.
  • warn_unused_ignores turns stale suppressions into errors — the ratchet that stops the exception list growing quietly.
  • Protocol over inheritance for typing duck-typed arguments — the direct analogue of a Go interface, satisfied structurally.
  • Type the data at the edge — Pydantic at the boundary, plain dataclasses inside. The checker is only as good as the point where untyped data becomes typed.
  • Run the checker in CI on the whole tree, not just changed files — a change in one module breaks types in another.
L3 · Advanced

Where the type system gets interesting

  • TypeVar, ParamSpec, Concatenate — how a decorator keeps its wrapped function’s signature instead of collapsing it to (*args, **kwargs).
  • overload for functions whose return type depends on argument types, and Literal for the flags that select between them.
  • Narrowing — isinstance, assert, and TypeGuard/TypeIs teach the checker facts it cannot infer; match statements narrow too.
  • Variance bites in real code: list[Dog] is not a list[Animal], because you could append a Cat. Accept Sequence when you only read.
  • Any is contagious — it silences errors downstream of itself. --disallow-any-explicit and object plus narrowing are the honest alternatives.

Layout, naming, and version numbers

Two directory layouts are common and one of them lets your tests import a copy of the code that will never be installed. The naming conventions are trivial to learn and instantly visible in review, which is exactly why they are worth getting right.

Version numbers

SemVer (2.4.1) is the ecosystem default; CalVer (2026.8.1) is common for applications and tools where dates mean more than compatibility promises. Python’s own rules live in PEP 440, which also defines pre-releases (1.0.0rc1), post-releases and the ~= compatible-release operator.   • src/ makes the installed package the only importable one, so pip install -e . plus pytest tests the real artefact.

  • Entry points in pyproject.toml give you console scripts and plugin discovery without an import-everything scan.
  • Trusted publishing to PyPI via OIDC removes the long-lived API token from CI entirely — the same identity-federation idea as IRSA on EKS.

Reach for the standard library first

L2 · Intermediate

Know the default and why it won

  • FastAPI + pydantic + SQLAlchemy + pytest is the modern service stack; Django is the other coherent answer, and mixing the halves of the two is the usual mistake.

What “idiomatic” means in review

Idiomatic Python is not a style preference. Each of these rewrites removes a way for the code to be wrong — an index that can drift, a resource that can leak, an exception that can vanish. That is why reviewers keep asking for them.

The Zen, minus the poetry

import this prints nineteen lines. Three of them do real work in review. Explicit is better than implicit — pass the dependency, do not reach for a global. Flat is better than nested — guard clauses and early returns instead of an arrowhead of ifs. Errors should never pass silently — the one that except Exception: pass violates every time.

Idioms that have quietly expired

Let the language do the work

  • Iterate objects, not indices; enumerate when you genuinely need the position, zip when you have two sequences.
  • Comprehensions for transform-and-filter, a loop for anything with side effects. If it needs a comment to read, make it a loop.

L2 · Intermediate

Structure the function itself

  • Guard clauses first. Handle the impossible cases and return, so the happy path is at one indent level and reads top to bottom.
  • Return one type. A function that returns a dict, or None, or raises, has three contracts and no callers who handle all of them.
  • Keyword-only arguments (* in the signature) for booleans and options — charge(amount, retry=True) reads; charge(amount, True) does not.
  • Small, pure core; thin, effectful shell. Push I/O to the edges and the middle becomes trivial to test.
  • Docstring the why. The what is in the signature and the types; the why is the only thing a reader cannot reconstruct.
L3 · Advanced

Know when to stop being clever

  • Metaclasses, __getattr__ magic and dynamic imports all work, and all defeat the type checker, the IDE and the next reader. The bar is high and it is rarely met.
  • Prefer composition and Protocol to deep inheritance; Python’s MRO is well defined and still nobody wants to reason about it at 3am.
  • Make illegal states unrepresentable — frozen dataclasses, enums instead of string flags, and a parsed type at the boundary rather than a validated dict passed onward.
  • Consistency beats personal preference. In an existing codebase, the local convention wins; change it deliberately and everywhere, or not at all.
  • Optimise for the reader who is on call. The next person to open this file will be tired, in a hurry and looking for one specific thing. Clever code charges them at exactly the worst moment.

Parsing an untrusted payload with Pydantic

from decimal import Decimal
from typing import Annotated, Literal, Self
from pydantic import BaseModel, ConfigDict, EmailStr, Field, field_validator, model_validator

Money = Annotated[Decimal, Field(gt=0, max_digits=12, decimal_places=2)]
Sku   = Annotated[str, Field(pattern=r"^[A-Z]{3}-\d{4}$")]

class LineItem(BaseModel):
    sku: Sku
    qty: Annotated[int, Field(ge=1, le=100)]
    price: Money

    note: str | None = None

    def strip_and_bound(cls, v: str | None) -> str | None:

L1 · Beginner

What the code does

  • BaseModel turns annotations into run-time checks — the one place in Python where a type hint has teeth.
  • Field carries the constraints: gt, ge, le, min_length, pattern. They land in the JSON schema too.
  • model_validate takes a dict and returns an instance or raises; model_dump goes back the other way.
  • Annotated[Decimal, Field(...)] names a reusable rule — Money is now one word you can put on any field.
  • ValidationError.errors() is a list of dicts, not a string. Return it as the response body.
L2 · Intermediate

Why it is written this way

  • extra="forbid" makes a typo in the client an error instead of a silently ignored field — the default is to drop unknown keys, which hides bugs for months.
  • frozen=True makes the parsed request immutable, so no later code can “fix up” the input and leave the log disagreeing with what happened.
  • Decimal for money, never float — and pydantic will coerce the string "12.50" straight to Decimal without going through binary floating point.
  • field_validator for one field, model_validator(mode="after") for a rule that needs several; mode="after" means every value is already the right type.
  • Separate the request model from the database model. They change for different reasons, and merging them is how internal columns end up in your public API.
L3 · Advanced

What bites in production

  • Validation is not free. v2’s core is Rust and fast, but validating the same object at four internal layers is four times the cost for no extra safety. Parse once, at the edge.
  • model_construct skips validation for data you already trust — useful on a hot path out of the database, dangerous anywhere near a socket.
  • Union order matters. Prefer a discriminated union (Field(discriminator="kind")) over a bare A | B: it picks by tag rather than by trying each in turn, and the errors name one branch instead of all of them.
  • ValidationError messages can leak input. Return type and loc to the caller; keep input for your logs, and never let a SecretStr reach either.
  • Generated schemas are a contract. If clients consume your OpenAPI, adding extra="forbid" or tightening a pattern is a breaking change — version it like one.

One endpoint, end to end

The job: accept an order, write it once, and return an answer the caller can retry safely. Four layers, each owning exactly one thing — and the transaction boundary drawn so a raised exception cannot leave half an order behind.

# deps.py — one session and one transaction per request
async def get_session() -> AsyncIterator[AsyncSession]:
    async with SessionLocal() as session:      # closes, returns to the pool
        async with session.begin():            # COMMIT on clean exit,
            yield session                      # ROLLBACK on any exception
# routes.py — HTTP shapes in, HTTP shapes out, nothing else
router = APIRouter(prefix="/orders", tags=["orders"])

class OrderCreated(BaseModel):        # response contract ≠ request contract
    id: UUID
    status: Literal["accepted"]
    total: Decimal

@router.post("", status_code=201, response_model=OrderCreated)
async def create_order(
    body: CreateOrder,                                  # validated already
    idem_key: Annotated[str, Header(alias="Idempotency-Key")],
    session: Annotated[AsyncSession, Depends(get_session)],
) -> OrderCreated:
    try:
        order = await orders.place(session, body, idem_key)   # INSERT inside session.begin_nested()
    except orders.DuplicateKey as e:
        order = await orders.get(session, e.existing_id)  # same answer
    except orders.OutOfStock as e:
        raise HTTPException(409, str(e)) from e           # keeps the cause
    return OrderCreated(id=order.id, status="accepted", total=order.total)
L1 · Beginner

What the code does

  • The type hints are the wiring. body: CreateOrder means “parse the JSON body into this”; Header(...) means “read this header”.
  • Depends(get_session) runs the dependency, hands you what it yields, and resumes it after the response.
  • The savepoint is load-bearing. A unique-key violation aborts a plain Postgres transaction — every later statement fails with InFailedSQLTransaction. Because place() wraps its INSERT in session.begin_nested(), only the savepoint rolls back, and the orders.get on the next line still runs inside a healthy transaction.
  • response_model filters the response through a second model, so an internal field cannot leak by accident.
  • raise HTTPException(409, ...) is how you choose a status code deliberately.
  • from e keeps the original traceback attached — the chained cause you saw in the exceptions topic.
L2 · Intermediate

Why it is written this way

  • The route knows HTTP; the domain does not. orders.place raises OutOfStock, never HTTPException — so the same function works from a worker, a CLI and a test.
  • Yield-style dependencies own the resource. The async with pair means the transaction cannot outlive the request, no matter how the handler exits.
  • Request and response models are separate classes even when they look alike today; they diverge the first time you add an internal field.
  • Idempotency is a database constraint, not an if. A unique index on the key is the only version that survives two concurrent retries.
  • A duplicate is not an error. Returning the original answer is what makes a client retry safe, which is what makes at-least-once delivery workable.
L3 · Advanced

What bites in production

  • One blocking call poisons the loop. A synchronous driver, time.sleep or a CPU-heavy hash inside an async def stalls every other request on that worker — asyncio.to_thread or a sync def endpoint instead.
  • The client can vanish mid-request. A disconnect cancels the task and raises CancelledError inside your handler; the rollback is correct, but any external side effect already sent is not undone.
  • Long transactions hold locks. Do not call another service inside session.begin() — a two-second HTTP timeout becomes a two-second row lock.
  • The dependency’s COMMIT runs after the response is sent — FastAPI resumes yield dependencies once the body is out the door. If the caller must be able to trust the 201, commit explicitly in the handler before returning, and keep the dependency as the rollback-on-error backstop.
  • Pool sizing is a total, not a per-worker setting. Eight workers × a pool of 20 is 160 connections; Postgres’s default max_connections is 100.
  • Validation errors are a 422 by default, which many clients treat as unretryable — deliberate, and worth documenting rather than discovering.

Calling another service without hanging

The job: call an internal API, survive its bad minutes, and never become the reason your own workers are all stuck. Two numbers decide everything — the per-attempt timeout and the total budget the caller is willing to wait.

# client.py — one client for the process, not one per call
TIMEOUT = httpx.Timeout(connect=1.0, read=2.0, write=2.0, pool=1.0)
LIMITS  = httpx.Limits(max_connections=100, max_keepalive_connections=20)

client = httpx.AsyncClient(base_url="https://ledger.internal",
                           timeout=TIMEOUT, limits=LIMITS)
# a fresh AsyncClient per call throws away the connection pool and the
# TLS session, and turns a 2 ms call into a 40 ms one

class Retryable(Exception): ...      # 5xx, timeouts: worth another try
class Permanent(Exception): ...      # 4xx: retrying cannot help

@retry(stop=stop_after_attempt(3),
       wait=wait_exponential_jitter(initial=0.1, max=1.0),   # jitter matters
       retry=retry_if_exception_type((httpx.TransportError, Retryable)),
       reraise=True)
async def post_entry(entry: LedgerEntry, idem_key: str) -> LedgerRef:
    r = await client.post("/entries", json=entry.model_dump(mode="json"),
                          headers={"Idempotency-Key": idem_key})
    if r.status_code >= 500:
        raise Retryable(f"ledger {r.status_code}")
    if r.status_code >= 400:
        raise Permanent(r.text[:200])
    return LedgerRef.model_validate(r.json())   # their JSON is untrusted too
L1 · Beginner

What the code does

  • Every call has a timeout. httpx defaults to five seconds; requests defaults to waiting forever, which is the difference that matters.
  • One client, reused — it holds the connection pool. Create it at start-up, close it at shutdown.
  • Retry only what a retry can fix: connection errors and 5xx. A 400 will be a 400 again.
  • Back off between attempts, and add jitter so a thousand clients do not all retry on the same tick.
  • Validate their response too — another service’s JSON is exactly as untrusted as a browser’s.
L2 · Intermediate

Why it is written this way

  • Two exception types, not status-code checks at the call site. Retryable and Permanent put the policy in one place and make the retry decorator declarative.
  • The idempotency key is generated by the caller and reused across all attempts — that is what makes a retry safe rather than a second charge.
  • Timeouts are named separately so you can allow a slow response while still failing fast on a dead host.
  • Cap the total attempts against the caller’s deadline, not against a number that felt right. Three × 600 ms does not fit in a 2s budget.
  • max_connections is your bound on the downstream, and it is the only thing standing between a slow dependency and every worker you own.
L3 · Advanced

What bites in production

  • Retries are a load multiplier. A struggling service that you hit three times instead of once gets 3× the traffic exactly when it can least take it — the metastable failure from the foundations page.
  • A circuit breaker is the missing piece. After N consecutive failures, fail immediately for a cooldown instead of queueing more work against a service that is down.
  • Retrying a non-idempotent POST duplicates work unless the server enforces the key. “We send a key” and “they honour it” are different claims — check which one is true.
  • Propagate the deadline, not just a timeout: pass the remaining budget downstream so the whole chain gives up together, the way a Go context does.
  • Connection pools and forked workers — a client created before fork shares sockets across processes. Build it in the worker’s own start-up hook.

Fan-out with a bound on it

The job: enrich two hundred records by calling a service for each. The naive version issues two hundred simultaneous requests, and the thing that breaks is not your process — it is theirs.

# bounded fan-out, partial failure allowed
async def enrich_all(ids: list[str], *, limit: int = 20) -> list[Result | BaseException]:
    sem = asyncio.Semaphore(limit)

    async def one(oid: str) -> Result:
        async with sem:                        # the bound, not the loop
            async with asyncio.timeout(2.0):   # per item, not per batch
                return await enrich(oid)

    return await asyncio.gather(*(one(i) for i in ids), return_exceptions=True)
    # return_exceptions=True: one bad id does not lose the other 199 results
# all-or-nothing instead: 3.11+ TaskGroup cancels siblings on first failure
async def must_all_succeed(ids: list[str]) -> dict[str, Result]:
    async with asyncio.TaskGroup() as tg:
        tasks = {i: tg.create_task(enrich(i)) for i in ids}
    return {i: t.result() for i, t in tasks.items()}

# the exit raises ExceptionGroup — handle by type, not by position:
try:
    results = await must_all_succeed(ids)
except* TimeoutError as eg:
    log.warning("slow upstream", count=len(eg.exceptions))
except* ValidationError as eg:
    log.error("bad payload", count=len(eg.exceptions))
L1 · Beginner

What the code does

  • gather starts everything at once and waits for all of it. The list you pass decides how much runs concurrently.
  • Semaphore(20) hands out twenty permits; the twenty-first async with waits until one is returned.
  • return_exceptions=True puts failures in the result list instead of losing the successes.
  • asyncio.timeout is a context manager, so it bounds a block rather than a single call.
  • TaskGroup is the newer, stricter option: if one child fails the rest are cancelled.
L2 · Intermediate

Why it is written this way

  • The timeout is inside the semaphore, so the two seconds measure the actual call — not two seconds of queueing behind other tasks.
  • Choose the failure mode deliberately. gather(return_exceptions=True) for “do as much as you can”; TaskGroup for “all of it or none”.
  • except* handles an ExceptionGroup, which is what a TaskGroup raises when several children fail at once.
  • The limit should be derived, not guessed: their capacity divided by the number of instances of you.
  • Order out matches order in. gather preserves position, so you can zip results back to inputs; as_completed does not.
L3 · Advanced

What bites in production

  • Cancellation is cooperative. A cancelled task resumes with CancelledError at its next await — if it is blocked in C code it will not stop at all.
  • Never swallow CancelledError. except Exception will not catch it — it inherits from BaseException, deliberately. What breaks shutdown is except BaseException or a bare except: that catches it and carries on.
  • Fire-and-forget tasks get garbage collected. create_task without keeping a reference can have the task vanish mid-flight; hold it in a set and discard on completion.
  • Two hundred coroutines is memory too — each holds its own frame and its own response buffer. Bounded concurrency bounds peak memory as well.
  • The real limit is often theirs, expressed as 429. Read the Retry-After header rather than guessing your own backoff.

A file that does not fit in memory

The job: load an 8 GB compressed export into the database. The version that works and the version that gets OOM-killed differ by one word — list — and the generator topic earlier is the reason.

# each stage is lazy; nothing is read until the for loop pulls
def rows(path: str) -> Iterator[dict[str, str]]:
    with gzip.open(path, "rt", newline="") as fh:      # decompresses as it reads
        yield from csv.DictReader(fh)

def valid(raw: Iterable[dict[str, str]]) -> Iterator[Order]:
    for i, r in enumerate(raw, start=2):               # line 1 is the header
        try:
            yield Order.model_validate(r)              # pydantic, at the edge again
        except ValidationError as e:
            log.warning("skipped row", line=i, errors=e.error_count())
# the driver: one transaction per batch, so a failure loses 1000 rows, not 8 GB
from itertools import batched            # 3.12+; recipe in the docs before that

totals: Counter[str] = Counter()
for n, batch in enumerate(batched(valid(rows("orders.csv.gz")), 1000), start=1):
    with session.begin():
        session.execute(insert(OrderRow), [o.model_dump() for o in batch])
    totals.update(o.currency for o in batch)
    if n % 100 == 0:
        log.info("progress", batches=n, rows=n * 1000, totals=dict(totals))
L1 · Beginner

What the code does

  • yield makes the function lazy — calling rows(path) reads nothing; the for loop at the end pulls one row at a time through the whole chain.
  • yield from forwards every item of an inner iterable without a loop.
  • with gzip.open(...) decompresses on the fly; the file is never on disk uncompressed and never fully in memory.
  • batched turns a stream of items into a stream of tuples of n.
  • Counter.update accumulates counts without building an intermediate list.
L2 · Intermediate

Why it is written this way

  • Each stage does one thing, so each can be tested with a three-item list instead of an 8 GB file.
  • Bad rows are skipped with the line number, not silently dropped and not fatal — an import that dies on row 4 million is an import you run four times.
  • One transaction per batch bounds both the lock duration and how much work a crash costs.
  • Batch inserts, not row inserts. A thousand single INSERTs is a thousand round trips; the batch is one.
  • Log progress by batch count. A silent job that runs for an hour is indistinguishable from a hung one.
L3 · Advanced

What bites in production

  • A generator holds its resources open. The with inside rows only closes when the generator is exhausted or garbage collected — break out early and the file handle lingers.
  • Restartability beats speed. Record the last committed batch so a rerun resumes rather than starting again; with a unique key the insert can be an upsert and the whole job idempotent.
  • The database is usually the bottleneck, not the parse. Measure before reaching for multiprocessing — then COPY beats every Python-side optimisation by an order of magnitude.
  • Generators and exceptions interact badly under concurrency: a generator is not thread-safe, and sharing one across workers corrupts its state silently.
  • Watch fragmentation, not just peak. A long-running loop can hold flat RSS while the allocator never returns freed arenas to the OS.

Tests that catch what Python actually gets wrong

There is no compiler to tell you that a name is misspelt or an argument is the wrong type on the path nobody ran. Tests are the type checker for the paths you actually care about — and pytest’s mechanics decide how much they cost to keep.

import pytest
from app.orders import Order, parse_qty

@pytest.fixture(scope="module")
def store(tmp_path_factory):
    path = tmp_path_factory.mktemp("data") / "orders.db"
    s = Store(path)          # setup: once per test file
    yield s                  # the tests in this module run here
    s.close()                # teardown: runs even if a test fails

@pytest.mark.parametrize(
    "raw, want",
    [("3", 3), (" 3 ", 3), ("03", 3), ("", None), ("x", None)],
    ids=["plain", "padded", "leading-zero", "empty", "not-a-number"],
)
def test_parse_qty(raw, want):
    assert parse_qty(raw) == want

def test_rejects_negative_quantity(store, monkeypatch):
    monkeypatch.setattr("app.orders.now", lambda: FIXED_TIME)
    with pytest.raises(ValueError, match="quantity"):
        store.add(Order(qty=-1))
L1 · Beginner

pytest, and one behaviour per test

  • pytest finds test_*.py and functions named test_*. No class, no base class, no registration.
  • A plain assert is enough — pytest rewrites it so a failure shows both sides, which is why you never need assertEqual.
  • Arrange, act, assert, in that order, with a blank line between the three.
  • One behaviour per test, named for the behaviour: test_rejects_negative_quantity, not test_order_2.
  • Test the public function, not the private helper. The helper must stay free to change.
L2 · Intermediate

Fixtures, parameters, and the seams

  • A fixture is setup and teardown around a yield; naming it as an argument is the entire wiring mechanism. Shared ones live in conftest.py, imported by nobody.
  • scope decides how often it runs: function (the default), class, module, session. Session for a container or a pool; function for anything mutable.
  • parametrize with ids fans one body into many named cases, each reported separately, so the failure names the input.
  • monkeypatch for environment variables, attributes and the working directory — reverted automatically, unlike mock.patch applied by hand.
  • tmp_path for files, pytest.raises(ValueError, match=…) for errors, and markers plus -m "not slow" to keep the fast set fast.
L3 · Advanced

Tests that survive a refactor

  • Fakes over mocks. A small in-memory implementation of your own interface tests behaviour; assert_called_once_with tests today’s call graph and breaks on every refactor that found no bug.
  • Patch only at seams you own. mock.patch("app.module._helper") welds the test to an implementation detail — passing the collaborator in does not.
  • Time is an input. Inject a clock (now: Callable[[], datetime]) or use freezegun; a time.sleep in a test is a slow flake waiting for a loaded CI runner.
  • Property-based testing with Hypothesis: state the invariant — parse(format(x)) == x — and let it find the empty string, the surrogate pair and the boundary you would never have typed.
  • Coverage is a signal, not a target: it shows what never ran. A suite with no assertions can reach 100%. Mutation testing (mutmut) asks the sharper question — if I break the code, does anything fail?

Logging, configuration, and shipping it

Three decisions decide whether a running service can be debugged: what the logs carry, where the configuration comes from, and what exactly is inside the image. All three are made once, at start-up, in main.

# any library module: take a logger, never configure one
log = logging.getLogger(__name__)

def charge(order_id: str) -> None:
    log.info("charging", extra={"order_id": order_id, "req": request_id.get()})

# main.py: configure once, fail fast, drain on SIGTERM
def main() -> None:
    cfg = Config.from_env()          # SystemExit now beats a 500 later
    logging.basicConfig(level=cfg.log_level, handlers=[JsonHandler(sys.stdout)])
    server = make_server(cfg)

    stopping = threading.Event()

    def on_sigterm(signum, frame) -> None:
        ready.clear()                # 1. readiness starts failing
        stopping.set()               # 2. flip a flag -- a handler must never block

    signal.signal(signal.SIGTERM, on_sigterm)
    threading.Thread(target=server.serve_forever, daemon=True).start()
    stopping.wait()                  # main thread parks here until SIGTERM
    time.sleep(5)                    # 3. keep serving while the LB notices
    server.shutdown()                # 4. stop accepting, drain in flight
L1 · Beginner

Logging and configuration, plainly

  • logging, not print: levels, a timestamp, the module name, and a destination the operator chooses rather than you.
  • The levels mean something — DEBUG for you, INFO for lifecycle events, WARNING for something a human may need to look at, ERROR for a request that failed, CRITICAL for the process.
  • Configure exactly once, in main, at start-up. A library that calls basicConfig has stolen a decision that belongs to the application.
  • In every module: log = logging.getLogger(__name__). The dotted name gives per-package level control for free.
  • log.exception("…") inside an except records the traceback; log.error(str(e)) throws it away.
L2 · Intermediate

Structured logs, env config, a locked image

  • One JSON object per line, with fields — request_id, order_id, duration_ms — not an English sentence you will later have to write a regex against.
  • A correlation id minted at the edge, kept in a ContextVar so every record and every outbound header carries it. This is where these logs join the traces from the cloud page.
  • Config from environment variables, parsed into one frozen object and validated at start-up. A missing setting should kill the process in the first second, not the first request.
  • A committed lockfile and uv sync --frozen (or pip install -r a compiled requirements file) so CI and production resolve to identical versions.
  • A slim base image, dependencies in their own layer, non-root user. python -X dev turns on extra runtime checks in staging; python -O strips asserts, which is why an assert must never be your validation.
L3 · Advanced

What running it actually costs

  • Log volume is money and cardinality. One INFO line per request at 5,000 req/s is over 400 million lines a day: sample the routine ones, keep every error, and never put a user id or a full URL in a metric label.
  • SIGTERM, in the Go page’s order: fail readiness, wait for the load balancer to notice, stop accepting, drain in-flight work, close pools, exit. Python’s default on SIGTERM is to die immediately, mid-request.
  • Liveness and readiness are different questions — “should you kill me” versus “should you send me traffic”. A liveness probe that checks the database restarts your app whenever the database is slow.
  • Worker models: gunicorn with N sync workers is one process per core, no shared memory, and the safe default for blocking code; uvicorn/ASGI workers give I/O concurrency inside each process. Threads help only where the work releases the GIL.
  • A Python process is not a static binary. The interpreter, the C extensions and every wheel are part of what you ship, so the image — pinned by digest — is your dependency contract. There is nothing else to hand over.

The Python review checklist

Fifteen things worth a second look in any Python diff. Each takes about five seconds to check and can cost an afternoon to debug later — and roughly half of them a linter will find before you do.

The two questions behind all fifteen

“Who owns this object, and when is it released?” — which covers files, sockets, pools, caches, tasks and the references that keep them all alive. And “what does this do when the thing it calls never answers?” — the same question the Go page ends on, and the one that decides whether a slow dependency becomes a slow endpoint or a dead service.
